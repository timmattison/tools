## `src/workit/tests/output.rs` — `a_prefix_is_refused_because_each_member_already_names_its_package` passes on any refusal

**Settled** 2026-11-25 (branch workit, finding R-20261125T043207Z#N9)

The finding is accurate. Commit 8fdd953e wrote this test when `--prefix`
existed, and commit 64041a0b removed the flag. Today clap refuses `--prefix` as
an unknown argument, and the test passes on that refusal. The test passes on
any non-zero exit that writes no `Cargo.toml`. Its name and its message give a
reason, each member already names its package, that no code checks.

It is not fixed, because the fix costs more than the defect:

- **The test holds the fact that matters.** A run with `--prefix` fails and
  writes no manifest. If a change brings `--prefix` back and the run writes a
  manifest, the test fails.
- **The reason is the reason for the removal.** The name says why the flag
  went, not what the test checks. A wrong name does not make a wrong result.
- **The cost is a new review cycle.** This round of the review loop is
  record-only. A new name and a new assertion on stderr are new code in a test
  file that a review must read, and a fresh review can find a new nit in it.
  Tim chose to settle each nit with a record (decision H-742-2 on issue #742).

**The boundary.** This decision settles the name and the assertions of this
one test. A change that brings `--prefix` back and passes this test is a new
finding.
