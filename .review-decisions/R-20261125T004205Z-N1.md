## `src/ic/src/main.rs` — three refusals of the gate do not name the forced protocol

**Settled** 2026-11-24 (branch ic-xtermjs, finding R-20261125T004205Z#N1)

The finding is accurate. In `validate_terminal_for_graphics`, only the Mosh
refusal for a session that answered no query and the tmux refusal end with
`FORCED_PROTOCOL_REPAIR`. Three refusals do not name `--protocol` or
`IC_PROTOCOL`:

- the Alacritty refusal,
- the refusal of a different terminal that draws no image by its name,
- the Mosh refusal for no shared protocol.

Thus a ttyd page that loads `@xterm/addon-image` and inherits
`ALACRITTY_SOCKET` gets the Alacritty refusal. That refusal names iTerm2,
Kitty, and WezTerm, but not the forced protocol.

The verdict of each refusal is correct, and the way past it has a document
and a test. A forced protocol skips each of the three refusals, and the test
`a_forced_protocol_passes_the_gate_where_every_rule_refuses` holds that rule.
The README section "xterm.js Front Ends" tells the user of such a front end to
export `IC_PROTOCOL=sixel`. The doc of `FORCED_PROTOCOL_REPAIR` says that the
Mosh and the tmux refusals name it, and that statement is correct. The gap is
one hint in three error messages.

**The cost is a new review cycle.** This round of the review loop is
record-only. A change to three messages, to the doc of the const, and to the
tests is new code that a review must read. A fresh review can find a new nit in
it. Then a new fix round starts, and the loop does not end clean.

**The boundary.** This decision settles only the text of these three refusals.
A refusal that a forced protocol does not skip is a new finding. A document
that states that each refusal names `--protocol` or `IC_PROTOCOL` is a new
finding. A new refusal of the gate that does not name the forced protocol is a
new occurrence, and it reopens this decision.
