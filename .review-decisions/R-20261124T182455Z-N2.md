## `src/workit/src/main.rs` — a package directory whose name is not UTF-8 becomes a member that holds U+FFFD

**Settled** 2026-11-24 (branch workit, finding R-20261124T182455Z#N2)

The finding is accurate. `member_paths` makes each member with
`to_string_lossy`, thus a byte that is not UTF-8 in the path of a package
becomes U+FFFD. The manifest then names a directory that does not exist, and
the run reports success. A TOML string cannot hold such a name at all.

It is not fixed, because the fix costs more than the defect on the platform
that this tool runs on:

- **macOS cannot make the name.** APFS refuses a file name that is not UTF-8.
  On 2026-11-24, `mkdir` of a name with the byte `0xFF` failed with "Illegal
  byte sequence". The defect can occur only on a file system that keeps such a
  name, for example ext4 on Linux.
- **The failure is loud at the next step.** Cargo cannot load a member that
  does not exist. Thus the first `cargo build` or `cargo metadata` of the
  workspace stops with an error that names the member. No build uses the wrong
  package.
- **The fix is not local.** `member_paths` has no `Skipped` today. It runs
  after the refusal of an empty result in `main`, thus a skip there must also
  move that refusal, or a run that skips its last package reports success with
  no member.
- **No run of this repository can prove the fix.** The test must make a name
  that is not UTF-8. This Mac cannot make one, and the repository has no CI
  workflow on Linux.
- **The branch stopped at the blocking level.** The review marked this finding
  as a nit. At the stall (decision H-742-2 on issue #742), Tim chose to fix
  each blocking finding and to settle each nit with a record.

The boundary: this settles a path that is not UTF-8. A path that is UTF-8 and
that `member_paths` changes in a different way, for example a lost component or
a wrong separator, is a different finding. A report of this defect on a real
Linux tree, or a CI job on Linux, reopens this decision.
