## `src/gsw/src/watch.rs` — no test drives the production hooks of `m`, `p` and `G` through `watch::run`

**Settled** 2026-09-14 (branch issue-496, finding R-20260914T214851Z#I1)

The review found that no test reaches the production `start_conflicts` hook in
`watch::run`, or the paint of the notice from `conflicts.shutdown` at the quit.
Every loop test injects its own hook closures, and the worker tests call
`ConflictsWorker` directly. A change that empties the hook body, or removes the
shutdown call, keeps every `gsw` test green. The production `start_push` and
`start_issue` hooks have the same gap. The finding is accurate.

The gap stays open for all three keys, for these reasons:

- A test that reaches a hook must start watch mode on a pseudo-terminal, send a
  key, and read the screen until the outcome shows. `gitscratch::testing::pty`
  cannot send keys. It runs a child to its end and reads the output once. The
  fix thus needs a new interactive driver: key input, reads with deadlines, and
  the parse of an alternate screen in raw mode.
- Such a test is fragile on this machine. Pseudo-terminals are a scarce
  resource here, and tests that put a deadline around a spawned binary already
  fail under the load of a full workspace run.
- The notice at the quit shows only when a replay is in flight at the quit. A
  test cannot control that timing without a hook into the worker, and that hook
  is the production code the test must reach.
- A move of each hook body into a function that a test drives covers the event
  mapping only. The closure keeps a one-line call, so an empty closure still
  passes. The move adds a pass-through and closes no part of the gap.

The cost of the gap is small. Each hook is a few lines of wiring over code that
has tests, and a break in a hook shows at the first press of its key.

**Boundary.** This record covers only the wiring in `watch::run`: the
production hook closures and the call to `conflicts.shutdown`. It does not
cover the logic behind them — `ConflictsWorker`, `push::spawn`, `issue::run`
and `event_loop` — which must keep their tests. Reopen this record when a hook
breaks in use and no test fails, or when `gitscratch` gets an interactive pty
driver for a different reason.
