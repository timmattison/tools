## `src/repo-guards/tests/pre_commit_hook.rs` — issue #757 and the body of PR #646 do not show that `install_fake_program` uses `write_executable`

**Settled** 2026-11-25 (branch github-actions-ci, finding R-20261125T160416Z#N1)

The finding is accurate. Commit f38e69016 moves `install_fake_program` (the
`install_fake_cargo` of #684) to `write_executable`. Issue #757 still lists
`src/repo-guards/tests/pre_commit_hook.rs:562` as an open box. The body of the
PR of issue #651 (PR #646, branch github-actions-ci) says that 36 sites use
`write_executable`, and it does not name this site.

**The cost of a change to the PR body is a new review cycle.** This round of
the review loop is record-only. A review reads the PR body, thus a change to
the body is a new change that a review must read. A fresh review can find a
new nit in it. Then a new fix round starts, and the loop does not end clean.
The defect is in prose only. No code reads the count, and the hook tests
already write each fake program through `write_executable`.

**The box of issue #757 must wait for the merge.** The site is done on `main`
only when PR #646 merges. A box that this branch checks before the merge says
that `main` holds a change that it does not hold, and the box is false if the
PR does not merge. After the merge, a worker on issue #757 reads the site, sees
`write_executable` in it, and checks the box. That costs one read of one
function.

**The boundary.** This decision settles only the text of issue #757 and of the
PR body about this one site. A fake program of the hook tests that does not
use `write_executable`, or a site that the PR body counts and that does not use
it, is a new finding.
