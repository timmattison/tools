## `.husky/pre-commit` — a staged path that git C-quotes does not match the plugin trigger or the ic-inline trigger

**Settled** 2026-11-25 (branch ic-emit-rgba, finding R-20261125T052225Z#N1)

The finding is correct. `core.quotePath` is not set, thus git uses its default of `true`. `git diff --cached --name-only` then prints a path that holds a non-ASCII byte, a tab, a double quote, or a backslash in C-quoted form, with a leading double quote. The anchored patterns `^(plugins/|\.claude-plugin/)` and `^plugins/ic-inline/` do not match such a line. A commit that stages only such a path below `plugins/` thus runs no claude check and no `cargo test -p ic --test emit-rgba`.

The Rust trigger of the hook has the same gap on `main`: a C-quoted path ends in a double quote, thus `\.rs$` does not match it. A fix of the two blocks of this branch alone gives the hook two rules for one list of paths. The correct fix reads each trigger from one list that git writes with `-z`, or with `-c core.quotePath=false`, and it needs a fixture of a quoted path for each trigger. That change is a change to the whole hook, outside the scope of issue #745.

Today each file below `plugins/` and `.claude-plugin/` has a kebab-case ASCII name, thus no file of the repository hits the gap. This round of the review loop is record-only. A change to the hook is new code that the next review reads, and a new nit in it starts a new fix round. The cost of that review cycle is more than the cost of a gap that no file of the repository can hit today.

The boundary: this decision covers only a staged path that git prints in C-quoted form. A path with a plain ASCII name that a trigger of the hook does not match is a new finding.
