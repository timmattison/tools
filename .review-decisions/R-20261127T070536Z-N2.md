## `src/nle/src/filters/viewport.rs` `RawCrop` — a number that is not a whole number in the range of `i64` fails with a message of serde

**Settled** 2026-11-27 (branch issue-165, finding R-20261127T070536Z#N2)

The finding is accurate. The doc of `RawCrop`, the spec
(`specs/2026-11-27-nle-viewport-filter-design.md`) and the README say that an
index that is not on the screen fails with a message that names the option. The
filter reads each index as `i64`. Thus a number above `i64::MAX`, for example
`hide_rows: [18446744073709551615]`, or a fraction, for example
`rows: {start: 0, end: 1.5}`, fails in `serde_json::from_value`. The message of
serde names the type, but it does not name the option.

The defect is a message that is less clear. It is not a wrong output. The
render fails for each such number, as the three statements say. Only the text
of the message is different. A person who writes a fraction or a number of 20
digits as a row index gets the value and the expected type in the message.

**The fix costs more than the defect in this round.** The fix is a change of
three statements, or a reader of `serde_json::Number` for each index and a test
for each form. This round of the review loop is record-only. A change is a diff
that a review must read, and that review can find a new nit in it. Then one more
fix round starts.

**The boundary.** This record settles only the message for a number that is not
a whole number in the range of `i64`. Each of these occurrences reopens it:

- a number in the range of `i64` that fails with a message that names no option
- a number that is not in the range of `i64` and that the filter accepts
- a new option of the filter that reads a number with no check of its own
