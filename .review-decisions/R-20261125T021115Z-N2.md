## `src/nle/tauri.conf.json` — the CSP has no `connect-src` for the IPC custom protocol

**Settled** 2026-11-25 (branch 170, finding R-20261125T021115Z#N2)

The finding is accurate. Tauri 2.11.5 does not add `ipc:` or
`http://ipc.localhost` to the CSP. The doc example in `tauri-utils` writes
`connect-src ipc: http://ipc.localhost` by hand. Thus `connect-src` falls back
to `default-src 'self'`, and the webview blocks the fetch of the IPC custom
protocol.

`scripts/ipc-protocol.js` in the `tauri` crate catches that failure. It logs
`IPC custom protocol failed, Tauri will now use the postMessage interface
instead`, sets `customProtocolIpcFailed`, and sends the call again through
`postMessage`. Each later call goes through `postMessage` directly. Thus each
command still gets to the Rust side, and the console shows one warning.

The cost of the defect: one console warning, and the `postMessage` path for
each call. The frontend calls only `load_recording`, one time for each file that
the user opens, thus the slower path has no measurable effect. The cost of a
fix: a change to the security configuration and one more review round. A run of
the application to read the console is a manual check, and this round cannot do
it.

The boundary: a report that the CSP has no `connect-src` for IPC is this
decision. A command that fails because of the CSP reopens it. A frontend that
sends IPC calls at a high rate, for example one call for each frame of playback,
also reopens it.
