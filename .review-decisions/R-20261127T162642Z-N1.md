## `src/wdid/src/added.rs` `defined_names` — an alias command that is not the first command of its line gets no added date

**Settled** 2026-11-27 (branch issue-730, finding R-20261127T162642Z#N1)

The finding is accurate. `alias_names` stops at the first operator, and
`defined_names` reads an alias line only when the line starts with `alias`.
Thus the read misses each of these names, which zsh defines:

- `z` of `alias x=y && alias z=w`, and `c` of `alias a=b; alias c=d`
- `ls` of `(( $+commands[eza] )) && alias ls=eza`, and each other guard
  before `alias`, for example `[[ ... ]] &&`, `command -v ... &&`, or
  `if ...; then alias`

Such a name gets no added date. The report shows `unknown`, and a name that
never ran goes into "Never used, old". Thus the usual result is the safe
direction: the name never looks new by mistake. One case goes the other way.
If the history first adds the name in a guarded form, and a later commit adds
it again in the plain form, the name gets the date of the later commit. The
README list under "The added date" does not name this limit.

**The fix costs more than the defect in this round.** The fix is a read of
each command of the line, or a sentence in the README. Either one is new text
that a review reads, and this round of the review loop is record-only. The
alias reader drew a finding in almost each round of this branch: the brace
list, the brace sequence, the open quote, and the line join. A split of the
whole line into commands, with the guards before `alias`, makes that reader
larger again, and a new review can find a new form that it misses. The README
already states the forms that the read accepts ("An alias line starts with
`alias`").

**The boundary.** This record settles only a name that an alias command
defines when that command is not the first command of its line, or when a
guard comes before `alias`. Each of these occurrences reopens it:

- the read gives a name that zsh does not define on that line
- the read misses a name of the first command of a line that starts with
  `alias`
- a line form that the README says the read accepts defines no name
- a common dotfile form that is not a guard or a second command, for example
  `alias` inside a function body on its own line, gets no date
