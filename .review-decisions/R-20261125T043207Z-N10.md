## `src/workit/tests/worktree.rs` — the assertion on the word `worktree` adds nothing to the assertion after it

**Settled** 2026-11-25 (branch workit, finding R-20261125T043207Z#N10)

The finding is accurate. The test asserts that the output holds `worktree`, and
then that it holds `--include-worktrees`. The second text holds the first. Thus
the first assertion adds nothing, and its message claims a check, the filter
emptied the result, that it does not make.

It is not fixed, because the fix costs more than the defect:

- **The pair of tests holds the claim.** Only `explain_empty_result` prints
  `--include-worktrees`, and it prints it only when the filter left a manifest
  out. `an_empty_result_nothing_filtered_does_not_name_the_flag` holds the
  other side: a tree with no package does not name the flag. Thus a run that
  names the flag is a run that the filter emptied.
- **The cost is a new review cycle.** This round of the review loop is
  record-only. A new assertion in a test file needs a proof with a mutant of
  the code under test. A review must read that new code, and a fresh review can
  find a new nit in it. Tim chose to settle each nit with a record (decision
  H-742-2 on issue #742).

**The boundary.** This decision settles the first assertion of this one test.
A change that makes a different message print `--include-worktrees` reopens
it.
