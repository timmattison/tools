## `CLAUDE.md` "Checks in an issue-fleet Step" part 2 — "the same environment" and four commands that do not use `without_git_environment`

**Settled** 2026-11-27 (branch issue-799, finding R-20261127T051952Z#N2)

The finding is accurate. `scripts/rust-checks.sh` starts each of its four cargo
commands through `without_git_environment`. The four commands of part 2 give
the same flags and the same two color variables, but they do not remove the
`GIT_` variables. Thus the environment is the same only when the shell of the
step holds no `GIT_` variable.

**The fix costs more than the defect in this round.** A step of issue-fleet
runs in a `claude -p` process, not in a git hook, thus its shell usually holds
no `GIT_` variable. Each child that the Rust code of the workspace starts goes
through `childenv`, which removes the prefix. The gap is the build script of a
dependency under a shell that holds a `GIT_` variable. The first fix is prose:
"the same color variables" in place of "the same environment". The second fix
puts `without_git_environment` into four commands that a person types, and the
function must first come from `scripts/without-git-environment.sh`. This round
of the review loop is record-only. Each fix is a diff that a review must read,
and that review can find a new nit in it. Then one more fix round starts.

**The boundary.** This record settles only the words "the same environment" of
part 2. Each of these occurrences reopens it:

- a step of issue-fleet that starts its cargo commands from a shell that holds a
  `GIT_` variable, for example from a git hook
- a cargo command of part 2 that acts on a `GIT_` variable of the shell of the
  step
