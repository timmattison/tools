## `src/nle/src/filters/viewport.rs` — the reason for `ESC ( B` calls each line drawing glyph a box-drawing character

**Settled** 2026-11-28 (branch issue-161, finding R-20261128T053109Z#N1)

The finding is accurate. `line_drawing_glyph` in `src/termstate/src/lib.rs`
maps the 32 characters 0x5F to 0x7E. Only 11 of the glyphs are in the Unicode
box-drawing block (`j k l m n q t u v w x`). The other 21 are a blank, block
elements, control pictures, scan lines, math signs, `£` and `·`. The module doc
of `viewport.rs` (lines 53 to 55) and
`specs/2026-11-27-nle-viewport-filter-design.md` (lines 165 and 166) say that
the filter writes each line drawing character "as its Unicode box-drawing
character".

No output is wrong. The reason for `ESC ( B` stays correct: the filter writes
the Unicode glyph of each cell, thus the real terminal must use the ASCII set,
so that it does not map the glyph a second time. The defect is only the name of
the 21 glyphs.

**The fix costs more than the defect.** The fix is prose in two files: the
module doc and the spec. This round of the review loop is record-only. Two
changed documents are new text that a review must read, and that review can
start one more fix round.

**The boundary.** This record settles only the words "box-drawing character" in
the reason for `ESC ( B`. These occurrences reopen it:

- a cell that the filter writes as a glyph different from the glyph of
  `line_drawing_glyph`
