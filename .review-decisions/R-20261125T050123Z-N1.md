## `src/msgs/frontend/src/export.ts` — the default name of the export folder takes the UTC date of now

**Settled** 2026-11-25 (branch msgs, finding R-20261125T050123Z#N1)

The finding is accurate. `exportSelection` gives the save dialog
`` `msgs-export-${new Date().toISOString().slice(0, 10)}` `` as its default
path. `toISOString()` writes UTC, thus in New York after 19:00 EST (20:00 EDT)
the default name gets the date of the next day. Since f427883c, each message
date in `messages.json` carries its local date. Thus the folder name and the
dates in it can differ by one day.

**The fix costs more than the defect.** The name is only the default text of
the save dialog. The user sees it and can change it before the export starts.
The export does not read the name, and no date in `messages.json` or in an
attachment comes from it. A fix needs a local-date helper and a vitest test
with a fake clock near midnight UTC. This round of the review loop is
record-only, thus that change starts one more review cycle for a cosmetic
default.

**The boundary.** This record settles the date in the default name of the
export folder only. A date that the export writes into `messages.json`, into a
file name inside the folder, or into another output, and that comes from UTC
and not from the local zone, reopens this record.
