## `src/chf/src/index.rs` `candidates_from` — a transcript that vanished before its stat counts as unreadable for one run

**Settled** 2026-11-19 (branch issue-674, finding R-20261115T045925Z#N1)

The finding is accurate. `candidates_from` turns each error of `fs::symlink_metadata` into `Err`, and `NotFound` is one of them. Thus a transcript that Claude Code deletes between the `read_dir` of its folder and its stat sends `Unreadable`, and `process_folder` keeps its old cache entry. The doc comment of `process_folder` says that a transcript that chf can not stat is not a transcript that is gone. That sentence is false for `NotFound`. `discover` skips a folder entry that vanished before its stat, so the two levels do not agree.

The effect is small, and the next run repairs it:

- The status line shows one more unreadable file for that run.
- The cache file keeps one stale entry for that run. `process_folder` sends no `Session` for a kept entry, so the list does not show the session that is gone. The next run does not find the transcript and writes the cache without the entry.

The window is the time between the `read_dir` of the folder and the `lstat` of one file. Thus the defect occurs only in a race.

**Why it is not fixed.** The change in the code is small, but it is not free:

- A deterministic test needs a seam for the stat in `candidates_from`, because a real file cannot vanish at the correct moment. The seam is new code that makes the module larger for a defect that occurs only in a race.
- The review loop of this branch is in its record-only round. A code change goes into the next incremental review, and the sweep of nits starts again.

**The boundary.** This record settles the `NotFound` stat of one transcript in `candidates_from`, and the matching sentence in the doc of `process_folder`. It does not settle a stat error other than `NotFound`, which must keep the cache entry (finding R-20261115T043116Z#I1). It does not settle a stale entry that lives longer than one run, or a session that is gone and shows in the list. A real occurrence of either reopens this decision.
