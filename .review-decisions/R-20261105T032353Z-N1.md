## Commit order on a pushed branch — the `--expand` tests of `crap` came after their green commits

**Settled** 2026-11-05 (branch issue-637, finding R-20261105T032353Z#N1)

The review found that eight green commits implemented more than their red test
asked for, so the later tests passed at their first run:

- `0f4204ab` ("expand relinks the chain around each compaction") came after
  only `ba2f6f0b` (one partial compaction). It also added each refusal, the
  owner walk, the handling of duplicate lines, and the check for a cycle. The
  tests `1d3cf616`, `65735458`, `eac04fc4`, `dee1da0f`, `b37b9e7c`,
  `d5c47455`, `08432c27`, `e1d9922c`, `1812c972`, and `f8f6004c` came after it.
- `96ff6cfd` came before `451dbc74`.
- `7a2beb51` came before `2f031c9e` and `9f3ffaa6`.
- `c875e242` came before `dcc0dc54`.

- `6e408234` came before `8beeb677`.
- `8723a0f6` came before `3d8d4c3a`.

The TDD rule in `CLAUDE.md` asks for the red commit first. The finding is
accurate.

It is not fixed, because the defect is the order of the commits and nothing else.

**The coverage is real.** The body of each late test commit names a mutation
that fails its test, with two exceptions. `1d3cf616` and `451dbc74` name none.
The run of `address-issues` for this finding did four mutants of
`src/crap/src/expand.rs` on `7d1c4320`, one at a time, and ran
`cargo test -p crap --bin crap expand::tests` for each. The file was restored
after each mutant, and `git status --short` was empty at the end.

- M1: `while let` changed to `if let` in `resolve`, so a walk takes at most one
  hop. `two_compactions_are_undone` and
  `a_compaction_right_after_a_compaction_skips_both_summaries` fail in the
  `walk` helper with "unknown uuid", because a kept line links to a removed
  line. `lines_the_rules_do_not_change_stay_byte_identical` fails at
  `src/crap/src/expand.rs:725`, because the parent of `p1` is `b1`, not `m2`.
- M2: `.take(1)` added to the boundaries of step 3, so only the first
  compaction counts. `two_compactions_are_undone` and
  `a_compaction_right_after_a_compaction_skips_both_summaries` fail in the
  `expanded` helper, because `expand_transcript` refuses the transcript.
- M3: the `\r\n` branch of `terminator` returns `\n`.
  `lines_the_rules_do_not_change_stay_byte_identical` fails at
  `src/crap/src/expand.rs:725`, because the rewritten line lost its `\r\n`.
- M4: `&& l.pairs.is_some()` added to the filter of the kept lines in step 7,
  so a line that is not JSON is dropped.
  `lines_the_rules_do_not_change_stay_byte_identical` fails at
  `src/crap/src/expand.rs:720`, because the line that is not JSON is missing.

What TDD gives, a test that can fail for the behavioral reason, is present. Only
the order of the commits is wrong.

**The one fix is a rewrite of pushed history, and it buys nothing durable.** The
finding says that the branch has no PR. It has one: PR #638 (branch issue-637)
opened at 2026-11-05T03:23:38Z, and `origin/issue-637` was at `a67874bf` when
the review ran. A red-first order needs `0f4204ab` and the seven other green
commits split, and every later commit gets a new SHA. The tool is an
interactive rebase, which only Tim can run. The next push then needs a force
push, which `block-dangerous-git.ts` refuses with no override. After a rewrite,
`pr-merge-gate.ts` calls the review `R-20261105T032353Z` `rewritten` and refuses
the merge until a fresh review of the whole branch. Against that: this
repository squash-merges every PR with an explicit `--subject` and `--body`, so
no commit of this branch reaches `main`.

**The boundary.** This decision settles the order of the named commits on the
branch `issue-637` only, where each test exists and a mutant shows that it can
fail. It does not settle a missing test, or a test that nobody showed can fail.
It does not permit a green commit that implements more than its red test asks
for, as a habit.

**The pattern.** This is the twelfth branch with this shape. The finding counts
it as the tenth, but `R-20261101T170934Z-N1` is the tenth and
`R-20261102T134608Z-N1` is the eleventh. The record `R-20261101T170934Z-N1`
names the nine before it. The repair belongs to the brief of the green step in the
TDD skills of the dotfiles repository (timmattison/dotfiles issue #22), and not
to this record.
