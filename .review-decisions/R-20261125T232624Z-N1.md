## `src/nle/tests/dev-script.rs` — the `assert_eq!` after the `find` of the dx install line stays

**Settled** 2026-11-25 (branch issue-761, finding R-20261125T232624Z#N1)

The finding is accurate. The `find` selects only a line whose trimmed text
equals `DX_INSTALL_COMMAND`. Thus the `assert_eq!` after it cannot fail, and its
message about a version pin never prints.

The test still does its job. A command with a version pin or with flags does
not match the `find`, and the test fails with the message "the message must
give the command that installs dx". That message holds the whole stderr, thus a
reader sees the wrong command. The redundant assertion gives no false green.

The cost of a fix: remove the assertion and move its text into the panic, or go
back to `contains()` in the `find`. Each fix is new code in a test file, thus it
starts one more review round, which can find a new nit in the new code.

The boundary: a report about this redundant assertion is this decision. This
change reopens it:

- A change to the test or to `scripts/dev.ts` lets a pinned command or a
  command with flags pass the test.
