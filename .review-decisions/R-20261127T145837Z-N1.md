## `src/nle/src/preview/screen.rs` — the docs of `single_cell` say a box of one cell, and a wide run has both flags

**Settled** 2026-11-27 (branch issue-165, finding R-20261127T145837Z#N1)

The finding is accurate. `runs_of` sets
`single_cell = wide || ch.width() != Some(1)`, thus a wide run has
`single_cell` and `wide` both set. `ui/preview.rs` reads `wide` first and
draws such a run with the class `cell wide`, two cells wide. The doc of the
field `single_cell` says "a box of one cell", and the module doc (lines 3-6)
reads as if the two flags exclude each other.

No output is wrong. The UI reads `wide` before `single_cell`.
`a_wide_character_is_a_run_of_its_own` in `src/nle/src/preview/screen/tests.rs`
pins both flags as set on a wide run. Only a reader of the doc can get the
wrong model of the flags.

**The fix costs more than the defect in this round.** The fix changes two doc
comments. This round of the review loop is record-only. A change is a diff that
a review must read, and that review can find a new nit in it. Then one more fix
round starts.

**The boundary.** This record settles only the text of the field doc of
`single_cell` and of the module doc of `screen.rs`. A change of the UI that
reads `single_cell` before `wide`, or a run that the UI draws with the wrong
width, is a new occurrence, and it reopens this decision.
