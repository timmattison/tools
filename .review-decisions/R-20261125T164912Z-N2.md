## `.husky/pre-commit` — a commit that stages only `scripts/without-git-environment.sh` runs neither check script

**Settled** 2026-11-25 (branch github-actions-ci, finding R-20261125T164912Z#N2)

The finding is accurate. `scripts/rust-checks.sh` and `scripts/plugin-checks.sh`
each source `scripts/without-git-environment.sh`. The Rust trigger and the
plugin trigger of the hook each match their own script, but not the helper.
Thus a commit that stages only the helper runs neither script. `main` has the
same gap since #684.

**The cost of the fix is a new review cycle.** This round of the review loop is
record-only. The fix changes both triggers and adds a hook test that stages
only the helper. A fresh review can find a new nit in that change. Then a new
fix round starts, and the loop does not end clean.

**Two layers catch a broken helper before a merge.** The hook sources the
helper itself, at its start. Thus a helper that does not parse fails each
commit, also a commit that stages only the helper. A helper that parses but
removes the wrong variables passes the hook. But CI runs both scripts for each
pull request, and the Rust jobs run `src/repo-guards/tests/pre_commit_hook.rs`,
which holds each cargo and claude command of the hook free of `GIT_` variables.

**The boundary.** This decision settles only the two trigger patterns of the
hook. A broken helper that merged because no check ran it, or a CI job that
stops running either script, is a new finding.
