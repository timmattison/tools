## Commit content on an unpushed branch — the cut of a long runner name in `ha` landed in a test commit

**Settled** 2026-10-20 (branch issue-584, finding R-20261020T163846Z#N1)

The review found that the commit `645c422d` ("test(ha): a runner name needs 4 columns
to be cut") holds two things. It holds the green code that cuts a long runner name in
`fit_runner` of `src/ha/src/render.rs`:

```rust
Some(truncate_to_budget(name.as_str(), room))
```

That code makes the red test of `a28bb098` pass,
`a_long_runner_name_is_cut_to_the_room_that_the_job_text_leaves`. The commit also holds
the red test of the 4-column rule, which `ea35f735` makes pass. Thus the red test of
`a28bb098` has no green commit of its own, and a test commit changes production code.
The TDD rule in `CLAUDE.md` says: "Never combine the red and green commits." The
finding is accurate.

It is not fixed, because the defect is the content of one commit and nothing else.

**The coverage is real.** The run of `address-issues` for this finding did two
mutations on `a68f39d2`, with `cargo test -p ha --lib render::tests`:

- With `None` in place of the cut, 1 test fails:
  `a_long_runner_name_is_cut_to_the_room_that_the_job_text_leaves`.
- With `room >= 1` in place of `room >= MIN_RUNNER_WIDTH`, 1 test fails:
  `a_long_runner_name_with_fewer_than_4_columns_does_not_show`. The commit `90671d23`
  renamed and split the red test of `645c422d`, and this is its new name.

Each red test can fail for its behavioral reason. Only the split between two commits
is wrong.

**The one fix is a rewrite that only Tim can run, and it buys nothing durable.** A
split of `645c422d` into a green commit and a red commit needs an interactive rebase,
and the agent shell does not support interactive git commands. The split gives a new
SHA to `645c422d` and to each commit after it. The review `R-20261020T163846Z` ends on
`192231d9`, which is one of those commits. `pr-merge-gate.ts` looks for that exact SHA
on the branch, not for a patch-id. After the split, it calls the review `rewritten`
and refuses the merge until a fresh review of the whole branch. Against that cost:
this repository squash-merges every PR with an explicit `--subject` and `--body`, thus
no commit of this branch reaches `main`. Tim chose to decline when he saw both costs.

This decision applies the reasons of `R-20261017T222526Z-N1` (branch `issue-565`) and
`R-20261018T041353Z-N1` (branch `issue-566`) to this branch.

**This is the third branch with this shape.** The record of `issue-566` says that a
third branch "is a new finding about the process, not a re-litigation of this
decision." This record does not settle that process finding. It settles only the
content of `645c422d`.

**The boundary.** This decision settles the content of `645c422d` on the branch
`issue-584` only, where both tests exist and a mutation shows that each can fail. It
does not settle a missing test, or a test that nobody showed can fail. It does not
permit a green change in a test commit as a habit.
