## `src/msgs/frontend/src/main.ts` — the sidebar does not restore the selection after a search clears

**Settled** 2026-11-24 (branch msgs, finding R-20261124T221923Z#N3)

The finding is accurate. `handleSearchNavigate` calls
`highlightConversationById` while the sidebar holds search results, thus the
call finds no `.conversation-item`. When the search clears, `hideSearchResults`
rebuilds the list from page 1 with no active item. ArrowDown then starts at the
first conversation, not at the open chat. `getSelectedChatId` has no caller.

**The fix costs more than the defect.** The open chat stays open, and the
message view does not change. The user loses only the highlight in the sidebar,
and one click or one arrow key gives a selection again. A fix changes the
selection state of `conversations.ts`: set it in `openConversationAt`, and
restore it after each reload. It also needs vitest tests of the reload. This
round of the review loop is record-only, thus that code starts one more review
cycle.

The finding `R-20261124T232234Z#N5` of a later review reports the same defect.
Its record is `R-20261124T232234Z-N5.md`.

**The boundary.** This record settles the lost highlight after a search clears,
and the unused `getSelectedChatId`. A key or a click that opens a chat that the
user did not choose reopens this record.
