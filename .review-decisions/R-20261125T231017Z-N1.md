## `plugins/ic-inline/hooks/register.tsx` `show_diff` — an empty mode gets the refusal of a wrong mode, not of a missing mode

**Settled** 2026-11-25 (branch issue-764, finding R-20261125T231017Z#N1)

The finding is correct. A `show_diff` call with `mode: ''` gets the refusal
`show_diff takes a mode of boxes, highlight or mask, and it got .`, which names
an empty mode. The command form refuses the same empty value with
`--mode needs a mode` (`hooks/argument.ts`, the `value === ''` branch), thus
the tool and the command answer one input in two ways.

Both answers refuse the call, and both name the three modes. Only the words
for the cause differ. The input schema of `show_diff` gives the modes as an
enum, thus a model seldom sends an empty mode, and the user does not type the
tool input.

The fix changes the code of the tool path and adds one row to the mode refusal
table of the `show_diff` tests. Its cost is that change and one more review
cycle of this branch, which is in a record-only round. The cost of the gap is
one refusal whose words name an empty value as a wrong mode.

The boundary: a review that asks again for the words of the refusal of an
empty mode in the tool path is settled by this record. An empty mode that the
tool accepts, or a refusal that does not name the modes, is a new finding. A
change of the refusal words of the command form reopens this decision.
