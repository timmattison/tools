## `src/workit/src/main.rs` — the rewrite of `workspace.members` does not look at `workspace.default-members`

**Settled** 2026-11-25 (branch workit, finding R-20261125T043207Z#N3)

The finding is accurate. The rewrite drops each member that the scan did not
find, and it names each one on stderr. It does not read
`workspace.default-members`. On 2026-11-25, cargo refused a manifest whose
`default-members` named a package that `members` did not list, with exit 101
and the message "is listed in default-members but is not a member". Thus a run
that drops a member that `default-members` also names writes a manifest that
cargo refuses.

It is not fixed, because the fix costs more than the defect:

- **The case is narrow.** The defect needs an existing manifest that holds
  `default-members`, and a member of it that the scan does not find. A new
  `--exclude` or the worktree filter can drop such a member.
- **The failure is loud at the next step.** The next cargo command stops, and
  its error names the package and the manifest. The `Dropping N member(s)`
  warning of the run already named the same package. The repair is the removal
  of one entry.
- **The fix needs a choice.** The run can name the entry in its warning, or it
  can remove the entry from `default-members` too. The second choice changes a
  key that the run leaves alone today, and the README says that the run leaves
  the rest of the manifest alone.
- **The cost is a new review cycle.** This round of the review loop is
  record-only. A fix and its test are new code that a review must read, and a
  fresh review can find a new nit in it. Tim chose to settle each nit with a
  record (decision H-742-2 on issue #742).

**The boundary.** This decision settles `workspace.default-members`. A
different key of the manifest that cargo checks against the members list is a
new finding. A run that writes a manifest that cargo refuses when the existing
manifest holds no `default-members` is a new finding.
