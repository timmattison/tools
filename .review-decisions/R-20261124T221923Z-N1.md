## `src/msgs/src/db.rs` — `get_last_message_preview` keeps `.ok()` on its query

**Settled** 2026-11-24 (branch msgs, finding R-20261124T221923Z#N1)

The finding is accurate. `get_last_message_preview` ends its `query_row` with
`.ok()`. Thus each error of the query gives an empty preview, the same as a
chat with no messages, and the function never returns its `Err`.

**The fix costs one more review cycle, and the defect has almost no reach.**
`list_conversations` calls `get_participants` for the same chat, on the same
connection, immediately before the preview query. `get_participants` returns
its error with `?`, and the query of the chat list runs before both. Thus a
locked or corrupt `chat.db` fails the list with an error that the user sees,
before the preview query runs. The swallowed error is only an error of the
preview query alone. This round of the review loop is record-only. A change to
`.optional()?` and its test is new code, and a review of it starts one more fix
round.

**The boundary.** This record settles the `.ok()` of the preview query only. A
second query that turns an error into an empty value reopens this record. A
chat list that shows an empty preview for a chat that has messages also
reopens it.
