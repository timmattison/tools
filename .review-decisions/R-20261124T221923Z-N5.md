## `README.md` — the `msgs` entry says that each start makes the search index

**Settled** 2026-11-24 (branch msgs, finding R-20261124T221923Z#N5)

The finding is accurate. The README says: "After each start, `msgs` makes a
full-text index of the message text in the background". `run_build`
(`src/msgs/src/state.rs`) rebuilds the index only when
`TextCache::needs_rebuild` finds a change of the source fingerprint of
`chat.db`. A start with an unchanged `chat.db` uses the old index. The spec
states the rule correctly, in the Text Cache item of
`specs/2026-03-17-msgs-imessage-browser-design.md`.

**The fix is prose, and it costs more than the defect.** The fix changes one
clause. The user sees no wrong behavior: after a start with an unchanged
`chat.db`, the search is ready sooner than the README says. This round of the
review loop is record-only, and a change of the README starts one more review
cycle on this branch.

The finding `R-20261124T232234Z#N6` of a later review reports the same
sentence. Its record is `R-20261124T232234Z-N6.md`.

**The boundary.** This record settles the clause "After each start" only. A
README statement that makes the user expect text that the index does not hold
reopens this record. A false statement about the location or the removal of
the index also reopens it.

**Superseded** 2026-11-24 (finding R-20261124T203119Z#I17). The search index now lives in memory, and each start builds it. Thus the README clause "After each start" is true, and `TextCache::needs_rebuild` is gone.
