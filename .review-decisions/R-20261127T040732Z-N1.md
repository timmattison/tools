## `src/nle/src/filters/keystroke_hud/keys.rs` — the step counter of `defer` does not count a copy

**Settled** 2026-11-27 (branch issue-161, finding R-20261127T040732Z#N1)

The finding is correct. The counter that the tests read in `defer` adds steps
only for the drain, and only when `start > 0`. A mutant that copies
`chars[start..]` with `to_vec` at start 0 adds 0 steps. Thus
`a_string_over_many_events_costs_steps_linear_in_its_length` passes for that
mutant. The test guards the scan, not the copy.

The code is correct: `defer` moves the `Vec` with `std::mem::take` and
copies no character. The fix is a second measure in a counter that exists
only for the tests, a check of the allocation pointer, and a proof with a
mutant. This round of the review loop is record-only. That change is new
test code that a review must read, and that review can start a new fix
round. The counter already took a red and a green commit to guard one line.
A third measure costs more than the risk of a later change that puts the
copy back.

Boundary: a change to `defer` that copies the kept characters reopens this
decision. A new argument about the counter does not.
