## `src/nle/src/ui.rs` `SPEED_HINT` — "the speed changes above" stays as it is

**Settled** 2026-11-26 (branch issue-153, finding R-20261126T201057Z#N1)

The finding is accurate. `SpeedPanel` puts the hint under the **Speed**
heading, above the three fields. The rows of the speed changes come after the
**Apply Speed** button. Thus "the speed changes above" has no referent in the
panel. A person who looks above the hint finds the metadata. The README text
("the speed changes above it") means the rows above the new row in the list,
but the hint does not name the list.

The defect is one phrase of help text. The rule that the hint states is
correct: a new region goes to the end of the list, and its times are on the
timeline after each change that is in the list before it. The panel applies
each change in the order of the list, so a person who types times from the
edited playback gets the result that the hint promises.

The fix costs more than the defect. It changes `SPEED_HINT`, the expected text
in `src/nle/src/ui/tests.rs`, and the README paragraph. That change is new
text that a fresh review must read, and the loop then starts one more fix
round for one phrase of help text.

The boundary: this settles the word "above" in `SPEED_HINT` and in the README
paragraph of the speed panel. A hint that states a wrong rule, for example a
timeline that the edit does not use, is a new finding. A change to the layout
that moves the rows above the fields makes the text correct and closes this
decision.
