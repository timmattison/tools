## `src/ufa/.env.example` — line 12 names the Linux path of the config file

**Settled** 2026-11-25 (branch ufa, finding R-20261125T182148Z#N2)

The finding is accurate. Line 12 says that the keys are referenced "from
~/.config/ufa/config.toml". `config.rs` takes the directory from
`dirs::config_dir()`. Thus on macOS the file is
`~/Library/Application Support/ufa/config.toml`, and on Windows it is
`%APPDATA%\ufa\config.toml`. The README states the three paths.

**The cost is a new review cycle.** The fix is prose in an example file. This
round of the review loop is record-only, and a fresh review reads the changed
line and can find a new nit in it. Then a new fix round starts, and the loop
does not end clean. The harm is small. Lines 3 and 4 of the same file tell
the reader to run `ufa config path`, which prints the path on each system.
Line 12 names the file in an aside about `ufa config setup`, and it is not a
step to obey. `ufa config setup` writes the file, thus the reader does not
type that path.

**The boundary.** This decision settles only the path in the aside on line
12. A step that tells the reader to make or edit a file at a path that is
wrong for the system of the reader is a new finding.
