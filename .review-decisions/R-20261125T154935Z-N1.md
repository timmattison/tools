## `src/nle/src/commands.rs` — the `beta` child starts through tauri-plugin-shell, not through `childenv`

**Settled** 2026-11-25 (branch 170, finding R-20261125T154935Z#N1)

The finding is accurate. `beta_command` builds the child with
`app.shell().command("beta")`. tauri-plugin-shell 2.3.6 makes that child with
its own `std::process::Command::new` (`process/mod.rs:167`), and its `Command`
has `env_clear` but no `env_remove`. Thus the `beta` child keeps each inherited
`GIT_*` variable. The test
`beta_command_finds_beta_in_cargo_bin_from_the_finder_path` starts `/bin/echo`
the same way. The clippy ban does not see a spawn inside a dependency, and
CLAUDE.md ("What the Ban and the Guard Do Not Prove") names that gap.

The leak stops at `beta`. `beta` is a binary of this workspace, and the ban
covers its code. It starts `ffmpeg` with `childenv::command`
(`src/beta/src/export/video.rs`), and its recorder removes each name that
`childenv::inherited_git_variables` gives (`src/beta/src/recorder.rs`). Thus no
`GIT_*` variable from the app gets to a git process. `/bin/echo` ignores the
variables. An app that starts from Finder or the Dock has no `GIT_*` variable.

The cost of a fix: replace the shell plugin with
`tokio::process::Command::from(childenv::command("beta"))`, change the
signature of `beta_command`, write the tests again without `mock_shell_app`,
and remove the plugin from `lib.rs`, `Cargo.toml`, and the capabilities. That
change is new code for one more review round, and it removes no risk that
exists today.

The boundary: a report that the `beta` child of `nle` keeps `GIT_*` variables
is this decision. These changes reopen it:

- `nle` starts a different program through the shell plugin.
- `beta` starts a child that does not shed the `GIT_` prefix.
- `nle` starts `beta` from a git hook or from a different tool that sets `GIT_*`.
