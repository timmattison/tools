## `src/nwt/src/main.rs` — the `git worktree add` of `try_create_worktree` keeps the inherited git environment

**Settled** 2026-09-03 (branch issue-439, finding R-20260903T225843Z#I5)

`branch_exists` calls `gitscratch::shed_inherited_git_environment`, which removes
every inherited variable whose name starts with `GIT_`. The `git worktree add` of
`try_create_worktree`, whose failure `branch_exists` classifies, removes no
variable. Under a leaked `GIT_DIR` the add acts on one repository, and the branch
question answers about a different one. The misclassification this branch fixes
then comes back. Before this branch both facts came from the one command, and two
facts from one command do not disagree.

The finding is accurate. It is not fixed, because each fix available costs more
than the defect.

- **A blanket shed on the add decides a design question that issue #415 owns.**
  #415 exists to settle how the production git children of `nwt` treat the
  inherited environment. Its argument is that a blanket `GIT_*` prefix strip is
  correct for a test fixture and wrong for production. A user who exports
  `GIT_CONFIG_GLOBAL` means it, and `missing_hooks_path` reads that config to
  predict what git does at commit time. #415 proposes a prefix strip plus an
  allowlist of `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM`, `GIT_SSH`,
  `GIT_SSH_COMMAND`, `GIT_ASKPASS` and `GIT_TERMINAL_PROMPT`. A blanket shed on
  the add settles that question in passing, on a branch about error
  classification. It also changes what the `post-checkout` hook of a repository
  sees during the add.
- **The allowlist fix is the whole of #415, done on the wrong branch.** #415
  carries a pair of constants, a disjointness rule against the variables git
  exports into a hook, three tests, and an acceptance proof against a decoy
  repository. That work belongs to its own review.
- **A `branch_exists` that keeps the inherited environment restores agreement and
  keeps the wrong answer.** Both commands then act on the foreign repository, so
  the classification agrees with an add that already went to the wrong place. It
  also makes a fourth call site that sheds nothing, against the direction #415
  sets.

**What the accepted consequence is.** A run that inherits a `GIT_*` variable
reports a branch collision as a directory collision. That run needs a leaked
variable to reach the fault, and a normal run of `nwt` does not start inside a git
hook. The same run already sends its `git worktree add` to the wrong repository.
That is the larger fault, and it is the subject of #415.

**What this entry records.** `try_create_worktree` is a fourth call site. #415
names three sites: `get_tracked_files`, `bootstrap_hooks` and
`missing_hooks_path`. It calls them "all identical", and gives each one a
three-name `env_remove`. The `git worktree add` removes no name, so the
prefix-plus-allowlist fix of #415 does not reach it. This file records that gap.
The user decides what goes on GitHub.

**The boundary.** This decision settles *whether the `git worktree add` of
`try_create_worktree` sheds the inherited `GIT_*` family on this branch*. A
finding that asks for that shed, or that observes the add and `branch_exists` read
different environments, is settled here. It does not settle `branch_exists`
itself: a wrong answer from `show-ref`, or a branch question asked on a path that
makes no branch, is a real finding. It does not cover the three call sites #415
names. It does not settle what production keeps and what production drops. That
design question stays open in #415, and a decision there reopens this entry. A
misclassification observed in the wild reopens it. A run that demonstrably acts on
the wrong repository belongs to #415 and not here.
