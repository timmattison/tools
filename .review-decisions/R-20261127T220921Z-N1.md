## `src/nle/src/ui/timeline/tests.rs` `a_chapter_after_the_end_of_the_timeline_shows_no_marker` — the name of the test stays

**Settled** 2026-11-27 (branch issue-164, finding R-20261127T220921Z#N1)

The finding is accurate. The name of the test states a rule about the end of
the timeline, but `ChapterRow::of` hides only a chapter outside the window.
The test passes because its 60 s fixture puts the chapter at 90 s at 1,800 px,
outside the window of 1,200 px. In a project shorter than about 1.2 s, or in a
project with no clip, the window is wider than the project. Then a chapter
after the end of the project gets a marker in the empty area after the clips.

That behavior is the rule of the code, and the doc of `ChapterRow::of` states
it: "or `None` for a chapter outside the window". A marker at the correct time
in the empty area after the clips shows the user where the chapter is. The
chapter panel tags the same chapter late. Thus the rule needs no change, and
the defect is only the name of the test.

**The fix costs more than the defect.** The fix renames a test whose assertion
is correct. The new name is test code that a fresh review reads. The loop then
starts one more fix round for the name of a test.

**The boundary.** This record settles only the name of the test. These
occurrences reopen it:

- a change of `ChapterRow::of` that draws a marker outside the window, or that
  hides a marker inside the window
- an assertion of the test that expects a wrong value
- a decision that a chapter after the end of the project must get no marker
  in each case, also when the window reaches its time
