## `scripts/plugin-checks.sh` — the test of the glob match uses `[ -d ]`, not `[[ -d ]]`

**Settled** 2026-11-25 (branch github-actions-ci, finding R-20261125T164912Z#N1)

The finding is accurate. `scripts/plugin-checks.sh` is a bash script, and
`[ -d "${plugin}" ] || continue` uses `[ ]`. Item 4 of the Shell Script Style
Guidelines in `CLAUDE.md` says to use `[[ ]]` in bash, and
`scripts/rust-checks.sh` uses `[[ ]]`.

**The cost of the fix is a new review cycle.** This round of the review loop is
record-only. A change to the line is a new change that a review must read, and
a fresh review can find a new nit in it. Then a new fix round starts, and the
loop does not end clean. The test is correct: the variable has quotes, thus
`[ ]` and `[[ ]]` give the same result for each path. The behavior of the
script does not change.

**The boundary.** This decision settles only the style of this one test. A
`[ ]` test that gives a wrong result, for example on a variable with no quotes
that splits into words, is a new finding.
