## `src/workit/tests/manifest.rs` — the comment about `CARGO_TARGET_DIR` gives a reason that `cargo metadata --no-deps` does not need

**Settled** 2026-11-25 (branch workit, finding R-20261125T043207Z#N8)

The finding is accurate. The comment above `.env("CARGO_TARGET_DIR", …)` says
that the build products of the `cargo metadata` child belong inside the
fixture. The module doc says that the target directory keeps the run from
disturbing the workspace. On 2026-11-25, `cargo metadata --no-deps --offline`
in a temporary workspace wrote no `target` directory and no `Cargo.lock`. Thus
the child has no build products, and the stated reason is false.

It is not fixed, because the fix is prose or the removal of a harmless line:

- **The line does no harm.** The variable points at a directory inside the
  fixture, which the test deletes. A later flag that makes the child build
  keeps its products there.
- **No behavior changes.** A new comment, a new module doc, or the removal of
  the line changes no result of a test.
- **The cost is a new review cycle.** This round of the review loop is
  record-only. A change of the comment and the module doc is text that a review
  must read, and a fresh review can find a new nit in it. Tim chose to settle
  each nit with a record (decision H-742-2 on issue #742).

**The boundary.** This decision settles the comment and the module-doc clause
about `CARGO_TARGET_DIR` of the `cargo metadata` child in
`tests/manifest.rs`. `.review-decisions/R-20261124T182455Z-N1.md` still
settles the working directory of that child. A child that builds and shares the
`./target` of the workspace is a new finding.
