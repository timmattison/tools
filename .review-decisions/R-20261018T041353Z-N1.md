## Commit order on a pushed branch — the test of the job filter in `settle` came after its green commit

**Settled** 2026-10-18 (branch issue-566, finding R-20261018T041353Z#N1)

The review found that the green commit `088d3235` added this filter to `settle` in
`src/ha/src/board.rs`, and no test at that commit could fail for it:

```rust
.filter(|old| runs.get(position).is_some_and(|run| run.id == old.run.0))
```

The filter keeps the job part of the selection only when the run at the settled
position is the run that was selected. Without it, a run that leaves the board
gives its job position to the next run. The test that can fail for the filter is
`a_run_that_leaves_the_board_takes_the_selected_job_with_it`, and commit `bc95326f`
gave it that power, after the green commit. The TDD rule in `CLAUDE.md` asks for
the red commit first. The finding is accurate.

It is not fixed, because the defect is the order of two commits and nothing else.

**The coverage is real.** The run of `address-issues` for this finding did the
mutation again on `8bfaded6`, with `cargo test -p ha --lib board::tests`. With no
filter, `a_run_that_leaves_the_board_takes_the_selected_job_with_it` fails on its
assertion at `board.rs:1715`, and the other 74 board tests pass. Thus the test can
fail for the behavioral reason. Only the commit order is wrong.

**The one fix is a rewrite of a pushed branch, and it buys nothing durable.** To
fix the order, the change of `bc95326f` must move into the red commit `7baed9ac`.
That gives a new SHA to each commit from `7baed9ac` to HEAD, which was 16 commits
at the time of the review. `origin/issue-566` holds those commits, thus the rewrite
needs a force push. `block-dangerous-git.ts` refuses a force push with no override,
thus only Tim can run it. The review `R-20261018T041353Z` ends on `8bfaded6`, which
is one of those commits. After the rewrite, `pr-merge-gate.ts` finds that the
commit is not on the branch, calls the review `rewritten`, and refuses the merge
until a fresh review of the whole branch. Against that cost: this repository
squash-merges every PR with an explicit `--subject` and `--body`, thus no commit of
this branch reaches `main`.

This decision applies the reasons of `R-20261017T222526Z-N1` to this branch. That
decision settled the same shape for the branch `issue-565` only.

**The boundary.** This decision settles the order of `088d3235` and `bc95326f` on
the branch `issue-566` only, where the test exists and a mutation shows that it can
fail. It does not settle a missing test, or a test that nobody showed can fail. It
does not change the rule of `R-20260820T153740Z-N2` for an unpushed branch where no
review names the commits that a rebase moves. It does not permit implementation
first as a habit. A third branch with the same shape is a new finding about the
process, not a re-litigation of this decision.
