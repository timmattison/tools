## `src/workit/tests/manifest.rs` — the `cargo metadata` child of the manifest tests takes no working directory

**Settled** 2026-11-24 (branch workit, finding R-20261124T182455Z#N1)

The finding is accurate. The `cargo metadata` command in the manifest tests
(lines 266-285 at commit 7bc226f) takes no `current_dir`. Thus it starts in
`src/workit` and reads each `.cargo/config.toml` above that directory. The
`workit` runs of the same file start in the fixture.

It is not fixed, because the defect is latent:

- **No such file exists.** On 2026-11-24, no `.cargo/config.toml` lies in
  `src/workit`, in `src`, at the root of the worktree, or in a directory above
  it, and `origin/main` holds no `.cargo` directory. The only config that the
  child reads is `~/.cargo/config.toml`, and cargo reads that file from each
  working directory.
- **A file there changes more than this child.** A `.cargo/config.toml` above
  `src/workit` also changes the build of the test binary itself, because
  `cargo test` starts in the same tree. A working directory on one child does
  not make the run hermetic against such a file.
- **The command already pins what can change the answer.** It gives
  `--no-deps`, `--offline`, `--manifest-path`, and a `CARGO_TARGET_DIR` inside
  the fixture, and it removes each inherited `GIT_*` variable. The test reads
  only the list of members.
- **The branch stopped at the blocking level.** The branch took eight reviews
  before this record. At the stall (decision H-742-2 on issue #742), Tim chose
  to fix each blocking finding and to settle each nit with a record.

The boundary: this settles the working directory of this one `cargo metadata`
child. A test that runs `git`, `gh`, or a cloud tool with no working directory
and no scrub is a different finding. A `.cargo/config.toml` that appears above
`src/workit` and changes the answer of this child reopens this decision.
