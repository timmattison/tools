## `README.md` `nle` color scheme — the last step of the restore says "the SGR colors that the recording set", but the code writes only the converted ones

**Settled** 2026-11-27 (branch issue-166, finding R-20261127T061843Z#N1)

The finding is accurate. `SchemeEditor::restore` in
`src/nle/src/filters/color_scheme.rs` ends with `SlotStates::restore`, which
writes one SGR with only the slots in `SlotState::Set { converted: true }`. A
kept color (`38;5;196` under `cube: keep`) and a slot after SGR 0, 39, 49, or 59
get no SGR. The module doc states that limit, but the README sentence states the
wider set.

The effect on the screen is the same. A kept color is already the color of the
recording in the terminal, and a slot after a reset or a default is already at
the default. Thus the text after the range has the colors of the recording in
each case, as the next sentence of the README says.

more clause in the README sentence. Prose fixes nothing in the code. This round
of the review loop is record-only. Each fix is a diff that a review must read,
