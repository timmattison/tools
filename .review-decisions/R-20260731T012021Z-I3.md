## `zellij-install/zellij-install.ts` — four defects on the destructive path, filed rather than fixed here

**Settled** 2026-09-04 (branch issue-328, findings R-20260731T012021Z#I3, #I4,
#I7, #I8)

Four blocking findings name `zellij-install/zellij-install.ts`: `--ref` reaches
`sh -c` as text at `:361`, a flag with a missing value falls back to the default
at `:289`, both destructive guards read stderr as data at `:334` and `:354`, and
nothing validates the argv vocabulary at `:287`.

All four are accurate. All four were re-checked against the current `main` on
2026-09-04 and all four are live. They are tracked in
[#452](https://github.com/timmattison/tools/issues/452).

They are not fixed on this branch, because this branch does not touch the file:

- **The review read a merge, not this branch's work.** Round
  `R-20260731T012021Z` covered the range `e13ab47..fd32d98`, and `fd32d98` is a
  merge of `main` into `issue-328`. Thus the range carried the
  `zellij-install` changes that PR #336 landed on `main`, and the round read
  them as the work of this branch. `git diff --name-only main...HEAD` lists 34
  files, and none of them is under `zellij-install/`. The file last changed in
  `1cdd4e12`, which is on `main`.
- **The fix is a rewrite of the process helpers of a second tool.** Finding #I3
  changes `run()` and `stream()` from `sh -c` to an argv array, which touches
  every call site in the file, including the `lsof` call at `:206` that needs
  its shell for a stderr redirect. Findings #I4 and #I8 rewrite `parseArgs`
  together. Finding #I7 splits the return type of `run()` and re-reads both
  guards. That work carries its own tests and its own review.
- **A branch about `grind` and `gitscratch` is the wrong place to review it.**
  The four findings are a security and correctness change to a TypeScript
  installer. To land them here hides them under a Rust rebase dry-run, and the
  reviewer who reads this PR is reading for the wrong thing.

**What the accepted consequence is.** `zellij-install` keeps all four defects
until #452 is done. The exposure needs a hand-typed `--ref`, a hand-typed flag
with a missing value, or a typed flag name that misses. The tool is a personal
installer that one person runs by hand, so no automated path reaches it.

**The boundary.** This decision settles *whether the four findings are fixed on
branch `issue-328`*. A finding that repeats any of the four against
`zellij-install/zellij-install.ts` is settled here and belongs to #452. It does
not settle the defects themselves, which stay open. It does not cover any other
file, and it does not cover `swt.ts`, whose `sh -c` helper interpolates only
repo-internal values. A branch that changes `zellij-install/zellij-install.ts`
reopens every one of the four.
