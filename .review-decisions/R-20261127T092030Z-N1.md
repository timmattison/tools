## `src/wdid/tests/defs-render.rs` `the_json_gives_the_state_and_the_reasons` — `.all()` on `never_used` passes for an empty list

**Settled** 2026-11-27 (branch issue-728, finding R-20261127T092030Z#N1)

The finding is accurate. The last assertion of the test holds `never_used`
with `.all(|entry| entry["name"] == "lonely")`, and `.all()` is true for an
empty list. Thus that assertion alone does not hold that `never_used` has the
entry `lonely`.

The gap is narrow. The same test holds that the entry `lonely` in
`definitions` has the classification `never_used`. `render.rs` builds the list
`never_used` from that classification with `named(&with(&every,
Classification::NeverUsed))`, and two other tests of the same file,
`json_document` and `the_json_holds_the_origin_and_mine_of_each_definition`,
compare the whole list `never_used` with `assert_eq!`. Thus a defect that
drops `lonely` from the list and keeps its classification must be a defect of
that shared builder, which those two tests find.

The fix costs more than the defect. The branch is in a record-only round of
its review loop. A changed assertion is new code that a fresh review reads,
and that review can find a new nit in it. That starts a new fix round for a
gap that two other tests close.

The boundary: this decision settles the assertion at
`src/wdid/tests/defs-render.rs:717-721`. A change that builds `never_used`
other than from the classification of each entry reopens this decision, and
that change compares the whole list in this test in the same commit.
