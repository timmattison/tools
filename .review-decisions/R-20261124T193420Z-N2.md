## `src/cdva/tests/lines.rs` — the planted build directory stays in the shared source tree

**Settled** 2026-11-24 (branch 170, finding R-20261124T193420Z#N2)

`PlantedBuildOutput` writes
`src/cdva/tests/planted-<pid>-<nanos>/dist/assets/index.js` for the length of
one walk, and `Drop` removes it. The guard walks with `no_ignore: true`, and
`cdva::walk` stops at the first entry error. A second run of the cdva tests at
the same time can list the planted directory of the first run. If the first run
removes the directory before the second run reads it, the second run fails with
`cannot read the tree under`. The guard in `src/cdva/tests/repository.rs` can
fail in the same way.

The finding is accurate. It is not fixed, because:

- **The guard must walk the real repository.** Its question is whether the walk
  of this repository skips build output. A plant in a temp directory outside
  the tree does not answer that question.
- **The other fix changes production code.** A `cdva::walk` that skips an entry
  that is gone changes what `cdva` reports for each tree that changes during a
  walk. That change is larger than the risk.
- **The window is small, and the failure is visible.** It opens only when two
  runs of the cdva tests overlap, and it closes after one directory read. The
  failure is a red test that a second run clears. It is not a wrong count.
- **The round is record-only.** A fix is new code, and it starts a new review
  cycle.

The boundary: one observed failure of either guard with
`cannot read the tree under` and a `planted-` path reopens this decision.
