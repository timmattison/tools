## `src/ufa/src/config.rs` — the hint of a settings line that cannot be parsed names one cause only

**Settled** 2026-11-25 (branch ufa, finding R-20261125T162254Z#N1)

The finding is accurate. `load_environment_file` adds "Put quotes around a
value that holds a space." to each `dotenvy::Error::LineParse`. The hint
applies to one cause. For a value with no closing quote, the value already has
a quote. For a bad key, for example `.KEY=VALUE` or a line with no `=`, the
hint does not apply either.

**The cost is a new review cycle.** This round of the review loop is
record-only. A change to the hint is new text in an error, and a hint for
each cause needs a new test for each cause. A fresh review reads both and can
find a new nit. Then a new fix round starts, and the loop does not end clean.
The harm is small. The message names the file and the line where the setting
starts, and the user finds the cause on that line. The hint is one example of
a cause, and it does not stop the user from seeing a quote with no end or a
bad key on the named line.

**The boundary.** This decision settles only the words of the hint. A wrong
line number is a new finding. A message that shows the text of the line is a
new finding too, because that line can hold a key.
