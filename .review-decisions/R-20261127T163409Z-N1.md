## `src/nle/src/ui.rs` `SPEED_HINT` — "on the timeline" stays as it is beside the new timeline view

**Settled** 2026-11-27 (branch issue-150, finding R-20261127T163409Z#N1)

The finding is accurate in part. This branch adds a visible timeline, and its
ruler shows project time, before the filters. Before this branch, "the
timeline" in the hint had no visible referent. Now a person can read "the
timeline" as the ruler. The ruler shows a different time when an earlier speed
change is in the list.

The hint does not name the bare timeline. It says "the timeline after the
speed changes above". That qualifier names the time that the panel uses: the
time after the earlier changes of the list, not the project time of the ruler.
The README paragraph of the timeline says that the ruler shows the time before
the filters. It also says that a filter that changes the speed moves the
playhead away from the time of the ruler. Thus the hint and the README do not
state a wrong rule. The defect is a second reading of one word of help text.

**The fix costs more than the defect.** The fix changes `SPEED_HINT`, its
expected text in `src/nle/src/ui/tests.rs`, and the README paragraph of the
speed panel. That change is new text that a fresh review must read. The loop
then starts one more fix round for one word of help text.

**The boundary.** This record settles the word "timeline" in `SPEED_HINT` and
in the README sentence "The times of a new region are on the timeline after
the speed changes above it." Decision R-20261126T201057Z-N1 settles the word
"above" in the same text. These occurrences reopen this record:

- a change that removes "after the speed changes" from the hint or from the
  README sentence, so that the text names the bare timeline
- a change that makes the speed panel read its times in a time that is not the
  time after the earlier changes of the list
- a control that copies a time from the ruler into the fields of the speed
  panel
