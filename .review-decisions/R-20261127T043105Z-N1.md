## `src/ufa/README.md` — the `.env` example says that `config.toml` takes `UNIFI_INSECURE=true`

**Settled** 2026-11-27 (branch ufa, finding R-20261127T043105Z#N1)

The finding is correct. The comment `# .env file beside the config file, or
config.toml` puts the line `UNIFI_INSECURE=true` in both files. `config.toml`
has no key `UNIFI_INSECURE`, because the field of `Config` is `insecure`. The
toml block directly below the comment gives the correct form,
`insecure = true`.

The defect fails in the safe direction. `Config` does not refuse an unknown
key, thus a user who pastes the line into `config.toml` gets a key with no
effect, and certificate verification stays on. The next block of the README
shows the correct spelling. A fix changes one comment, and it starts one more
review cycle.

**The boundary.** A doc that gives a form that turns verification off with no
warning line, or a form that `ufa` reads in a different way than the doc says,
is a new occurrence. This comment is settled.
