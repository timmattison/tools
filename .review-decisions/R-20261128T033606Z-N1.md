## `src/nle/src/filters/idle_compression.rs` and `README.md` — the idle filter replays on the size of the screen at its step, not on the size of the recording

**Settled** 2026-11-28 (branch issue-167, finding R-20261128T033606Z#N1)

The finding is accurate. The merge `4fd72c21` brought the screen form of a
filter from `main` (issue #165, PR #803, branch issue-165). In `apply` of
`src/nle/src/pipeline.rs`, the Span arm sets `SpanContext::size` to the size of
the screen at the step of the filter. A screen filter on `All` before the idle
filter, for example a crop to 40x10, changes that size. The idle filter then
replays on 10 rows, and `ignore_bottom_rows` counts up from row 10. Three
places still say "the size of the recording": lines 5-6 and 22-23 of the module
doc of `idle_compression.rs`, and the entry of `idle-compression` in
`README.md` (lines 6751-6752).

The code is correct. The events after a crop draw on the cropped screen, thus
a replay on the size of the recording reads them on the wrong screen. The doc
of the field `SpanContext::size` says "the size of the terminal that the
events draw on", which is true. Only the prose of the idle filter is stale.

The cost of the defect is small. It shows only when a project puts a screen
filter on `All` before the idle filter. The idle panel of the window appends
its filter at the end of the list. A count of rows to ignore that is too large
for the cropped screen is refused, and the error gives the rows of the screen.
No test and no tool reads the prose.

**The fix costs more than the defect in this round.** The fix is prose in a
Rust source file and in `README.md`. This round of the review loop is
record-only. A change of the text is new text that the next review reads, and
that review can find a new nit in it. Then one more fix round starts. A change
of the first paragraph of the module doc must also wrap that paragraph again,
as record R-20261128T030045Z-N1 says.

**The boundary.** This record settles only the three statements that the idle
filter replays on the size of the recording. These occurrences reopen it:

- a run that changes the text of the module doc of `idle_compression.rs` or of
  the `idle-compression` entry in `README.md`, and leaves these statements
- a change of the code, so that the idle filter does not read the size from
  `SpanContext::size`
- a panel or a command of the window that puts a screen filter before the idle
  filter
- a new statement in the docs that the size of a `SpanContext` is the size of
  the recording
