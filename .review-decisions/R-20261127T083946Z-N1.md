## `src/nle/src/pipeline.rs` `FilterRegistry::render` — rule 6 of the doc does not name the mark times

**Settled** 2026-11-27 (branch issue-167, finding R-20261127T083946Z#N1)

The finding is accurate. Rule 6 of the doc of `FilterRegistry::render` says
"Each event time and the duration must be finite". The branch made
`run_with_end` also refuse a mark time that is not finite after the last
filter, with the text "the render gives the time {time} s, which is not
finite". `render` calls `render_with_marks`, which calls `run_with_end`. Thus
`render` also fails on a mark time that is not finite, and rule 6 does not say
so. Rule 6 is in the description of `render`, not in its `# Errors` section.
Thus record R-20261127T022719Z-N2 does not cover it.

**The fix costs more than the defect in this round.** The defect is a list of
rules in a doc that names too few times. The code refuses each mark time that is
not finite, and the error text that a user reads gives the time and the rule.
The doc of `run_with_end` names "a mark time", step 9 of `FilterFn` and step 7
of `SpanFilterFn` state the mark rule, and the PR body states it too. Thus no
caller gets a wrong behavior or a wrong message, and each caller already handles
`NleError::RenderError`.

The fix is a change of a document. This round of the review loop is
record-only. A change of a document starts one more review cycle, and that
review can find a new nit in the new text.

**The boundary.** This record settles only the omission of the mark times from
rule 6 of the doc of `render`. Each of these occurrences reopens it:

- code that accepts a mark time that is not finite after the last filter, or
  that gives that error as a different `NleError` variant
- a rule of the doc of `render` that states a rule wrongly, not only too
  narrowly
- the doc of `run_with_end`, `FilterFn`, or `SpanFilterFn` that stops naming
  the mark rule

Record R-20261127T022719Z-N2 settles the same two mark errors in the `# Errors`
docs of `run`, `render`, and `render_with_marks`. This record does not change
that record.
