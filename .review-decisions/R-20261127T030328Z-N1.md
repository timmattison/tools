## `specs/2026-11-26-nle-plugin-architecture-design.md` step 4 of the install — nothing deletes a temporary folder that a crash leaves

**Settled** 2026-11-26 (branch issue-169, finding R-20261127T030328Z#N1)

The finding is accurate. Step 4 of "Load from a URL" writes the new plugin into
a temporary folder of the plugins directory, whose name starts with `.`. The
load skips each `.` folder, and slice 7 asserts that skip. No step deletes such
a folder. Thus each crash during an install keeps up to 64 MiB in the plugins
directory, with no end.

The cost of the defect is disk space, and only after a crash during an
install. No leftover folder loads, thus a leftover changes no render. The user
can see each leftover with `ls -a` and delete it.

**The fix costs more than the defect in this round.** The finding gives a
sweep at start: a fixed prefix for the temporary folder, and a delete of each
folder with that prefix before the load. That sweep deletes folders in the
plugins directory. Thus it needs its own test, and a test that it deletes no
folder of an installed plugin.

This round of the review loop is record-only. A change of the spec starts one
more review cycle, and that review can find a new nit in the new text. Slice 7
writes the install code, and a review of slice 7 reads the real temporary
folder.

**The boundary.** This record settles only the temporary folder that a crash
during an install leaves. The records of R-20261126T223433Z#N2 and
R-20261127T032320Z#N4 settle the same subject from other findings. Each of
these occurrences reopens this record:

- a leftover `.` folder loads, or changes a render
- the install code of slice 7 leaves a temporary folder with no crash, for
  example after a refusal of the user or a failed download
- a temporary folder grows past the size limits of step 2
