## `src/ufa/src/main.rs` — a 403 still makes `ufa` read the key from 1Password again (second report)

**Settled** 2026-11-26 (branch ufa, finding R-20261126T160105Z#N2)

This finding is the same as R-20261126T031142Z#N2, from a later review. It
asks for a read again after a 401 only, or for a doc that states the cost of
the read again after a 403.

The decision of `.review-decisions/R-20261126T031142Z-N2.md` applies, for the
same reason. No test on a real controller or on the Site Manager API shows
that a revoked key always gets a 401. A narrower rule can thus leave a rotated
key broken until the user deletes the cache file, and that costs more than one
read of 1Password for each refused command of a key with limited permissions.

Commit `ae90f5828` gives the second option of the finding: the doc of
`run_with_the_current_key` and the README now state that a 403 can refuse a
current key with limited permissions, and that each such command reads
1Password one more time.

**The boundary.** The boundary of `.review-decisions/R-20261126T031142Z-N2.md`
applies.
