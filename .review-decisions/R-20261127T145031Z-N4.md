## `src/ufa/src/site_manager/utils.rs` `is_cloud_console_url` — a case or port spelling of the cloud console URL gets past the refusal

**Settled** 2026-11-27 (branch ufa, finding R-20261127T145031Z#N4)

The finding is accurate. `is_cloud_console_url` compares the raw text with
`starts_with`, case-sensitive, before `Url::parse`. Thus
`HTTPS://UNIFI.UI.COM/consoles/X` and `https://unifi.ui.com:443/consoles/X`
get past the refusal in `UnifiClient::new` (`src/ufa/src/client.rs`).
`Url::parse` then makes the host lowercase and removes the default port. Thus
`ufa` sends a controller request, with the controller key, to
`unifi.ui.com`.

**The refusal is a message about support, not a guard of the key.** Its text
says that cloud console URLs "are not yet supported for direct API access".
`--url` sends the key to each host that the user names, and that is the
contract of the flag. A user who types a different host also sends the key
there. In this case, the user typed the URL, the host is the server of the
vendor, and the request uses TLS.

**The fix costs more than the defect in this round.** The fix moves the check
after `Url::parse` and adds tests of the spellings. That code starts one more
review cycle, and this round of the review loop is record-only.

**The boundary.** This record settles only a spelling of a cloud console URL
that the user typed. Each of these occurrences reopens it:

- `ufa` sends the controller key to a host that the user did not name, for
  example a URL that `ufa` builds from discovery or from 1Password
- the refusal becomes a guard of the key, for example a refusal that a
  different command trusts to keep the key off a host
- a request with the key over plain HTTP to a host that the user did not ask
  for
