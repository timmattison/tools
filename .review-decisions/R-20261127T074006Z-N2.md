**Settled** 2026-11-27 (branch issue-161, finding R-20261127T074006Z#N2)

The finding is correct. `u8::from_str_radix("+f", 16)` gives `Ok(15)`, and
no input of `rgb_parse_refuses_bad_text` holds a `+`. Thus a mutant that
removes the `is_ascii_hexdigit` check of `Rgb::parse` passes each test.

The check is in the code, and its comment gives the reason for it. The fix
is two more inputs in the list of a test. This round of the review loop is
record-only. A test change is new code that a review must read, and that
review can start a new fix round. If a later change removes the check,
`#+fffff` parses as the color `#0fffff`. That text comes from the project
file of the user, and the result is a valid color.

Boundary: a change to `Rgb::parse` reopens this decision.
