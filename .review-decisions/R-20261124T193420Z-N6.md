## `src/nle/run-nle.sh` — the script does no check of pnpm

**Settled** 2026-11-24 (branch 170, finding R-20261124T193420Z#N6)

`run-nle.sh` names the account and the repair when cargo, the Tauri CLI, or
portplz is missing (4f89bd32), but not when pnpm is missing. With no pnpm on
the PATH and no `frontend/node_modules`, `set -e` stops the script with
`pnpm: command not found`. With `frontend/node_modules` present,
`cargo tauri dev` fails later, at the `pnpm dev` of `beforeDevCommand`.

The finding is accurate. It is not fixed, because:

- **The bare message names the missing tool.** The three checks exist because
  their raw failure names a different thing: a missing Tauri CLI shows as
  "no such command: `tauri`". `pnpm: command not found` names pnpm, and the
  repair is to install pnpm.
- **The round is record-only.** A fix adds a fourth check and a shim test in
  `src/nle/tests/run-nle-script.rs`. That change is new code, and it starts a
  new review cycle.

The boundary: a report of a person who could not find the repair from the bare
message, or a change to how the script installs the frontend, reopens this
decision.
