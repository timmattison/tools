`site_manager_api_key` when the user pastes a key in setup. The field is thus a
current field, not only a field of old configs. The doc of
`site_manager_key_falls_back_to_the_plaintext_field`, its literals, and its
`expect` message call it legacy.

names no 1Password path. Only the words around the assertion are stale. A fix
changes one test doc, two literals, and one message. That change starts one more
review cycle, and it changes nothing that the test proves.

**The boundary.** A doc or a message that a user reads, and that calls the
plaintext field legacy or deprecated, is a new occurrence. The words of this one
test are settled.
