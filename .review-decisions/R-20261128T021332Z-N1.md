## `src/nle/src/pipeline.rs` `render` — the `# Errors` section names the errors of `FilterRegistry::run`

**Settled** 2026-11-28 (branch issue-165, finding R-20261128T021332Z#N1)

The finding is accurate. Commit `390713c1` added to the `# Errors` section of
`FilterRegistry::run` the refusal of each filter of the screen form, because
`run` has no header and thus no size to give. The `# Errors` section of
`render` is older than the branch, and it still says that `render` gives "the
errors of `FilterRegistry::run`". `render` gives a size to `run_with_end`, thus
it accepts a screen filter. The test
`a_screen_filter_on_all_sets_the_size_of_the_rendered_recording` holds that
behavior. The section also does not name the errors that only a screen filter
gives in `render`: an error answer, a size with no cells, a new size on a
range, and a time outside its region.

No output is wrong. The code accepts a screen filter in `render` and refuses it
in `run`, and the tests hold both results. The defect is only the text of one
doc comment.

**The fix costs more than the defect.** The fix is prose: a new list of errors
in the doc comment of `render`. This round of the review loop is record-only. A
change of the doc comment is new text that a review must read, and that review
can start one more fix round. The rule list of `render` above the section
already says that a screen filter sets `width` and `height`, thus a reader of
the full comment does not conclude that `render` refuses a screen filter.

**The boundary.** This record settles only the text of the `# Errors` section
of `render`. These occurrences reopen it:

- a change of `render` that refuses a screen filter, or that gives an error
  that neither `run` nor the screen form gives
- a caller that matches on the error text of `render` and depends on the list
  in the doc comment
- a change of the `# Errors` section of `render` that leaves it wrong about a
  case other than the screen form
