## `src/repo-guards/src/op_wall.rs` — `rust_sources` follows symbolic links

**Settled** 2026-11-27 (branch ufa, finding R-20261127T131122Z#N4)

The finding is correct. `rust_sources` asks `Path::is_dir`, which follows a
symbolic link. `clippy_superset::walk` reads `entry.file_type()` for this
reason. In `op_wall`, a link to an ancestor reads the tree again for each level,
until the system refuses the path. Then the read of the directory fails as
`OpWallError::ReadDir`. A link to a directory outside the member is read as a
source of the member.

Each result fails in the safe direction. A loop ends in an error, not in a
clean report. A link to more files can only add a violation, and it cannot hide
one. On 2026-11-27, `find src -type l` found 0 links in the source trees of the
workspace. A fix changes the walk of a guard and adds a fixture with a link,
and it starts one more review cycle.

**The boundary.** A walk that skips a real source file of a member, or that
reports clean when a link hides a file, is a new occurrence. A symbolic link
that a commit adds to a member source tree is a new occurrence too. The use of
`Path::is_dir` in a tree with no links is settled.
