## `README.md` — the `cargo tauri build` step does not name the install of the frontend dependencies

**Settled** 2026-11-25 (branch 170, finding R-20261125T021115Z#N3)

The finding is accurate for some versions of pnpm. `beforeBuildCommand` in
`src/nle/tauri.conf.json` runs `pnpm build` in `src/nle/frontend`, and that
script runs `tsc -b && vite build`. `src/nle/frontend/package.json` pins no
pnpm version.

A measurement on 2026-11-25 with pnpm 12.5.1 does not show the failure. A copy
of `src/nle/frontend` with no `node_modules` and no `dist` ran `pnpm build`.
pnpm installed the dependencies from `pnpm-lock.yaml` first, ran `tsc -b && vite
build`, and stopped with exit status 0. A pnpm that does not install before it
runs a script gives the failure that the finding describes. I did not measure
an older pnpm.

Tim accepted `cargo tauri build` from `src/nle` (finding
R-20261124T183444Z#I6). The README gives `./src/nle/scripts/dev.ts`, which
installs the frontend dependencies, before the build step. The cost of a fix: a
change to the README or to `beforeBuildCommand`, and one more review round, for
one sentence that the pnpm of this repository does not need.

The boundary: a report that the build step does not name `pnpm install` is this
decision. A build that fails with pnpm 12 or later on a fresh checkout reopens
it. A pin of a pnpm version that does not install before a run also reopens it.
