## `src/nle/src/commands/tests.rs` — the json-to-gzip link test reads the ending as a substring

**Settled** 2026-11-26 (branch issue-158, finding R-20261126T205525Z#N2)

The finding is accurate. `save_recording_to_refuses_a_json_link_to_a_gzip_name`
asserts that the message contains `must end in .json`. That text is also a
substring of `must end in .json.gz`. Thus a message that names the wrong
ending passes the assertion.

The test still does its main work:

- It asserts that the call gives `NleError::SaveError`.
- It asserts that the target file `b.json.gz` keeps its bytes, so a write
  through the link fails the test.
- The ending in the message comes from `matching_ending` of the path
  `a.json`. For `RECORDING_ENDINGS`, the only ending of that name is
  `.json`. A mutant that names `.json.gz` must read the ending from the end
  of the chain, which is a different function.

The cost of a fix: a change to the assertion, and a mutant of the code under
test to prove the new assertion. That change is new code in a test file, and
it starts one more review round, which can find a new nit in the new code.

The boundary: a report that this one assertion matches a substring is this
decision. These changes reopen it:

- The refusal message names the ending of the end of the chain, not the
  ending of the path.
- A second test of the refusal message relies on the same substring.
