## `src/nle/src/ui/export.rs` — the export status stays after a second recording opens

**Settled** 2026-11-26 (branch issue-158, finding R-20261126T205945Z#N3)

The finding is accurate. `App` sets `loaded` from one `Some` document to the
next, so `ExportBar` stays mounted, and its `status` signal stays. Only a
click on Export clears it. After an export of `a.json` and an open of
`b.json`, the bar still shows `Exported to /tmp/a-edited.json`. The error
banner clears on an open, but the export status does not.

The text stays true:

- It names the absolute path of the file that the export wrote. That file
  exists, and it holds the export of `a.json`.
- It does not name the open document, and it does not say that the open
  document was exported.
- No file is written, changed, or lost because of it. The next click on
  Export clears it before the check of the settings and before the dialog
  opens. A click that a bad setting stops clears it too (finding
  R-20261127T132133Z#I1).

The cost of a fix: a source path kept with the status text, a comparison
with the `metadata.file_path` of the open document, and a new window test
that exports, opens a second recording, and reads the `role="status"`
element. That fix is new code in the view, and it starts one more review
round, which can find a new nit in the new code.

The boundary: a report that the status text stays visible after a new
recording opens is this decision. These changes reopen it:

- The status text names the open document, or says that the open document
  was exported.
- The status shows during a later export, or after a failed export.
- A user reports that the stale status led to a wrong file.
