## `src/nle/src/types.rs` — the mode test of an existing file keeps 0o640

**Settled** 2026-11-24 (branch 170, finding R-20261124T193144Z#N1)

`test_save_keeps_the_mode_of_an_existing_file` sets 0o640 on a saved
recording, saves it again, and expects 0o640. A save creates its temp file with
0o666 less the umask. Under umask 026 or 027, that mode is 0o640. Thus on such
a machine, the test also passes when the copy of the old mode is removed.

The finding is accurate. It is not fixed, because:

- **The machines that run the test today prove the copy.** The machine of the
  pre-commit hook has umask 022 (measured on 2026-11-24). Under umask 022, the
  mutant check of 74bc0f6d shows that the test fails when the copy is removed
  (644 against 640).
- **The fix is a change to a test, in a record-only round.** A test that is
  correct under each umask picks its mode from a reference `File::create`, as
  `test_save_gives_a_new_file_the_mode_that_file_create_gives` does. That change
  is new code, and it starts a new review cycle for a test that already fails
  on the machines that run it.

The boundary: a run of the test under umask 026 or 027 reopens this decision.
A defect in the copy of the mode itself is a new finding, not this one.
