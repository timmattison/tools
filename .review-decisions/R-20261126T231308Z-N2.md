## `README.md` "What does not count" — an alias in the body of a function gets no use, and the README says why

**Settled** 2026-11-26 (branch issue-725, finding R-20261126T231308Z#N2)

The finding is accurate. Issue #725, section "The count", says that when the
body of a function calls a second function or an alias, that definition gets a
use through the first function. The branch counts only the functions that a
body calls (`count_word` in `src/wdid/src/defs.rs`). The README states the
limit and its reason under "What does not count", and the doc of
`defs::tally` states it too. The PR body does not name the departure from the
text of the issue.

The departure is correct, as the finding says. zsh and bash expand each alias
in a function body when they read the definition. Thus the body that `wdid`
gets holds the value of the alias, not its name, and no count can find the
alias there. Acceptance criterion 3 does not name this rule.

The fix costs more than the defect. The fix is prose in the PR body, and it
changes no behavior. A review reads the PR body, thus the new text can start
one more fix round. The README and the doc of `defs::tally` already give the
rule and its reason to each reader of the tool and of the code. This record
gives it to each later review.

The boundary: this settles where the departure is stated. A count that gives
an alias a use through a function body, or a README text that says an alias in
a function body counts, is a new finding.
