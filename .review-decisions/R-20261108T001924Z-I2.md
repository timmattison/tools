## `src/op-cache/tests/audit-trail.rs` — `Fixture::install_script` keeps `std::fs::write` until `write_executable` is on `main`

**Settled** 2026-11-08 (branch issue-640, finding R-20261108T001924Z#I2)

The finding is accurate. `Fixture::install_script` writes the fake `op`, and on
macOS the fake `osascript`, with `std::fs::write`. Thus the test process holds a
write descriptor for the script for a short time. On Linux, a test thread that
forks in that time gives its child a copy of the descriptor until the child
execs. If op-cache runs the stub in that window, it gets `ETXTBSY`, and the test
fails on `outcome` or on stdout.

**The cost of the fix on this branch.** The workspace fix for this race is
`gitscratch::testing::executable::write_executable`: a `/bin/sh` child writes
the file, thus the test process never holds a write descriptor for it. That
helper comes with PR #646 (branch `github-actions-ci`), which is open. It is not
on `main`, thus this branch cannot call it. A fix here is a second copy of that
helper in the test file, which the migration must find and remove later. The fix
also has no proof on this machine. macOS runs a script that a process holds open
for writing, the Docker daemon does not run, and the Colima VM is stopped.

**The cost of the defect until then.** The race occurs only on Linux. No gate of
`main` runs the tests on Linux, because the Linux CI job comes with PR #646
itself. Thus the race cannot fail a run before `write_executable` is on `main`.

**The tracking.** Issue #651 lists the sites that the migration in PR #646 moves
to `write_executable`. Its search ran before this file existed. The list now
holds `src/op-cache/tests/audit-trail.rs:42`, with the instruction to migrate
the site on the branch that merges second.

**The boundary.** This decision holds only while `write_executable` is not on
the base of the branch that holds this file. When `main` has `write_executable`
and `install_script` still calls `std::fs::write`, the decision ends, and a
review reports the site again. A Linux failure of an `audit-trail` test with
`Text file busy` also ends it. The stub of `unstartable_op_writes_spawn_error_pairs`
is out of scope, because that test expects a spawn error.
