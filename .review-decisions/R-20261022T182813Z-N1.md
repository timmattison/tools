**Settled** 2026-10-22 (branch issue-599, finding R-20261022T182813Z#N1)

The review found that the green commit `1eb66a60` added three tests, together
with the rules that they cover in `suspicion_of_sweep` of `src/ha/src/worker.rs`:
the proof from the created answer of this cycle, and the Gone path of the direct

- `a_run_that_left_the_sweep_and_that_the_created_answer_holds_as_finished_is_gone`

finding is accurate.

It is not fixed, because the defect is the content of one commit and nothing else.

Each test fails for its behavioral reason. The file was restored after each
mutation, and `git status --short` was empty at the end. Only the split between
two commits is wrong.

**The one fix is a rewrite that only Tim can run, and it buys nothing durable.**
The branch is pushed and PR #602 (branch issue-599) is open. A split of `1eb66a60`
into a red commit and a green commit needs an interactive rebase and a force
push. The agent shell does not support an interactive rebase, and
`block-dangerous-git.ts` refuses a force push with no override. The split gives
a new SHA to `1eb66a60` and to each commit after it. `pr-merge-gate.ts` looks
for the exact SHA that the review `R-20261022T182813Z` ends on. After the
split, it calls the review `rewritten` and refuses the merge until a fresh
review of the whole branch. Against that cost: this repository squash-merges
every PR with an explicit `--subject` and `--body`, thus no commit of this
branch reaches `main`. Tim chose to decline when he saw both costs.
