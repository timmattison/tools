## `src/wl/src/socket_table/mod.rs` — Windows has no reader of the socket table, and `wl` does not take Free from `listeners` there

**Settled** 2026-11-24 (branch wl, finding R-20261124T160606Z#I2)

The finding is correct about one defect: on a platform with no reader, `wl`
printed "wl could not read the kernel's list of listening sockets", but `wl`
did not try a read. Commits `4e954f63`, `fa9f8974` and `7bc7771e` fix that
defect. `socket_table::port_status` now gives `None` on a platform with no
reader, and `wl` prints that it reads the list on macOS and Linux only.

This record settles the two other changes that the finding offered:

1. **`wl` does not give Free on Windows when `listeners` names no process.**
   `listeners` 0.2.1 fails open on Windows. In
   `src/platform/windows/tcp_listener.rs`, `TcpListener::get_all` calls
   `.into_iter().flatten()` on the `Result` of each table read, thus a failed
   `GetExtendedTcpTable` read becomes an empty list. `to_listener` also drops a
   row whose process the Toolhelp snapshot cannot name. An empty answer from
   `listeners` thus does not prove a port free. The rule of `socket_table` is
   that only a complete read gives Free, and the macOS and Linux readers obey
   it.
2. **This branch does not add a reader of `GetExtendedTcpTable`.** Issue #747
   is about a listener of another user on macOS and Linux. A Windows reader is
   unsafe FFI code that no machine of this project can run: the development
   machine is macOS, and CI is Linux. Clippy for `x86_64-pc-windows-gnu` can
   compile the reader, but nothing can do a test of it. The cost of that
   untested code is more than the cost of the gap: on Windows, `wl` says that
   it cannot tell, and it does not say a false thing.

The boundary: a review that asks again for Free from `listeners` on Windows, or
for the Windows reader on this branch, is settled by this record. A new false
statement about Windows in the output or in the docs is a new finding. A change
of `listeners` that stops the fail-open behavior reopens item 1.
