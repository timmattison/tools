## `src/nle/src/pipeline.rs` `FilterRegistry::run` — the `# Errors` doc names only a time after the region

**Settled** 2026-11-26 (branch issue-168, finding R-20261126T225106Z#N1)

The finding is accurate. The `# Errors` doc of `FilterRegistry::run` says that
an in-place filter fails the run when it "answers a time after its region". The
code refuses each answered time outside `0.0..=view.length`, thus it also
refuses a time before the region. In
`an_in_place_filter_cannot_answer_a_time_outside_its_region`, the answer -0.5 on
a range from 1.0 s gives 0.5 s on the timeline. That time is not below zero, so
the first clause of the doc does not name it, and the run fails as outside its
region.

**The fix costs more than the defect in this round.** The defect is one word of
a doc header. The code and its test refuse both sides of the region. The doc of
`InPlaceFilterFn`, step 3, states the full rule: "from 0 to the length of the
region, both included". The error text that a user reads says "outside its
region", which is also correct. Thus no caller gets a wrong behavior or a wrong
message.

The fix is a change of a document. This round of the review loop is
record-only. A change of a document starts one more review cycle, and that
review can find a new nit in the new text.

**The boundary.** This record settles only the word "after" in the `# Errors`
doc of `FilterRegistry::run`. Each of these occurrences reopens it:

- code that accepts an answered time before the region, or that refuses less
  than `0.0..=view.length`
- an error message that a user reads, or the doc of `InPlaceFilterFn`, that
  names only one side of the region
- a different doc that states the rule of the region wrongly
