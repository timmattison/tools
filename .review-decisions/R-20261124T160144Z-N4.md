## Commit order on branch issue-669 — the budget and the reused PID of `faulte` came before their tests

**Settled** 2026-11-24 (branch issue-669, finding R-20261124T160144Z#N4)

The review found that two green commits carried more behavior than their red
tests. `ba6ec2da` (the memory budget, 445 lines) and `834031f2` (a reused PID,
345 lines) brought the eviction, the release of identities, the cut of a
command, the span sums, the gaps, and the map of the timeline. Their tests came
after them and passed at once: `19a78358`, `a7ab72b3`, `6eedceca`, `92dda0bf`,
`61cc57b3`, `cf83e44c`, `70a16135`, `c23404c5`. The test-only commits
`d1175f88`, `581bbbca`, `534fe1d6`, `7fc2537b`, `d3169441` and `79bbde32` did
the same in `stream.rs`, `view.rs` and `app.rs`. Most of their bodies name no
mutant. The TDD rule in `CLAUDE.md` asks for the red commit first. The finding
is accurate.

It is not fixed by a rewrite, because the defect is the order of the commits.

- **The only fix is a rewrite of a pushed branch.** The git guardrail refuses a
  force push, and only Tim can run one. A rewrite also changes the hash of each
  later commit, and the review logs and PR #751 name those hashes.
- **The order does not reach `main`.** Each PR merges as one squash commit.

production code only. The baseline was `cargo test -p faulte --lib` on the
modules `history::tests` (25), `stream::tests` (21), `tui::view::tests` (28),
and `tui::app::tests` (23). All passed. The file was restored after each

Two tests failed only on a side rule, and not on the rule in their names. The
suite held both rules through another test, and both tests now hold their own
rule, in commit `31792dee`:

- `the_oldest_entry_leaves_first`: with `pop_back` in `evict_oldest`, the old
  test passed, and `an_identity_leaves_when_no_frame_points_at_it` failed (24
  passed, 1 failed). The new test checks the time of the kept entries and fails
  on the same mutant.
- `an_absent_detail_never_erases_a_known_one`: with a row with no directory
  that erases the known one, the old test passed, and
  `a_span_sums_orders_and_takes_the_newest_state` failed. The new test ends on
  the frame with no directory and fails on the same mutant.

The boundary: this settles the order of the commits named above on branch
issue-669, for the tests in the table. A rule of these commits that a mutant
can change while every test of the crate passes is a new finding, not a new
argument about this one. A merge of this branch with a merge commit or a rebase
merge puts the order on `main`, and that reopens this decision.
