## `src/nle/src/types.rs` `Seconds::from_whole_seconds` — the test and the constructor stay in one commit

**Settled** 2026-11-26 (branch issue-155, finding R-20261127T004416Z#N2)

The finding is accurate. ad800cb adds the public constructor
`Seconds::from_whole_seconds` and its test
`seconds_from_whole_seconds_gives_that_many_seconds` in one commit. Its message
says that a red test of the constructor can fail only because the symbol is
undefined. That reason is not correct. A stub body `Seconds(0.0)` with the test
gives a red that fails for its behavior, as the stub of `normalize` in dad9b10
does. Thus the red commit of the TDD rule is missing for this constructor.

The code and the test are correct. The constructor is one cast of a `u32` to an
`f64`, and the test holds 0, 2 and `u32::MAX`. The missing red commit changes
no behavior of the branch.

The fix costs more than the defect. The only fix is a rewrite of the history of
the branch: a stub red commit before ad800cb. That rewrite needs a force push,
which the guardrail of this repository refuses, and it changes the SHAs that
the status logs and the earlier decision records name. A new commit cannot put
a red before a green that is already in the history.

The boundary: this decision settles the commit order of
`Seconds::from_whole_seconds` in ad800cb. A new function on this branch, or on
a later branch, that comes with its test in one commit is a new finding. The
next new function gets a stub body and its test in the red commit.
