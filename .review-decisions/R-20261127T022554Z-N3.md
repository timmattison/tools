## `src/nle/src/ui/preview.rs` `use_ticker` — the guard of a frame that wakes after Pause or Stop has no test

**Settled** 2026-11-26 (branch issue-151, finding R-20261127T022554Z#N3)

The finding is accurate. Commit 848d2d02a added the guard
`if !*playing.peek() { return; }` after the sleep of each frame, with no red
test. Its commit body states the gap: no test can force the order of the
scheduler. Thus a mutant that removes the guard passes all tests of `nle`.

The guard closes a race of one frame. Pause and Stop cancel the ticker through
a restart of its resource, and the cancel runs in a later step of the
scheduler. Without the guard, a frame that woke before that step moves the
playhead one frame past zero after Stop. The result is one frame of a wrong
playhead, not a crash and not a loss of data.

**The fix costs more than the defect in this round.** A test needs a Dioxus
runtime with paused tokio time. It must wake the ticker and send Stop in the
same step of the scheduler, before the restart of the resource cancels the
task. The test harness of `nle` gives no such control now, thus the fix is a
new mechanism in the harness and a new test. This round of the review loop is
record-only. That code is a diff that a review must read, and that review can
find a new nit in it. Then one more fix round starts.

**The boundary.** This record settles only the missing test of this one guard.
Each of these occurrences reopens it:

- a report of a playhead that moves after Pause or Stop
- a change of the test harness of `nle` that gives control of the order of the
  scheduler
- a second guard of the ticker that has no test
