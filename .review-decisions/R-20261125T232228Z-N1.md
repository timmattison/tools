## `src/nle/src/commands/tests.rs` — the stdin probe keeps the name `stdin_probe_runs_beta_with_the_stdin_of_this_process`

**Settled** 2026-11-25 (branch issue-761, finding R-20261125T232228Z#N1)

The finding is accurate. The probe asserts that `beta` gets `/dev/null` as its
stdin, but its name states the defect that it forbids. A failure prints that
name next to `FAILED`.

The name gives no wrong result. The probe is `#[ignore]`, and only the outer
test `run_beta_gives_beta_a_null_stdin_when_the_app_stdin_is_a_pipe` starts it.
The name of the outer test states the expected behavior, and a failure shows
that name too. The doc comment of the probe states that `beta` must exit 0
only when its stdin is `/dev/null`.

The cost of a fix: rename the probe, and change the name in the `format!` of
the outer test. That change is new code in a test file, thus it starts one more
review round, which can find a new nit in the new text.

The boundary: a report about the name of this probe is this decision. These
changes reopen it:

- A different test or tool starts the probe by its name.
- A failure report shows the name of the probe without the name of the outer
  test.
