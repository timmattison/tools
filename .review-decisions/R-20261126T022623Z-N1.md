## `src/nle/src/commands/tests.rs` — the `no-such-file` argument of the failed-beta test stays

**Settled** 2026-11-26 (branch issue-761, finding R-20261126T022623Z#N1)

The finding is accurate. The name `missing` and the path `no-such-file` come
from the `/bin/ls` link that the merge of main removed. `FAILING_BETA` prints
each argument on stderr and exits 1, thus the test does not need a missing
file. The name tells the reader that it does.

The test still does its job. It asserts that the error text holds
`beta export failed` and the argument that the script printed on stderr. A
change that drops the stderr of `beta` from the error fails the test. The
misleading name gives no false green.

The cost of a fix: rename the binding and pass a plain marker. That fix is new
code in a test file, thus it starts one more review round, which can find a
new nit in the new code.

The boundary: a report about the name or the path of this argument is this
decision. These changes reopen it:

- The test stops asserting that the error text holds the stderr of `beta`.
- A change makes the test depend on a file that does not exist.
