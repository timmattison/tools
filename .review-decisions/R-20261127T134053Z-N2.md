## `src/nle/src/filters/viewport/tests.rs` — two tests run one shape two times with the same stream

**Settled** 2026-11-27 (branch issue-165, finding R-20261127T134053Z#N2)

The finding is accurate. Two tests run one shape two times with the same
stream:

- `the_output_shows_the_crop_when_the_cursor_goes_to_a_hidden_row_and_back`
  runs `hidden_third`, which hides row 2. Then it runs `shapes()`, and the
  first shape of `shapes()` also hides only row 2.
- `a_range_masks_plain_text_and_gives_it_back_after_the_range` runs
  `assert_range_property_each_shape`. Then it runs `assert_range_property`
  with `hide_rows` `[0, 2, 4]` and `hide_columns` `[3]`. That shape is
  `shapes()[3]`.

Each extra run does the same assertion again. It costs some milliseconds of
test time. It cannot hide a defect, and it cannot make a correct emulator fail.

The extra runs also keep a fact. Each one states in its test the shape that
the stream is about. A later change of `shapes()` does not remove that shape
from the test.

**The fix costs more than the defect in this round.** The fix removes two
calls. This round of the review loop is record-only. A change is a diff that a
review must read, and that review can find a new nit in it. Then one more fix
round starts.

**The boundary.** This record settles only the two runs above. A third test
that runs a shape of `shapes()` a second time with the same stream is a new
occurrence, and it reopens this decision.
