## `src/nle/src/pipeline.rs` — the `# Errors` list of `run_on` omits the in-place errors

**Settled** 2026-11-27 (branch issue-161, finding R-20261127T024653Z#N1)

The finding is correct. `run_on` runs the same apply as `run`. Thus an
in-place filter that fails, or that answers a time after its region, fails
`run_on` too. The `# Errors` list of `run` names those two errors, and the
list of `run_on` does not.

The fix is one clause in a doc comment. This round of the review loop is
record-only. A change to the text is new text that a review must read, and
that review can start a new fix round. That cost is more than the cost of a
list that omits two errors. The behavior is correct, and the error is the
same `NleError::RenderError` that the list already names.

Boundary: this decision covers the text of the doc only. A reason to reopen
it is a case where `run` and `run_on` give different errors for the same
filter.
