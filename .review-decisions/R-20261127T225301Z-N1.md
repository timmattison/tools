## `src/nle/src/filters/fast_forward.rs` module doc — the doc gives 10 to 50 for Accelerate, and the filter accepts each finite value above 1

**Settled** 2026-11-27 (branch issue-162, finding R-20261127T225301Z#N1)

The finding is accurate. The module doc says "Accelerate plays the region at
10 to 50 times its speed". `Acceleration::new` accepts each finite value above
1, and `NleError::InvalidAcceleration`, the doc of `Acceleration`, and
`src/beta/NLE-ROADMAP.md` all say "above 1". The panel does not limit the
value to 10 to 50.

**The gap is a nit in prose, not a defect.** The paragraph describes the three
modes that issue #162 names, and 10 to 50 is the range that the issue gives.
The type and the error, which a caller reads, state the real bound. No result
is wrong: a speed of 1.5 or of 100 works.

**The fix costs more than the gap in this round.** The fix changes one
sentence of a doc comment. That change is new text that a review must read,
and it starts one more review cycle. This round of the review loop is
record-only.

**The boundary.** This record settles only the range in the module doc of
`fast_forward.rs`. Each of these occurrences reopens it:

- the code starts to limit the acceleration to 10 to 50, or to a different
  range, and a doc or an error still says "above 1"
- `Acceleration`, `NleError::InvalidAcceleration`, a README, or the panel
  states a bound that the code does not apply
- a user-facing text tells a user that a value above 1 and outside 10 to 50
  fails
