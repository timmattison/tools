## `src/ic/src/main.rs` — the order of the red and green commits of the frame-size fix stays as it is

**Settled** 2026-11-22 (branch issue-731, finding R-20261122T212331Z#N1)

The review found that the green commit `a6647119` added the `None` branch of
`rgb_frame_bytes` and the error text that names the dimensions, but the red commit
`68cb1171` before it does not test that branch. Its test,
`rgb_data_to_image(&[], 40_000, 40_000)`, fits in `usize` on a 64-bit target and
fails with the size-mismatch error. The tests of the `None` branch and of the
message came after the green, in `04ac9e12`.

The finding is accurate. The order breaks the rule that a failing test comes before
the code that it asks for.

**The only fix is a rewrite of the history, and it costs more than the defect.** The
three commits are on `origin/issue-731`, the head of PR #735. A new order needs an
interactive rebase and a force push, and the git guardrail of this machine refuses a
force push. The coverage is real: the body of `04ac9e12` records two mutants
(`saturating_mul`, and an error text with no dimensions) that its tests fail. This
repository squash-merges each PR, thus the three commits do not reach `main` as
separate commits. The reviewer also said not to rewrite the branch for the order
alone.

**The boundary.** This decision settles the order of the commits `68cb1171`,
`a6647119`, and `04ac9e12` only. It does not settle a missing test: a branch of
`rgb_frame_bytes` or `require_rgb_frame_bytes` that no test holds is a new finding.
It does not let a later green commit, on this branch or on a different branch, add
code that its red test does not ask for.
