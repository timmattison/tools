## `src/nle/src/commands/tests.rs` — the `beta` tests link coreutils binaries under the name `beta`

**Settled** 2026-11-25 (branch issue-761, finding R-20261125T232624Z#N2)

The finding is accurate. Three tests link a coreutils binary as `beta`:
`/bin/echo`, `/usr/bin/true`, and `/bin/ls`. On `ubuntu-latest`, the Rust
coreutils (uutils) reads its name from argv[0] and refuses `beta`. Thus these
tests fail on such a Linux host, and they pass on macOS.

The `/bin/echo` link is older than this branch. `origin/main` has it in
`beta_command_finds_beta_in_cargo_bin_from_the_finder_path`. This branch adds
two more links of the same kind, in
`run_beta_returns_the_output_path_when_beta_succeeds` and
`run_beta_reports_the_stderr_of_a_failed_beta`.

No run of these tests on such a host exists today. `origin/main` has no
`.github/` directory, and PR #766 (issue #761, branch `issue-761`) has no CI
check. The Linux CI comes with issue #651 (PR #646, branch
`github-actions-ci`), which is open. Its commit `1ebf64c8` already fixes the
`/bin/echo` test of `main`.

The failure is loud. When the Linux job of PR #646 runs on a tree that holds
these tests, the job fails and names each test. The fix of PR #646 (a
`#!/bin/sh` stub through `gitscratch::testing::executable::write_executable`)
applies to the two new tests in the same way.

The cost of a fix on this branch: replace three links with shell stubs. That
change is new code in a test file, thus it starts one more review round, for a
host that runs no test of this branch.

The boundary: a report that a `beta` test of `nle` links a coreutils binary is
this decision. These changes reopen it:

- A CI job or a person runs the `nle` tests on a Linux host with uutils, on a
  tree that holds these tests.
- PR #646 merges before this branch, and this branch keeps the links.
- A test links a coreutils binary under a different name after PR #646 merges.
