**Settled** 2026-11-27 (branch issue-156, finding R-20261127T010840Z#N1)

The finding is accurate. The roadmap row of issue #156 says that the filter
never searches an escape sequence. `README.md` and the module doc of
`src/nle/src/filters/redaction.rs` say that the text of an OSC sequence is
searched, for example a window title and the values of OSC 1337 such as
`RemoteHost=user@host`.

The defect is one clause of a summary row. The README and the module doc give
the full rules, and both are correct about the OSC text. The row also errs in
one direction only: the filter masks more than the row states, never less. A
reader who trusts the row does not expect a mask that the filter does not
apply, thus no secret stays in a recording because of the row.

The fix costs more than the defect. The branch is in the record-only round of
the review loop. A change to the row is new text that a fresh review must read,
and a nit in that text starts one more fix round. Thus the loop does not end
clean.

The boundary: this record settles the clause "never searches or changes an
escape sequence" in the roadmap row of issue #156 only. A roadmap text that
tells a reader that the filter masks a value that it does not mask is a new
finding. A change to the row that states the OSC rule closes this decision.
