## `src/nle/frontend/src/components/menu-bar.test.tsx` — the cancel test and the dialog-reject test do not assert that Open Recording is enabled again

**Settled** 2026-11-25 (branch 170, finding R-20261125T124305Z#N1)

The finding is accurate. Commit 97f9bee2 disables Open Recording until the
dialog and the load end. Only the success test and the load-failure test assert
that the button is enabled again. The cancel test and the dialog-reject test do
not. A mutant that calls `setOpening(false)` only after `onRecordingLoaded` and
in the `catch` leaves the button disabled after a cancel, and no test fails.

The component calls `setOpening(false)` in a `finally` block
(`src/nle/frontend/src/components/menu-bar.tsx`). The `finally` block runs on
each path out of the `try`: a cancel, a dialog that rejects, a load that fails,
and a load that succeeds. Thus the code is correct today. The gap is in the
tests only, and only a change that removes the `finally` block opens it.

The cost of a fix: two more assertions, and one more review round, for a mutant
that a reader of the component sees at once.

The boundary: a report that the cancel test or the dialog-reject test does not
assert the enabled state is this decision. A change that moves
`setOpening(false)` out of the `finally` block reopens it.
