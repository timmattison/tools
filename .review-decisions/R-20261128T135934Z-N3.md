## `src/nle/src/editor.rs` `Edit::AddChapter` — the doc names only the id rule, and no editor test applies a blank label

**Settled** 2026-11-28 (branch issue-164, finding R-20261128T135934Z#N3)

The finding is accurate. The doc of `AddChapter` says that the edit is refused
when its id is in use. It does not say that a blank label is refused, but the
doc of `UpdateChapter` says so for its label. `Editor::apply` refuses an
`AddChapter` with a blank label through `EditProject::validate`, with
`NleError::InvalidProject`, and the doc of `Edit` states that rule for each
edit. Thus no doc is false. No test in `src/nle/src/editor/tests.rs` applies
`AddChapter` with a blank label.

The rule has tests at the places that make it. The test
`validate_refuses_a_chapter_with_a_blank_label` in
`src/nle/src/project/tests.rs` holds the rule of `validate`. `Editor::apply`
runs `validate` after each edit, through `validate_without_render`, and the
editor tests give `TrimClip`, `AddFilter`, and `UpdateChapter` edits that
`validate` refuses. The chapter panel refuses a blank label in `read_fields`
before it makes the edit.

The fix costs more than the defect. One half of the fix is prose, which fixes
nothing. The other half is a new test. The branch is in the record-only round
of the review loop, and new text or new code starts one more fix round.

The boundary: this record settles the omission of the blank-label rule from
the doc of `AddChapter`, and the missing editor test of that rule. It is a
different subject from record `R-20261128T051847Z-N4`. These occurrences reopen
it:

- an `AddChapter` with a blank label that `Editor::apply` accepts
- a sentence of the doc of `AddChapter` or of `Edit` that is false at the head
  of the branch
- a path that adds a chapter and does not go through `validate`
