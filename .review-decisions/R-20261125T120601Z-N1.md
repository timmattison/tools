## `src/nle/src/commands.rs` — `list_recordings` gives the joined path, and `load_recording` gives the canonical path

**Settled** 2026-11-25 (branch 170, finding R-20261125T120601Z#N1)

The finding is accurate. `list_recordings_in` gives `file_path` as the
directory string joined with the file name. `load_recording_from` gives the
canonical path from `validate_path`. For a relative directory, a symlink, or a
`..` in the directory, the two paths of one file are different.
`list_recordings_in_keeps_only_loadable_json_and_json_gz_files` in
`src/nle/src/commands/tests.rs` expects the joined form.

No code compares the two paths today. The frontend does not call
`list_recordings`. The only reader of `file_path` is
`src/nle/frontend/src/components/properties-panel.tsx`, and it shows the last
part of the path of the open recording. Thus the difference has no effect that
a user can see.

The cost of a fix: a change to `list_recordings_in`, a change to the expected
paths of its test, and one more review round, for a mismatch that nothing
reads.

The boundary: a report that the two commands give different strings for one
file is this decision. A frontend or a command that compares a path from
`list_recordings` with a path from `load_recording` reopens it.
