## `src/sirn/src/main.rs` — `main` keeps its `Box<dyn Error>` return

**Settled** 2026-11-26 (branch issue-441, finding R-20261126T200957Z#N1)

The finding is accurate. `main` returns `Result<(), Box<dyn Error>>`, thus
`Termination` prints the error through `Debug`. The new failure path prints
`Error: "sirn stopped serving on 127.0.0.1:45479: Too many open files (os error 24)"`,
with the message in quotes. The comment at `src/sirn/src/main.rs:37-39` says
that `main` renders each error through `Display`, and that claim is false.

The acceptance criterion of issue #441 holds: the message goes to standard
error, and the exit status is not zero. The quotes are cosmetic. The comment
and the `Debug` output are not new: at the base 6d815dc72, each `map_err`
site before the bind already printed through `Debug` under the same comment.

The cost of a fix: a `run()` split moves the whole body of `main` into a new
function. That is new code that the next review reads, thus
it starts one more review round. The other fix, a change of the comment, is
prose and fixes nothing.

The boundary: a report about the `Debug` form of an error that `main` of
`sirn` returns is this decision. This change reopens it:

- An error of `sirn` loses its text, or `sirn` exits with status 0 after a
  failure.
