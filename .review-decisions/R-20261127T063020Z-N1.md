## `src/nle/src/ui.rs` `REDACTION_HINT` — "Escape sequences do not change." stays as it is

**Settled** 2026-11-27 (branch issue-156, finding R-20261127T063020Z#N1)

The finding is accurate. The hint of the redaction panel says that escape
sequences do not change. The filter searches and changes the text of an OSC
sequence: a window title (OSC 0 and OSC 2) and the plain values of OSC 1337,
for example `RemoteHost=user@host` (`osc_text` and `iterm2_value` in
`src/nle/src/filters/redaction/stream.rs`). The test
`the_redaction_panel_shows_its_fields_and_its_button` in
`src/nle/src/ui/tests.rs` holds the same string.

The defect is one clause of a one-line hint. The hint errs in one direction
only: the filter masks more than the hint states, never less. A person who
trusts the hint does not expect a mask that the filter does not apply, thus no
secret stays in a recording because of the hint. `README.md` gives the full
rule, with the OSC exception and its example. This is the reason of the
settled records `R-20261127T010840Z-N1` (the roadmap row) and
`R-20261127T010840Z-N2` (the README bullets), applied to a third location.

The fix costs more than the defect. The branch is in the record-only round of
the review loop. A change to the hint is a change to a constant and to the
test that holds it. That change is new code that a fresh review must read,
and a nit in it starts one more fix round. Thus the loop does not end clean.

The boundary: this record settles the clause "Escape sequences do not change."
in `REDACTION_HINT` only. A text of the window that tells a person that the
filter masks a value that it does not mask is a new finding. A change to the
hint that states the OSC rule closes this decision.
