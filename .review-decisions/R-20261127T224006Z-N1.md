## `src/nle/src/filters/keystroke_hud/timeline.rs` — rule 2 does not say that a press at `last` opens a closed entry again

**Settled** 2026-11-27 (branch issue-161, finding R-20261127T224006Z#N1)

The finding is correct. `Timeline::new` sets `open = !closes` after each
press, also after a press that joined a closed entry at `last`. Thus
`ls`, `Enter`, `pwd` at 1.0 and `x` at 1.1 give one box, `ls Enter pwdx`.
Rule 2 of the doc of `Timeline` does not say if the entry is open after such
a join, and no test pins the case.
`a_key_after_an_enter_at_one_time_still_starts_a_new_box` holds only an input
event whose last press is `Enter`.

The code is correct. The input event at 1.0 is a paste that leaves `pwd` on
the command line of the shell, and `x` then adds to that line. Rule 2 says
that `Enter` closes an entry, and the last press of this entry is `pwd`, not
`Enter`. The gap is one sentence of the doc and one test that pins behavior
that is already correct.

The fix is prose and a new test. A change of the doc and of the tests is new
text that a fresh review must read, and the loop then starts one more fix
round. This round of the review loop is record-only. The finding
R-20261127T230440Z#N2 reports the same gap with the input `Enter`, `x` at 1.0
and `y` at 1.1, and its record states the same decision.

Boundary: a change to the join rule of `Timeline::new`, or to how it sets
`open`, reopens this decision. A change that keeps the entry closed after such
a join, and that passes the tests, reopens it too. A new argument for the
sentence or the test does not.
