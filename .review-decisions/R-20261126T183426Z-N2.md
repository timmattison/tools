## `src/ff/src/walk.rs` — the stat after `ENOTDIR` on a root stays a direct `std::fs::metadata` call

**Settled** 2026-11-26 (branch issue-508, finding R-20261126T183426Z#N2)

The finding is accurate. When `open_dir` of a root gives `ENOTDIR`,
`walk_root` calls `std::fs::metadata` to find if the root exists. That call
does not go through `self.retry`, and it does not go through the
`FileSystem` seam. Thus no `Faulty` test can inject a fault there, and an
`EINTR` from that stat puts the root in the incomplete class.

The risk is small, and the failure is loud:

- The call runs one time for each named root that is not a directory. It
  does not run for the entries below a root, where the walk spends its
  system calls.
- `stat(2)` on macOS lists no `EINTR` in its errors. The walk retries
  `device` and `is_directory`, which are stat calls too, thus the seam does
  not trust that list. But this one call is the only stat outside the seam.
- If the call fails, `ff` names the root as incomplete and exits 1. It does
  not lose the root in silence.

The cost of a fix: a new method on the `FileSystem` trait, an implementation
in `RealFs` and in `Faulty`, and a new `Faulty` test. That fix is new code in
the seam of the crate, and it starts one more review round, which can find a
new nit in the new code.

The boundary: a report that this one stat is not retried, or is not on the
seam, is this decision. These changes reopen it:

- A user or a test shows an `EINTR` from this stat.
- A second call of the walk bypasses `self.retry` or `self.fs`.
- A failure of this call changes the output in silence, for example a root
  that the walk skips with no report and exit status 0.
