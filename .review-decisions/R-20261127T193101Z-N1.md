## `src/nle/src/ui/tests.rs` `Specificity::of` — a pseudo-element gets a wrong count, and no panic

**Settled** 2026-11-27 (branch issue-824, finding R-20261127T193101Z#N1)

The finding is accurate. The `:` branch of `Specificity::of` counts each `:`
as one pseudo-class. Thus `Specificity::of("button::before")` gives
`(0, 2, 1)`, but the true specificity is `(0, 0, 2)`. The legacy forms
`:before`, `:after`, `:first-line` and `:first-letter` give one class in place
of one type. The doc sentence "A form that this function does not know fails
the test, so that no count is wrong in silence" is thus false for a
pseudo-element.

The defect has no effect now. `src/nle/assets/main.css` holds no
pseudo-element. The test `the_dismiss_button_keeps_its_own_hover_color` reads
`Specificity::of` only for `.error-dismiss:hover` and for each rule that starts
with `button:hover`. The Dismiss selector is a constant of the test, thus a
wrong count can only raise the rank of a `button:hover` rule. That error makes
the test fail, never pass.

**The fix costs more than the defect.** The fix is a sentence of doc prose, or
a new panic branch in a test helper. Either change is new code that a review
must read, and a new fix round then starts for a test that is correct for the
style sheet of now. The test helpers are already about 130 lines for one CSS
rule of 3 lines.

**The boundary.** This record settles only the wrong count for a
pseudo-element, and the doc sentence that claims each unknown form fails. These
occurrences reopen it:

- a pseudo-element (`::name`, or a legacy `:before`, `:after`, `:first-line`
  or `:first-letter`) in a selector of `main.css` that `Specificity::of` reads
- a pseudo-element in the Dismiss selector of the test, because then a wrong
  count can make the test pass
- a new caller of `Specificity::of` outside this test
