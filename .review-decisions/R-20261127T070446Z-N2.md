## `src/nle/src/filters/keystroke_hud/timeline.rs` — `Timeline::at` scans the entries from the start

**Settled** 2026-11-27 (branch issue-161, finding R-20261127T070446Z#N2)

The finding is correct. `Timeline::at` scans the entries from the start on
each call, and `draw` calls it once for each frame and once for each output
event. The cost of a render is (frames + output events) x entries. The
output is correct.

The fix, a `partition_point` on the sorted entries, is small, but it is a
code change. This round of the review loop is record-only. A code change is
new code that a review must read, and that review can start a new fix round.
The scan costs time, and it gives no wrong result. The case of the finding
needs 10,000 boxes of keys in one region.

Boundary: a measured render of a real recording that the scan makes slow
reopens this decision. A new argument about the complexity does not.
