**Settled** 2026-11-28 (branch issue-166, finding R-20261128T133342Z#N1)

The finding is accurate. The last paragraph of "How to see it" in the
description of issue #166 (PR #802, branch issue-166) says that the window
cannot save or export the edited recording (issue #158). The merge `00546f5e`
brought `e1041fa3`, the merge of issue #158 (PR #782). At HEAD `00546f5e`,
`src/nle/src/ui.rs:5-7` puts the export bar in the menu bar, and
`src/nle/src/export.rs` renders the whole project, filters included, into one
recording before it writes the file. `README.md` and `TLDR.md` say that `nle`
exports the edited recording as a `beta` recording, a web page, an MP4, or a
GIF. Thus a person can export the recolored recording, and try `beta play` and
the exports of `beta` on it.

**The fix costs more than the defect in this round.** The wrong text is not in
a file of the repository. It tells a person about one manual step fewer than
the person can do, and it changes no decision about the review or the merge.
The eleven steps of the section stay correct. The fix is an edit of the PR
body. A review reads that body, thus the edit starts one more review cycle,
and this round of the review loop is record-only. A later fix round that
changes the PR body for a different reason can replace the paragraph with an
export step at no extra cost.

that the window cannot export the edited recording. Each of these occurrences
