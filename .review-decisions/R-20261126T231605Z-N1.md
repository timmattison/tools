## `src/nle/src/pipeline.rs` `FilterRegistry::register_in_place` — no test holds the "any form" claim of its doc

**Settled** 2026-11-26 (branch issue-168, finding R-20261126T231605Z#N1)

The finding is accurate. The doc of `register_in_place` says that a filter of
any form that is already under `kind` is replaced. In the tests,
`register_in_place` occurs only in `in_place_spy` and in the test of the
`grumpy` filter. No test registers an in-place filter, then an event filter or
a span filter under the same kind, and asserts that the last registration
answers. `register_span_and_register_replace_each_other_under_one_kind` holds
that claim for `register_span` only.

The claim is true today. All three `register` functions insert into the one
map `FilterRegistry::filters`, and each value is one `Registered` variant. Thus
one kind holds one filter, whatever its form, and no caller gets a wrong
behavior.

**The fix costs more than the defect in this round.** The gap is a test of a
change that nobody made: a second map for in-place filters. This round of the
review loop is record-only. A new test is new code that a review must read, and
that review can find a new nit in it. Then one more fix round starts.

**The boundary.** This record settles only the missing test of the replacement
rule for `register_in_place`. Each of these occurrences reopens it:

- code that keeps the filters of one form in a map or a field of their own
- a fourth form of filter, or a fourth `register` function
- a defect report in which two filters answer under one kind
