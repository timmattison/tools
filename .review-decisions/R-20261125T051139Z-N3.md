## `src/workit/src/main.rs` — a dry run says `Dropping` for a member that it does not drop

**Settled** 2026-11-25 (branch workit, finding R-20261125T051139Z#N3)

The finding is accurate. Under `--dry-run`, the run writes nothing, but stderr
says `Dropping N member(s) of <file> that the scan did not find:`. The README
says that a dry run touches nothing. Thus the message states an action that did
not occur.

It is not fixed, because the fix costs more than the defect:

- **The same output gives the result.** The next lines on stdout say
  `Would write to <file>:` and print the whole manifest that the run would
  write, without the dropped members. Thus a reader of the dry run sees that
  nothing was written.
- **The file does not change.** The defect is the verb of one message. No
  manifest is wrong.
- **The cost is a new review cycle.** This round of the review loop is
  record-only. A new verb under `--dry-run` and its test are new code that a
  review must read, and a fresh review can find a new nit in it. Tim chose to
  settle each nit with a record (decision H-742-2 on issue #742).

**The boundary.** This decision settles the verb of the `Dropping` message
under `--dry-run`. A dry run that writes a file is a new finding.
