## `specs/2026-11-26-nle-plugin-architecture-design.md` "Failures" — an export that does not match is a load error, not a failure of a call

**Settled** 2026-11-26 (branch issue-169, finding R-20261127T032320Z#N1)

The finding is accurate. The list of "Failures" says that each of its failures
stops the call and fails the render. Its last bullet is a component that does
not export the interface of its manifest `type`, or that exports a version
that the host does not know. That mismatch is a load error. A plugin that fails
to load never registers, thus no call of it exists.

Three other places of the spec state the correct behavior. "The choice" says
that a plugin that does not match the contract fails at load. "The package"
says that the host refuses an unknown version before it instantiates the
component. Slice 2, which writes the load, answers a load error. Thus the
bullet misleads a reader of the list, but it does not change the code that
slice 2 writes.

**The fix costs more than the defect in this round.** The fix moves one bullet
out of the list into a sentence. This round of the review loop is record-only.
A change of the spec starts one more review cycle, and that review can find a
new nit in the new text.
