## `src/drun/src/main.rs` — `-h` after `ps`, `status`, `wait`, `hosts`, `pick`, and `check-flags` is a usage error, not the help

**Settled** 2026-11-24 (branch drun, findings R-20261124T213948Z#N2, R-20261124T213701Z#N1)

The finding is accurate. The first-argument shortcut in `dispatch` reads only
`--help` for the commands in `COMMANDS_WITHOUT_FLAGS`. Thus `drun ps -h` gives
"drun ps takes no arguments", and `drun wait -h` gives "drun wait needs one
container name". Each gives exit status 2. `docker ps -h` and `docker wait -h`
print "Flag shorthand -h has been deprecated, use --help" and then the help,
with exit status 0 (measured with docker 29.9.2).

**The fix costs more than the defect.** `drun` asks no host in either case.
The usage error ends with "Run drun --help to see how to use drun.", thus the
user gets to the help in one more command. Docker itself tells the user to
stop the use of `-h`. The help flags of `drun` started five fix rounds in a
row on this branch: R-20261124T195939Z#I1, R-20261124T203034Z#I1 and #I2,
R-20261124T205440Z#I1, and then this finding. Each fix of the help made a new
finding about the help.

The boundary: a non-blocking finding about how `drun` reads `--help` or `-h`,
where the result is a different message or exit status and `drun` asks no
host, is a re-litigation of this decision. A finding where a help flag makes
`drun` start, stop, or remove a container, or ask a host, is not covered.
