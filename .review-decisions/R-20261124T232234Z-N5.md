## `src/msgs/frontend/src/main.ts` — the open chat has no highlight after a search clears

**Settled** 2026-11-24 (branch msgs, finding R-20261124T232234Z#N5)

The finding is accurate. In search mode the sidebar holds no conversation
items, thus a click on a result highlights nothing, and `selectedChatId` keeps
the chat of before the search. When the search clears, `initConversations`
rebuilds the list, and `createConversationElement` marks no item active. The
open chat then has no highlight, Enter does nothing, and ArrowDown starts at the
first item. A search that clears also removes the highlight of a chat that the
user opened from the sidebar.

**The fix costs more than the defect.** The open chat stays open, and the
message view does not change. The user loses only the highlight in the sidebar,
and one click or one arrow key gives a selection again. A fix sets
`selectedChatId` in `openConversationAt` and marks its item active after each
reload, with vitest tests of the reload. This round of the review loop is
record-only, thus that code starts one more review cycle.

The finding `R-20261124T221923Z#N3` of an earlier review reports the same
defect. Its record is `R-20261124T221923Z-N3.md`.

**The boundary.** This record settles the lost highlight and the stale
`selectedChatId` after a search clears. A key or a click that opens a chat that
the user did not choose reopens this record.
