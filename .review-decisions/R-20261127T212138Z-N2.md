## `src/nle/src/pipeline.rs` `FilterRegistry::run` — the words of the cut error in `# Errors`

**Settled** 2026-11-27 (branch issue-164, finding R-20261127T212138Z#N2)

The finding is accurate. The `# Errors` doc of `FilterRegistry::run` says that
a cut filter "marks a count of events that is not the count of its region". A
reader can take that text as "the filter removes fewer events than the region
holds", which is not an error. The error is a count of marks that is not the
count of the events of the region. `run_with_end` gives the same error in
different words: "another count of marks than of events".

The code returns the correct error. Its message names both counts: "filter
\"{kind}\" answered {} marks for the {} events of its region". The doc of the
cut form near the top of `pipeline.rs` also says "A count of marks that is not
the count of events". Thus a reader who reads the cut form or the error
message gets the correct rule.

**The fix costs more than the defect.** The fix is a change of doc text in two
places. It changes no behavior, and a fresh review reads the changed docs. The
loop then starts one more fix round for the words of an error that the code
already returns correctly.

**The boundary.** This record settles only the words of the two docs. These
occurrences reopen it:

- a change that returns an error for a cut filter that removes fewer events
  than its region holds
- a change that accepts a count of marks that is not the count of the events
  of the region
