## `src/repo-guards/src/tool_index.rs` doc comments of `README` and `TLDR` — the old names "long index" and "one-line index" stay until part 8

**Settled** 2026-11-27 (branch issue-831, finding R-20261128T015855Z#N1)

The finding is accurate. Commit `e54e084d` changed the module doc. It now says
that the long entry of a tool is in `src/<tool>/README.md`, and that
`README.md` gives each tool one line with a link. The doc comment of the
constant `README` still calls `README.md` "the long index". The doc comment of
the constant `TLDR` still calls `TLDR.md` "the one-line index". Thus the module
doc and the two doc comments disagree.

The fix changes two lines of prose and no code. The guard reads the same two
files with the old words or the new words. The cost is a new review cycle. This
round of the review loop is record-only, because a change starts a fresh review
that can find a new nit in the change.

Issue #838 (part 8 of 8 of the README split) deletes `TLDR.md`, removes its
check from the guard, and rewrites `repo_guards::tool_index`. That work removes
the constant `TLDR` and replaces the doc comment of `README`.

The boundary: this decision covers only the doc comments of the constants
`README` and `TLDR` while `TLDR.md` exists. A doc comment that gives the guard a
wrong rule is a new occurrence. A doc comment that still calls `README.md` the
long index after issue #838 merges is a new occurrence too.
