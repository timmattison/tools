## `README.md` (nle export) — a typed name with an unknown ending keeps that ending

**Settled** 2026-11-27 (branch issue-158, finding R-20261127T133002Z#N1)

The finding is accurate. The README says that the editor replaces a different
typed ending with the ending of the format. `ExportKind::output_path` in
`src/nle/src/ui/export.rs` removes only the endings of `KIND_ENDINGS`
(`.json`, `.gz`, `.html`, `.mp4`, `.gif`), and then adds the ending of the
format. Thus `report.v2` with the Web format gives `report.v2.html`, and
`notes.txt` gives `notes.txt.html`. The test case
`("/tmp/report.v2", ExportKind::Web, "/tmp/report.v2.html")` in
`src/nle/src/ui/export/tests.rs` holds this behavior.

The defect is in the text only. The code is correct, and no file is lost: the
user gets a file with two endings, in the folder that the user selected, and
the file has the ending of the format.

The cost of a fix: a change of one sentence in `README.md`. The round that read
this finding was record-only. A changed sentence is new text that a review
must read, and it starts one more review round, which can find a new nit in
the new text.

The boundary: a report that the README sentence about a different typed ending
does not agree with `output_path` is this decision. These changes reopen it:

- `output_path` loses the ending of the format, or writes a file outside the
  folder that the user selected.
- `KIND_ENDINGS` or `output_path` changes, so that the README text and the code
  disagree in a new way.
- A second document, for example the help of the editor, repeats the wrong
  sentence.
