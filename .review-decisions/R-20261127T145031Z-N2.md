## `src/ufa/README.md` `ufa config setup` — the refusal of the typed URL does not name `--url` and `--api-key`

**Settled** 2026-11-27 (branch ufa, finding R-20261127T145031Z#N2)

The finding is accurate. The README says that a piped run of
`ufa config setup` "is told to use `--url` and `--api-key`". Only
`NEEDS_A_TERMINAL` (`src/ufa/src/config.rs`), the refusal of the numbered
menus, names the two flags. When 1Password holds no controller and network
discovery finds none, the wizard asks for the URL through `prompt::ask_line`.
On a pipe, `prompt::refuse_without_a_terminal` refuses that question with
"Run the command at a terminal to answer it." It does not name the flags.

**The fix costs more than the defect in this round.**

- The main promise of the README holds: a piped run refuses at once and does
  not wait for an answer. The refusal names the question that needs an answer.
- `--url` and `--api-key` are global flags of `ufa`, and the error of a
  missing key names `--api-key`. A person who reads the refusal can find the
  flags in `ufa --help`.
- `refuse_without_a_terminal` serves each free-text question of the crate,
  not only setup. A fix changes either that shared message or the text of the
  README. Each change starts one more review cycle, and this round of the
  review loop is record-only.

**The boundary.** This record settles only the missing names of the two flags
in the refusal of the typed URL. Each of these occurrences reopens it:

- a piped run of `ufa config setup` that waits for an answer, or that ends
  with no refusal
- a refusal that gives wrong advice, for example a flag that `ufa` does not
  have
- a different statement of the README about setup that the code does not obey
