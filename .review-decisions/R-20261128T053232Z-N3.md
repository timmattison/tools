## `src/nle/src/editor.rs` `UpdateChapter` — the second lookup of the chapter

**Settled** 2026-11-28 (branch issue-164, finding R-20261128T053232Z#N3)

The finding is accurate. `chapter_position` returns the index of the chapter,
or `missing_chapter(id)`. The `UpdateChapter` arm then calls
`get_mut(position)` with `ok_or_else(|| missing_chapter(*id))`. Nothing
changes the chapters between the two calls, thus that error path never runs.
The `RemoveChapter` arm uses the index directly.

The fix costs more than the defect. The dead path does not change a result or
an error. `get_mut` is also the form that the rules of this workspace ask for
in place of an index, because an index can panic and `get_mut` cannot. A fix
that removes the second lookup must change the shape of the arm, for example
with `iter_mut().find`. The branch is in the record-only round of the review
loop. That change is new code that a fresh review reads, and a nit in it
starts one more fix round.

The boundary: this record settles only the second lookup in the
`UpdateChapter` arm. A chapter edit that gives a wrong result or a wrong error
is a new finding. A lookup that can panic is a new finding too.
