## `specs/2026-11-26-nle-plugin-architecture-design.md` "Failures" — the list fails the render, but an analyzer runs after the render

**Settled** 2026-11-26 (branch issue-169, finding R-20261127T033410Z#N2)

The finding is accurate. The list of "Failures" says that each failure stops
the call and fails the render with a `NleError::RenderError`. The list covers
each plugin type. Slice 5 runs each applied analyzer after each render. Thus an
analyzer that traps or answers `err` has no render left to fail, and the spec
gives no other result for it.

The finding gives a second fix: let slice 5 decide it. Slice 5 adds the
`analyzer` interface, and the panel that shows the markers and the metrics of
an analyzer. The result of a failed analyzer is a decision about that panel,
thus slice 5 is the correct place for it. A filter and a renderer run inside
the render, thus a failed call of one of them can fail the render.

**The fix costs more than the defect in this round.** A fix in the spec now
decides the panel of slice 5 before slice 5 starts. This round of the review
loop is record-only. A change of the spec starts one more review cycle, and
that review can find a new nit in the new text.

**The boundary.** This record settles only the result of a failed analyzer
before slice 5 starts. Each of these occurrences reopens this record:

- slice 5 lands with no stated result for a failed analyzer
- a failed analyzer fails or stops a render
