## `src/workit/src/main.rs` — the worktree filter counts a manifest before it reads it (reported again)

**Settled** 2026-11-25 (branch workit, finding R-20261125T051139Z#N1)

The finding is accurate, and it reports the same defect as
R-20261125T043207Z#N1. The record of that finding is
`.review-decisions/R-20261125T043207Z-N1.md`. When the later review ran, the
earlier finding had no disposition on record. This run records both findings.

`find_cargo_tomls` counts each `Cargo.toml` in a worktree below the search path
before `is_package_toml` reads it. Thus a workspace manifest and a manifest
that does not parse are counted too. If the filter took out only such
manifests, `explain_empty_result` names `--include-worktrees`, and that flag
lists nothing. The doc of `explain_empty_result` says that the message must not
name a flag that changes nothing, and in this case it does.

The reasons of the earlier record apply. The case is narrow, an empty result
writes nothing and exits 0, and the cost to the user is one run with a flag.

**The cost is a new review cycle.** This round of the review loop is
record-only. A fix is new code that a review must read, and a fresh review can
find a new nit in it. Tim chose to settle each nit with a record (decision
H-742-2 on issue #742).

**The boundary.** The boundary of
`.review-decisions/R-20261125T043207Z-N1.md` applies.
