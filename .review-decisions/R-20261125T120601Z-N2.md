## `src/nle/src/lib.rs` — `run()` panics when the Tauri runtime cannot start

**Settled** 2026-11-25 (branch 170, finding R-20261125T120601Z#N2)

The finding is accurate. `run()` in the library crate `nle_lib` calls
`.expect("error while running tauri application")`. If the Tauri runtime cannot
start, the process stops with status 101 and a panic message, not with an error
message and status 1. The `# Panics` section of the doc comment of `run()`
states this behavior.

`nle` is a desktop application, and `run()` has one caller: `main` in
`src/nle/src/main.rs`. No other crate links `nle_lib`. The panic occurs one time,
at the start, and its message names the error that Tauri gave. A user who
starts the application from Finder does not see the status or the message in
either form.

The cost of a fix: a change of the signature of `run()` to return
`tauri::Result<()>`, a change to `main.rs` to print the error and exit with
status 1, and one more review round, for a different exit status at a failed
start.

The boundary: a report that `run()` panics at a failed start is this decision.
A second caller of `nle_lib::run`, or a script or a test that reads the exit
status of `nle`, reopens it.
