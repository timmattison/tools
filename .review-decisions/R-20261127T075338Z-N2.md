## `src/nle/src/filters/viewport/tests.rs` — the test of an attribute that the emulator does not model pins the same bytes as an older test

**Settled** 2026-11-27 (branch issue-165, finding R-20261127T075338Z#N2)

The finding is accurate.
`a_range_starts_with_a_full_sgr_for_an_attribute_that_the_emulator_does_not_model`
(commit `5b98a6f0c`) pins the same bytes at 3.0 as
`a_range_in_the_middle_of_a_recording_writes_the_start_and_the_restore`. Both
tests use a screen of 20 by 6, `hide_rows: [0]`, and the span from 3.0 to 6.0.
`termstate` ignores SGR 53. Thus the emulator has the same state after `ab` and
after `ab` with SGR 53, and the writer sees the same state for both. A mutant
that starts the writer of a range with the pen of the emulator writes no SGR at
3.0, and it fails both tests. No mutant of the current code fails only this
test.

The cost of the defect is one more fast unit test. The test fails for each
mutant that the older test finds, thus it gives no false result. It also states
the intent in its name: the writer of a range starts with a full SGR, because
the emulator does not see each attribute of the terminal. Round 1 removed a test
of the same kind in commit `96e0b2eb7` (finding R-20261127T055855Z#N5).

**The fix costs more than the defect in this round.** The fix is the removal of
the test. This round of the review loop is record-only. A change is a diff that
a review must read, and that review can find a new nit in it. Then one more fix
round starts.

**The boundary.** This record settles only this one test. Each of these
occurrences reopens it:

- a second test that pins the same bytes with the same setup
- a model of SGR 53 in `termstate`, which makes the two inputs give different
  states
- a writer of a range that reads the bytes of the events before the range, not
  only the state of the emulator
