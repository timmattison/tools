**Settled** 2026-11-24 (branch 191, finding R-20261124T184303Z#N1)

The finding is accurate. The tests of the skip cover one removed container
beside one container that stays. No test covers two removed listed
containers, or a `docker inspect` that finds no target and writes one empty
line to stdout. The code handles both cases today: `only_removed` reads each
line of stderr, and the parse loop of `find_running_tunnels_with` skips an
empty line.

**The cost is a new review cycle.** This round of the review loop is
record-only. A new test is new code that a review must read, and a fresh
review can find a new nit in it. Then a new fix round starts, and the loop
does not end clean. The defect is a gap in the tests, not in the behavior,
and two existing tests already hold each rule alone: the case-insensitive
match of the error line, and the refusal of a line of another kind.

**The boundary.** This decision settles only the two missing cases above. A
change to `only_removed` or to the parse loop that breaks either case is a new
finding, not this one. A different gap in the tests of the docker detection is
also a new finding.
