## `src/workit/tests/resilience.rs` — the two tests of an unreadable entry measure nothing when the run is root

**Settled** 2026-11-24 (branch workit, finding R-20261124T182455Z#N4)

The finding is accurate. `an_unreadable_manifest_does_not_stop_the_scan` and
`an_unreadable_directory_does_not_stop_the_scan` return early when the run can
read an entry of mode 000. Root can read such an entry, thus a run as root, for
example in a container, reports a pass and does a test of nothing.

It is not fixed, because the fix costs more than the defect:

- **No run of this repository is root.** On 2026-11-24, the branch and
  `origin/main` hold no CI workflow. The suite runs in the pre-commit hook and
  by hand, as the user of this Mac, and both runs do a test of the skip.
- **The test says when it measures nothing.** Each early return prints a line
  that starts with "skipping: this run can read a file of mode 000" or
  "skipping: this run can read a directory of mode 000". Thus a root run shows
  the gap in its output.
- **The suggested case does a test of a different path.** A directory named
  `Cargo.toml` fails `read_to_string` with EISDIR. That is a different error
  from a refused open. The two reach the same skip today only because the walk
  matches the name `Cargo.toml` and does not ask for the file type. A later
  check of the file type in the walk removes the directory case and leaves no
  test of a refused open.
- **The branch stopped at the blocking level.** At the stall (decision H-742-2
  on issue #742), Tim chose to fix each blocking finding and to settle each nit
  with a record.

The boundary: this settles the early return of these two tests for a run as
root. A CI job or a hook that runs as root reopens this decision, because then
the skip has no test in a run that the repository depends on.
