## `plugins/ic-inline/types/index.d.ts` `IcInlineDiffed` — the type of `mode` states the list of the modes again, beside `DiffMode`

**Settled** 2026-11-25 (branch issue-764, finding R-20261125T231017Z#N2)

The finding is correct. `IcInlineDiffed.mode` is
`'boxes' | 'highlight' | 'mask'`, and `DiffMode` in `hooks/picture.ts` states
the same three modes. If a mode changes in one of the two places only, the
result is a type error at the `$.state.set` and `$.state.get` calls of
`show_diff` in `hooks/register.tsx`. `claude plugin validate` reports a
TypeScript error as a warning and passes, thus no gate fails.

The copy is a type, not a value, and nothing reads it at runtime. The tool
path takes its mode through `isDiffMode` before it keeps the mode, thus the
kept value is always a member of `DIFF_MODES`. A drift shows as a type error
in each editor and in each `tsc` run of the plugin.

The fix moves `DiffMode` into the type file through an `import type` from
`../hooks/picture`. No type file of a plugin in this repository has an import
yet, and that file adds the state of the plugin to the `PluginState` of the
engine. Thus the fix needs a test of what the engine accepts there. Its cost is that test, a
code change, and one more review cycle of this branch, which is in a
record-only round. The cost of the gap is a type error that no gate stops, for
a list that changes only when `ic --diff-mode` gets a new mode.

The boundary: a review that asks again to take `DiffMode` into
`IcInlineDiffed` is settled by this record. A third copy of the list of the
modes, or a list in the type file that differs from `DIFF_MODES`, is a new
finding. A change of the modes of `ic --diff-mode` reopens this decision.
