## `src/nle/src/pipeline.rs` `SpanFilterFn` — the summary line does not name the `SpanContext` argument

**Settled** 2026-11-27 (branch issue-152, finding R-20261127T125059Z#N1)

The finding is accurate. The summary line of `SpanFilterFn` says that a span
filter is a function from a region and its length. The summary line is from
`main` (merge base 1cdd3fe60). Commit 91254c966 of this branch added the
`SpanContext` argument: the events before and after the region, and the size
of the terminal. The summary line does not name it.

The doc is incomplete, not wrong. Step 2 of the same doc, five lines below the
summary line, names the `SpanContext` and each of its parts. The signature of
the type names it too. The summary line never named the `FilterOptions`
argument either, so it was never a full list of the arguments.

**The fix costs more than the defect.** The fix is prose in a doc comment. It
changes no behavior, and a new review must read it. A new fix round then starts
for a summary line that the next lines of the same doc already complete.

**The boundary.** This record settles only the omission of the `SpanContext`
argument from the summary line of `SpanFilterFn`. These occurrences reopen it:

- a change that makes step 2 of the doc stop naming the `SpanContext`
- a change that makes the summary line say something false, for example that
  the filter sees only its region
