## `src/ufa/src/output.rs` — a closed pipe ends `ufa` with a panic, not a quiet stop

**Settled** 2026-11-26 (branch ufa, finding R-20261126T235238Z#N2)

The finding is correct. `print_output`, `print_vec_table`, and the page
listing write each document with `println!`. Rust ignores SIGPIPE, thus
`println!` panics when the reader closes the pipe early, and
`ufa devices list --all --output json | head -1` ends with exit 101 and a
panic message on stderr.

The output that the reader asked for is complete when the panic occurs, and
no data is lost. The panic changes only the exit status and the text on
stderr. A fix needs a write helper that each output site calls, a map of
`ErrorKind::BrokenPipe` to a clean exit, and an end-to-end test that starts
the binary and closes its stdout early. That is a new output layer for the
tool, and the branch already holds 38 review rounds.

**The boundary.** A closed pipe that loses data, that changes a file or a
controller, or that stops a write to the controller part way, is a new
occurrence and is not settled here. A panic on a closed stdout after the
output is complete is settled.
