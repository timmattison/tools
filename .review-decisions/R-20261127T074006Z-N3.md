## `src/nle/src/pipeline.rs` — the docs of `FilterFn` and `ScreenFilterFn` disagree on the screen form

**Settled** 2026-11-27 (branch issue-161, finding R-20261127T074006Z#N3)

The finding is correct. The doc of `FilterFn` names the event, in-place and
span forms, but not `ScreenFilterFn`. The doc of `ScreenFilterFn` says that
steps 1 to 3 of `FilterFn` are the same. But its own step 2 gives the filter
the events before the region, and step 3 of `FilterFn` says that a filter
sees only the events inside its region.

The fix is prose in two doc comments. This round of the review loop is
record-only. A change to the docs is new text that a review must read, and
that review can start a new fix round. The doc of `ScreenFilterFn` states its
own step 2 in full, thus a reader of that doc gets the correct rule. The doc
of `Registered` names the four forms.

Boundary: this decision covers the text of the docs only. A code path where a
screen filter does not get `Screen::before` reopens it.
