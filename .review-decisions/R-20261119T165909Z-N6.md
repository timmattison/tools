## `README.md` exit status table of `chf` — the row for status 2 does not name a usage error

**Settled** 2026-11-19 (branch issue-674, finding R-20261119T165909Z#N6)

The finding is accurate. The row for status 2 in the exit status table of `chf` (`README.md:5907`) names only standard input or standard output that is not a terminal, and a home directory that `chf` cannot find. clap also exits 2 for a usage error: `chf foo` and `chf --bogus` print `error: unexpected argument` and exit 2.

**Why it is not fixed.**

- clap writes the usage error on standard error before it exits, and the message names the bad argument. A person who gets status 2 from a usage error thus also reads its cause.
- `chf` is an interactive tool and needs a terminal, so no script reads its status alone.
- The review loop of this branch is in its record-only round. A document change goes into the next incremental review, and the sweep of nits starts again.

**The boundary.** This record settles the missing words for a usage error in that one row. It does not settle a status that the table gives with a wrong meaning, or an exit status that `chf` gives and the table does not list at all.
