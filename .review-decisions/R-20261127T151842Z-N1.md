## `src/nle/src/filters/redaction/tests.rs` — the threshold of 3 s in the comment of `a_mark_of_an_earlier_filter_keeps_its_time_through_a_redaction`

**Settled** 2026-11-27 (branch issue-167, finding R-20261127T151842Z#N1)

The finding is accurate. The comment of the test says that idle compression
shortens each gap of 3 s or more. The test builds
`IdleCompression::new(1.0, 0.5, 80, 24)`, and the first argument is the
threshold, thus the threshold is 1 s.

**The fix costs more than the defect in this round.** The gaps of the fixture
are 0.5 s, 3 s and 3.5 s. A threshold of 1 s and a threshold of 3 s give the
same idle stretches and the same marks, because a stretch is idle when its
length is the threshold or more (`>=`). Thus the comment gives the correct
result of the fixture, and the test proves the same behavior with each
threshold. If a change of the threshold removes the marks, for example a
threshold above 3.5 s, the assertion `compressed.marks.len() > 1` fails.

The fix is a change of one comment line or one argument in a test file. A
review reads that change, thus the fix starts one more review cycle. This round
of the review loop is record-only.

**The boundary.** This record settles only the threshold that the comment of
this one test names, while the gaps of its fixture give the same marks for
both thresholds. Each of these occurrences reopens it:

- a change of the fixture or of the threshold that makes the two thresholds
  give different marks
- a comment that gives a wrong result of the test, for example a wrong count
  or a wrong time of a mark
- the same mismatch in production code or in a document of the repository
