## `README.md` redaction rules — the bullets on escape sequences and on DCS and APC strings stay as they are

**Settled** 2026-11-27 (branch issue-156, finding R-20261127T010840Z#N2)

The finding is accurate in two parts:

- The bullet "An escape sequence never changes, and a search never matches
  inside one" states no exception. The next bullet states the exception: the
  text of an OSC sequence is searched.
- The README names DCS and APC strings as not searched, and it does not name
  SOS and PM strings (`ESC X`, `ESC ^`). The module doc of
  `src/nle/src/filters/redaction.rs` and `escape_sequence` in
  `src/nle/src/filters/redaction/stream.rs` skip all four.

The defect is the order and the scope of two sentences. A reader reads the two
bullets together, and the second bullet gives the OSC rule with an example. An
SOS or a PM string is an escape sequence, thus the first bullet already tells a
reader that the filter does not search it. The README does not tell a reader
that the filter masks a value that it does not mask.

The fix costs more than the defect. The branch is in the record-only round of
the review loop. A change to the README is new text that a fresh review must
read, and a nit in that text starts one more fix round. Thus the loop does not
end clean.

The boundary: this record settles the wording of these two bullets only. A
README text that tells a reader that the filter masks a value that it does not
mask is a new finding. A change to the bullets that states the OSC exception
in the first bullet and names SOS and PM strings closes this decision.
