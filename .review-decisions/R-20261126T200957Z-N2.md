## `src/localnext/tests/common/mod.rs` — the stop helper keeps no time limit

**Settled** 2026-11-26 (branch issue-441, finding R-20261126T200957Z#N2)

The finding is accurate. `stop` in the common module of the `localnext` tests
calls `httpfile::Pool::shutdown` with no time limit. Commit e1ed53fe6 put the
same helper of the `sirn` tests behind `within_timeout`. If `Pool::shutdown`
does not release each worker, the `localnext` suite hangs and does not fail.

This gap is not new. At the base 6d815dc72, `stop` called the
`localnext::Pool::shutdown` of the local copy, also with no time limit. The
shutdown is the same shared code that the `sirn` tests hold behind a time
limit, and `src/localnext/tests/pool.rs` holds its own `within_timeout` around
`Pool::shutdown`. Thus a defect in the shutdown also fails a test that has a
time limit.

The cost of a fix: new code in a test helper of a crate that issue #419
removes. That code starts one more review round, which can find a new nit in
it.

The boundary: a report about a time limit in the test helpers of `localnext`
is this decision. This change reopens it:

- Issue #419 closes and `localnext` stays in the workspace.
- `src/localnext/tests/pool.rs` loses its `within_timeout` around
  `Pool::shutdown`.
