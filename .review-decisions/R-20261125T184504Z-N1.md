## `src/msgs/frontend/src/export.ts` — an Escape in the search box also cancels the export selection

**Settled** 2026-11-25 (branch msgs, finding R-20261125T184504Z#N1)

The finding is accurate. `initExport` puts its Escape listener on `document`,
and the Escape handler of `#global-search` in `search.ts` does not stop the
event. Thus one Escape in the search box clears the search and also cancels a
range selection for export.

The effect is small. Both actions are a cancel, and the user loses only the
start message of the selection. Two clicks make the selection again. No export
starts, and no file changes.

The cost of a fix: stop the event in the search handler, or make the export
listener ignore an event from a control. Each fix is new code with a new test,
and a new review round must read it. That cost is more than two clicks.

The boundary: an Escape in a text control that also cancels the export
selection is this decision. These changes reopen it:

- An Escape stops an export that runs, or changes a file.
- An Escape in a control loses more than the selection, for example a typed
  path.
- A key other than Escape in a control acts on the export selection.
