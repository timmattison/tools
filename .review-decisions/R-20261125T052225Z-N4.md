## `src/ic/README.md` — the `--monitor` and `--will-display` sentences do not name `--emit-rgba`

**Settled** 2026-11-25 (branch ic-emit-rgba, finding R-20261125T052225Z#N4)

The finding is correct. Clap refuses `--emit-rgba` beside `--monitor` and beside `--will-display` (`conflicts_with_all` of `emit_rgba` in `src/ic/src/main.rs`). The `--emit-rgba` paragraph of the README names both refusals. The sentence "`--monitor` is an input mode of its own" and the sentence "`--will-display` is an input mode of its own" do not name `--emit-rgba`. Thus the README gives each refusal from one side only.

The README says nothing false. Each refusal is in the paragraph of the newest flag, which is the paragraph that a person reads to use `--emit-rgba`. If a person gives the two flags together, clap stops at once with a message that names both flags, thus no run does a wrong thing.

The fix is two edits of prose. This round of the review loop is record-only, and review-time reads the README. An edit is thus new text that the next review reads, and a new nit in it starts a new fix round. The cost of that review cycle is more than the cost of a refusal that the README gives from one side and clap gives at once.

The boundary: this decision covers only the two sentences that do not name `--emit-rgba`. A sentence of the README that says a combination works when clap refuses it, or that clap refuses a combination that works, is a new finding.
