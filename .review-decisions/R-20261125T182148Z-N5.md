## `CLAUDE.md` — no "Guards Enforcing This" bullet names `repo_guards::clippy_superset`

**Settled** 2026-11-25 (branch ufa, finding R-20261125T182148Z#N5)

The finding is accurate. The branch adds the guard
`repo_guards::clippy_superset` (`src/repo-guards/src/clippy_superset.rs`). A
crate-local `clippy.toml` replaces the root file, thus the guard makes each
crate-local file restate each entry of the root file. `CLAUDE.md` names the
guard nowhere. Only the header of `src/ufa/clippy.toml` names it. Other
`repo_guards` modules, for example `arboard_wall` and `op_wall`, have a bullet
under a "Guards Enforcing This" list.

**The cost is a new review cycle.** The fix is prose in `CLAUDE.md`. This
round of the review loop is record-only, and a fresh review reads the changed
section and can find a new nit in it. Then a new fix round starts, and the
loop does not end clean. The guard does its work with no bullet. It finds
each `clippy.toml` through a walk of the repository, not through a list, and
it fails `cargo test` on a crate-local file that drops an entry of the root
file. Its module doc states the rule and the reason. Thus a person who adds a
new crate-local file learns the rule from the failure, at the time the rule
applies. `R-20261124T185448Z-N2.md` settles a different gap in the text of
`CLAUDE.md` for the same reason.

**The boundary.** This decision settles only the absence of a bullet in
`CLAUDE.md`. A crate-local `clippy.toml` that the guard does not read, or a
statement in `CLAUDE.md` that contradicts the guard, is a new finding.
