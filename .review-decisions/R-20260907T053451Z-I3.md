## `src/termgfx/src/probe.rs` — the read of a refusal takes the bytes a user typed while the picture drew

**Settled** 2026-09-07 (branch issue-465, finding R-20260907T053451Z#I3)

`drain` reads the controlling terminal one byte at a time until the answer of
the primary device attributes arrives, and it gives every byte it read to the
parser, which keeps the APC blocks alone. A byte the user typed while the
picture drew stands in front of that answer, so `ic` reads it and drops it.

The finding is accurate, and it is accurate about the common path. Before this
branch, `Capabilities::ask_once` asked the terminal only when
`classify_terminal_type` gave `TerminalType::Unknown`, so a terminal that the
environment names — `xterm-kitty`, Ghostty, WezTerm — never opened `/dev/tty`
in raw mode at all. Now every still picture on a terminal of the Kitty protocol
does. A user who types the next command while a large picture crosses a mosh
link loses those characters.

It is not fixed, because the read is the price of the report and no cheaper
price exists.

- **The read is not optional once the picture carries `q=1`.** The terminal
  writes the refusal into the input queue whether or not a program reads it. A
  run that reads nothing leaves a whole APC block there, and the shell of the
  user reads that block next and takes it for key presses. The doc of
  `KITTY_FAILURES_ONLY` in `src/termgfx/src/draw.rs` already states this rule.
  So the choice is not "read or do not read". It is "report the refusal or do
  not ask for it".
- **A byte cannot go back on a terminal.** The read must reach the answer of
  the attributes, and every byte in front of that answer leaves the queue with
  it. `TIOCSTI` is the one call that pushes a byte back, and it is absent or
  disabled on the platforms this tool runs on, and it is a hazard where it
  exists.
- **A bound by picture size trades a certain small cost for an uncertain
  silence.** No terminal publishes the cap of its image store, so any threshold
  is a guess. A picture under the guess that a terminal refuses for another
  reason — `EINVAL`, `ENOTSUPP`, a PNG the decoder of the terminal will not
  take — goes back to exiting 0 in front of an empty screen. That is issue #465
  returning for exactly the pictures whose refusal has nothing to do with size.
- **The window is the round trip and not the budget.** `QUERY_BUDGET` is 500
  milliseconds, and `drain` ends at the answer of the attributes, which every
  terminal writes at once. A user loses the characters of one round trip, one
  time, for one still picture.

The boundary: this settles the round trip itself as the price of reporting a
refusal, for a still picture on a terminal that reads the Kitty protocol. A
finding that the read takes bytes it has no need to take is a different finding
and is not settled here. Two such findings would be a read that runs past the
answer of the attributes, and a read that runs for a picture which asked the
terminal for no answer.
