## `src/nle/src/pipeline.rs` `FilterRegistry::run` — the `# Errors` doc does not name the two mark errors

**Settled** 2026-11-27 (branch issue-167, finding R-20261127T022719Z#N2)

The finding is accurate. `FilterRegistry::run` gives each error of
`run_with_end`. Two of those errors are about marks: a span filter that answers
a mark time that is not finite, below zero, or after its length, and a mark
time after the last filter that is not finite. The `# Errors` doc of `run`
names neither of them. The docs of `render` and `render_with_marks` give "the
errors of `FilterRegistry::run`", thus they miss the same two errors.

**The fix costs more than the defect in this round.** The defect is a doc header
that names too few errors. The code refuses each bad mark, and the error text
that a user reads names the kind, the mark time, and the rule. The doc of
`run_with_end` names the two mark errors, and the doc of `SpanFilterFn` states
the rule for an answered mark. Thus no caller gets a wrong behavior or a wrong
message, and each caller already handles `NleError::RenderError`.

The fix is a change of a document. This round of the review loop is
record-only. A change of a document starts one more review cycle, and that
review can find a new nit in the new text.

**The boundary.** This record settles only the two mark errors that the
`# Errors` docs of `run`, `render`, and `render_with_marks` do not name. Each of
these occurrences reopens it:

- code that accepts a bad mark time that `run_with_end` refuses now, or that
  gives a mark error as a different `NleError` variant
- an error message that a user reads, or the doc of `run_with_end` or
  `SpanFilterFn`, that states the rule for a mark wrongly
- a new error of `run_with_end` that is not about a mark and that the doc of
  `run` does not name

Record R-20261126T225106Z-N1 settles the word "after" in the same doc. This
record does not change that record.
