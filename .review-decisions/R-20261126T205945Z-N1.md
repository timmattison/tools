## `src/nle/src/commands.rs` — the end of a link chain needs only the picked ending (second report)

**Settled** 2026-11-26 (branch issue-158, finding R-20261126T205945Z#N1)

The finding is accurate, and it is the same finding as
R-20261126T205525Z#N1. The record
`.review-decisions/R-20261126T205525Z-N1.md` gives the reason, the cost and
the boundary.

In short: `matching_ending` picks the longest ending of the path, but the
check of the end of the chain accepts each name that ends with that ending.
The two rules differ only for a set where one ending is a suffix of another.
`RECORDING_ENDINGS`, `VIDEO_ENDINGS` and `WEB_ENDINGS` hold no such pair, so
no current input shows the gap.

The cost of a fix: new code in `resolve_output_path`, a new unit test, and a
change to its doc. That fix starts one more review round, which can find a
new nit in the new code.

The boundary is the boundary of R-20261126T205525Z#N1. A set with a suffix
pair that reaches `resolve_output_path` reopens both records.
