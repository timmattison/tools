## `src/ufa/src/main.rs` — a blank `UNIFI_INSECURE` is refused, not read as absent

**Settled** 2026-11-27 (branch ufa, finding R-20261127T131122Z#N2)

The finding is correct. `clap_builder` 4.6.7 (`Parser::add_env`) gives an empty
environment value to the value parser, and `parse_bool_env("")` refuses it.
`--insecure` is global, thus a blank `UNIFI_INSECURE=` in the environment or in
the `.env` file stops each command, `ufa config path` included. A blank
`UNIFI_URL`, `UNIFI_API_KEY` or `url` goes to the next source.

The refusal is the written rule. `src/ufa/.env.example` says that each value
other than true/false, 1/0, yes/no and on/off "is rejected rather than
ignored". The refusal also fails in the safe direction: certificate
verification never turns off by accident. The error names the flag and the
accepted values, thus the user can find the variable. A fix changes the parse
of a security flag, adds a test, and starts one more review cycle.

**The boundary.** A value of `UNIFI_INSECURE` or `--insecure` that turns
verification off and is not in the written list is a new occurrence. A refusal
that does not name the flag or the accepted values is a new occurrence too. The
refusal of a blank value is settled.
