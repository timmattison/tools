## `README.md` chapters section and `Form::for_chapters` — the text names only a redo that gives back the chapter in edit

**Settled** 2026-11-28 (branch issue-164, finding R-20261128T005520Z#N1)

The finding is accurate. `Editor::undo` (`src/nle/src/editor.rs:398-406`)
puts back the `before` snapshot exactly. `Form::for_chapters`
(`src/nle/src/ui/chapters.rs`) keeps the form when the project holds the exact
marker of the form. Thus an undo that gives back the exact marker also gives
back the edit. For example: Add Intro at 5, Remove, Undo, Edit, Redo (the form
is empty), then Undo. The form shows **Save Chapter**, 5 and Intro again. The
README (`README.md:6785-6787`) and the doc comment of `Form::for_chapters` say
only that a redo gives back the edit.

The behavior is correct. Only the text is incomplete. The code makes no
difference between an undo and a redo: the one rule is "the project holds the
exact marker". The test
`a_redo_that_gives_back_the_chapter_in_edit_gives_back_the_edit`
(`src/nle/src/ui/tests.rs`) holds that rule for a redo. No user loses data
because of the text: the form shows a chapter that the project holds.
