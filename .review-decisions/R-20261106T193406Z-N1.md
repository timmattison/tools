What TDD gives, a test that can fail for the behavioral reason, is present for
each rule. Only the order of the commits is wrong.

**A reorder does not make a red, and the real fix buys nothing durable.** The
rules do not exist before their green commits. A move of the tests to before
those commits gives a compile error, not a behavioral red. A real red needs a
split of each green commit. The tool is an interactive rebase, which only Tim
can run. Every later commit then gets a new SHA.

The branch is pushed. `origin/issue-642` is at `b585c145`, and PR #647 (branch
issue-642) is open on that head. Thus a rewrite also needs a force push, which
only Tim can run. The review `R-20261106T193406Z` then reads `rewritten` in
`pr-merge-gate.ts`, and the gate refuses the merge until a fresh review of the
whole branch. Against that: this repository squash-merges each PR with an
explicit `--subject` and `--body`, thus no commit of this branch reaches
`main`.

**The boundary.** This decision settles the order of the named commits on the
branch `issue-642` only, where each test exists and a mutant shows that it can
fail. It does not settle a missing test, or a test that nobody showed can fail.
It does not permit a green commit that implements more than its red test asks
for, as a habit.

**The pattern.** This is the thirteenth branch with this shape.
`R-20261105T032353Z-N1` is the twelfth. The repair belongs to
timmattison/dotfiles issue #22, and not to this record.
