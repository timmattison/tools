## `src/faulte/src/main.rs:246` — `faulte --limit N kill` takes the flag and ignores it

**Settled** 2026-11-25 (branch issue-669, finding R-20261125T040555Z#N2)

The finding is accurate. `parse_cli` refuses a typed `--limit` with
`faulte tui` in both spellings. `faulte --limit 3 kill` still takes the flag
and ignores it, and `kill_refuses_the_limit_of_the_ranking`
(`src/faulte/tests/cli.rs`) asserts that the run succeeds. That spelling and
its test came with issue #512 (commit 406fd325), before this branch.
`README.md` said that `faulte kill` refuses `--limit` with no limit on the
spelling, which was false.

Issue #669 says: "The output and the exit codes of `faulte` and of
`faulte kill` do not change." A refusal of `faulte --limit 3 kill` changes
that exit code from 0 to 2, thus this branch must not make it. This branch
corrects the text instead: `README.md`, the doc of `parse_cli`, and the doc of
the test now say that `faulte kill` refuses `--limit` after its name, and
takes it and ignores it before its name.

The boundary: this settles the spelling `faulte --limit N kill` on branch
issue-669. A change of that exit code belongs to an issue of its own. A text
that again says that `faulte kill` refuses `--limit` in each spelling is a
new finding.
