## `README.md` and the doc of `walk()` in `src/ff/src/walk.rs` — the claim "as `find` does" stays without the exception for a root with no name

**Settled** 2026-11-26 (branch issue-508, finding R-20261126T182534Z#N1)

The finding is accurate. `match_root` gives no match for a named root whose
path has no file name, because `Path::file_name` gives `None` for `.`, `..`
and `/`. In a directory that holds the file `a`, `ff '*' .` prints only
`./a`, but `/usr/bin/find . -maxdepth 0 -name '*'` prints `.`. The sentence
of `README.md` and the doc of `walk()` do not give this exception.

The exception is not hidden. The doc of `match_root` states it, and the test
`a_root_with_no_name_never_matches` in `src/ff/tests/walk.rs` holds it. The
difference occurs only for a pattern that matches the name `.`, `..` or `/`.

The cost of a fix: the fix is prose in two files. Prose changes no behavior,
and it is new text that the next review reads. Thus it starts one more review
round, which can find a new nit in the new text.

The boundary: a report that the README or the doc of `walk()` omits the
no-name exception is this decision. These changes reopen it:

- `match_root` changes, and a named root that has a file name does not match
  where `find` matches it.
- A new place states the claim, for example the `--help` text of `ff`.
- The test `a_root_with_no_name_never_matches` goes away.
