## Commit order on an unpushed branch — fade guards of `ha` came before their tests

**Settled** 2026-11-01 (branch issue-623, finding R-20261101T170934Z#N1)

The review found that two green commits added rules that their red commits did
not ask for:

- The green commit `c5bf3bb1` ("fade the text of a finished run row by its
  age") added the `state.is_finished()` guard, thus an active run and a queue
  entry keep the default color. It also put the marker cells in `MARK_STYLE`.
  Its red commit `152039f5` tests only the gray of a finished row. The tests
  `a_run_that_is_not_finished_has_no_fade`, `a_queue_entry_has_no_fade` and
  `the_marker_cells_of_a_faded_row_keep_the_colors_of_the_terminal` came after
  it, in `b483365c`, and passed when they were written.
- The green commit `1e1931ea` ("fade the job rows of a finished run with their
  run") added the `run.state.is_finished()` and `selected: false` guards of the
  `Row::Job` arm of `age_style`. Its red commit `190303d5` tests only a
  finished job row with no highlight. The test
  `a_highlighted_job_row_of_a_finished_run_has_no_fade` came after it, in
  `49ddf833`.

The TDD rule in `CLAUDE.md` asks for the red commit first. The finding is
accurate.

It is not fixed, because the defect is the order of the commits and nothing
else.

**The coverage is real.** The run of `address-issues` for this finding did five
mutants on `933dd64e`, one at a time, with `cargo test -p ha --lib` (723
tests). The file was restored after each mutant, and `git status --short` was
empty at the end.

- M1: the guard `if state.is_finished()` of the `Row::Run` arm removed.
  `a_run_that_is_not_finished_has_no_fade` fails.
- M2: `MARK_STYLE` changed to `Style::new()`. Five tests fail, among them
  `the_marker_cells_of_a_faded_row_keep_the_colors_of_the_terminal` and
  `the_sleeping_mark_of_a_faded_row_keeps_the_colors_of_the_terminal`.
- M3: the guard `if run.state.is_finished()` of the `Row::Job` arm removed.
  `the_runner_name_is_cyan_and_the_rest_of_the_job_row_is_not` fails.
- M4: `selected: false` of the `Row::Job` arm changed to `selected: _`.
  `a_highlighted_job_row_of_a_finished_run_has_no_fade` fails.
- M5: the last arm `_ => Style::default()` changed to `_ => faded(now)`. Six
  tests fail, among them `a_queue_entry_has_no_fade`.

The guard of the `Row::Departure` highlight had no test. That gap was finding
`R-20261101T170934Z#I1`, and `933dd64e` added
`a_highlighted_departure_row_has_no_fade`, which fails under the mutant
`selected: _` of that arm.

What TDD gives, a test that can fail for the behavioral reason, is present.
Only the order of the commits is wrong.

**A reorder does not make a red, and the real fix buys nothing durable.** The
branch is not pushed, thus a rewrite needs no force push. But a move of the
tests to before their green commits does not make them red: before `c5bf3bb1`,
no row fades, thus each "has no fade" test passes there too. A real red for each
guard needs `c5bf3bb1` and `1e1931ea` split, first into a fade with no guard,
then a red test, then the guard. The tool is an interactive rebase, which only
Tim can run. Every later commit then gets a new SHA. The review
`R-20261101T170934Z` ends on `c0359385`, thus after a rewrite `pr-merge-gate.ts`
calls the review `rewritten` and refuses the merge until a fresh review of the
whole branch. Against that: this repository squash-merges every PR with an
explicit `--subject` and `--body`, thus no commit of this branch reaches `main`.

**The boundary.** This decision settles the order of the named commits on the
branch `issue-623` only, where each test exists and a mutant shows that it can
fail. It does not settle a missing test, or a test that nobody showed can fail.
It does not permit a green commit that implements more than its red test asks
for, as a habit.

**The pattern.** This is the tenth branch with this shape (see the records of
`R-20261017T222526Z-N1`, `R-20261018T041353Z-N1`, `R-20261018T170445Z-N1`,
`R-20261018T235403Z-N1`, `R-20261020T163846Z-N1`, `R-20261022T182813Z-N1`,
`R-20261025T160203Z-N1`, `R-20261028T194028Z-N1`, and `R-20261030T110703Z-N1`).
The repair belongs to the brief of the green step in the TDD skills of the
dotfiles repository (timmattison/dotfiles issue #22, open), and not to this
record.
