## `src/wl/src/socket_table/` — the order of the commits of the macOS reader and the Linux reader stays as it is

**Settled** 2026-11-24 (branch wl, finding R-20261124T160606Z#N1)

The finding is accurate. The green commit `355821cc` adds the Linux reader and
all of its unit tests, and no red commit comes before it. Its body gives the
reason that nothing on macOS reads `/proc`. But the same body says that the
text parse compiles on each platform, thus its tests run on macOS. A red commit
of those tests against a stub of `parse_port_status` was possible. The Tests
section of the body of PR #752 gives the same incorrect reason.

The green commit `5e8f3bf5` of the macOS reader has the same shape. Its
fail-closed rules (a bad `xi_len` or `xso_len`, an overrun, a short record, a
cut list, a short header) and their tests arrive together. The red commit
`3a4a3f62` before it asks only that port 1 reads free.

**The only fix is a rewrite of the history, and it costs more than the
defect.** The three commits are on `origin/wl`, the head of PR #752 (issue
#747). A new order needs an interactive rebase and a force push, and the git
guardrail of this machine refuses a force push. The tests exist and pass, and
the body of `355821cc` records a mutant (`parse_port_status` always gives
`Free`) that 7 of the Linux tests fail. This repository squash-merges each PR,
thus the commits do not reach `main` as separate commits. The review itself
proposes to decline the order with a record.

The text of the PR body stays as it is, because a change of it starts a new
review cycle for no change of behavior. This record holds the correct reason:
a red commit of the Linux tests was possible, and the branch did not make one.

**The boundary.** This decision settles the order of the commits `3a4a3f62`,
`5e8f3bf5`, and `355821cc` only. It does not settle a missing test: a
fail-closed rule of either reader that no test reaches is a new finding. It
does not let a later green commit, on this branch or on a different branch, add
code that its red test does not ask for.
