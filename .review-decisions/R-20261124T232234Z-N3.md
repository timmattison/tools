## `src/msgs/frontend/src/export.ts` — `performExport` reads the chat id after the save dialog

**Settled** 2026-11-24 (branch msgs, finding R-20261124T232234Z#N3)

The finding is accurate. `performExport` takes `start` and `end` before
`await save(...)`, but it reads `currentExportChatId` after the dialog returns.
It does not compare the selection before the call of `export_messages`. If a
change of chat completes while the save dialog is open, the call gets the new
chat id with the message ids of the old chat. Or it exports a selection that
the user left.

**The fix costs more than the defect.** The save dialog is modal, thus the
sequence needs a change of chat that completes while the dialog is open. When
the ids are not in the chat, `get_messages_between` refuses them with
"Message {message_id} is not in chat {chat_id}", and the export writes no file
of a different chat. The fix is two lines and a vitest test. But this round of
the review loop is record-only, thus that code starts one more review cycle.

**The boundary.** This record settles the read of the chat id after the dialog
only. An export that writes the messages of a chat that the user did not
select reopens this record.
