## Commit order on a pushed branch — three behaviors of `ha` got their tests after their green commits

**Settled** 2026-10-18 (branch issue-569, finding R-20261018T170445Z#N1)

The review found that two green commits added behaviors that no earlier red
commit tested:

- `dbeb0eee` added the removal of the marks of runs that leave the list of
  runs, in `cycle` in `src/ha/src/worker.rs`. Its test,
  `the_mark_of_a_run_that_leaves_the_list_of_runs_is_removed`, came after it,
  in `2e734370`.
- `b3eace96` added `self.jobs.retain` in `settle` in `src/ha/src/board.rs`, and
  it stored the job answer of a run that was never expanded. The tests
  `a_run_that_leaves_the_board_loses_its_job_states` and
  `a_run_that_never_was_expanded_shows_the_running_marker_of_its_jobs` came
  after it, in `10fd8a95`.

The TDD rule in `CLAUDE.md` asks for the red commit first. The finding is
accurate.

It is not fixed, because the defect is the order of the commits and nothing
else.

**The coverage is real.** The run of `address-issues` for this finding did
three mutations on `25b8db38`, the last commit of the review, with
`cargo test -p ha --lib`. With no mutation, 354 tests pass.

- With `.retain(|_, _| true)` in place of the removal of the marks, one test
  fails: `the_mark_of_a_run_that_leaves_the_list_of_runs_is_removed`.
- With no `self.jobs.retain` line in `settle`, one test fails:
  `a_run_that_leaves_the_board_loses_its_job_states`.
- With a `set_jobs` that stores an answer only for an expanded run, three
  tests fail: `a_run_that_never_was_expanded_shows_the_running_marker_of_its_jobs`,
  `the_answers_for_a_collapsed_run_show_after_an_expand`, and
  `app::tests::the_jobs_of_a_collapsed_queued_run_show_the_running_marker`.
  The second test came in the green commit `b3eace96` itself, and the third
  came in `10fd8a95`.

What TDD gives, a test that can fail for the behavioral reason, is present.
Only the order of the commits is wrong.

**The one fix is a rewrite of a pushed branch, and it buys nothing durable.**
To fix the order, each test must move into a red commit before its green
commit. The first such red commit is `60229b6c`. That gives a new SHA to each
commit from `60229b6c` to HEAD, which was 12 commits at the time of the review. `origin/issue-569` holds those commits,
thus the rewrite needs a force push. `block-dangerous-git.ts` refuses a force
push with no override, thus only Tim can run it. The review
`R-20261018T170445Z` ends on `25b8db38`, which is one of those commits. After
the rewrite, `pr-merge-gate.ts` finds that the commit is not on the branch,
calls the review `rewritten`, and refuses the merge until a fresh review of the
whole branch. Against that cost: this repository squash-merges every PR with
an explicit `--subject` and `--body`, thus no commit of this branch reaches
`main`.

This decision applies the reasons of `R-20261017T222526Z-N1` and
`R-20261018T041353Z-N1` to this branch.

**The process is not settled here.** `R-20261018T041353Z-N1` says that a third
branch with this shape is a new finding about the process. This branch is
that third branch. In each of the three branches, the green commit added a
cleanup rule, a `retain` or a filter, that the red test did not ask for. This
decision does not change the process. That change belongs to the instructions
that brief the subagent of each green step, and Tim decides it.

**The boundary.** This decision settles the order of `dbeb0eee` and
`2e734370`, and of `b3eace96` and `10fd8a95`, on the branch `issue-569` only,
where the tests exist and a mutation shows that each can fail. It does not
settle a missing test, or a test that nobody showed can fail. It does not
change the rule of `R-20260820T153740Z-N2` for an unpushed branch where no
review names the commits that a rebase moves. It does not permit
implementation first as a habit.
