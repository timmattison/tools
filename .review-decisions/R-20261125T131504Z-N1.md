## `src/wu/src/main.rs` — the doc comment of `get_file_users_linux` says that a failed walk of `target_path` is an error

**Settled** 2026-11-25 (branch github-actions-ci, finding R-20261125T131504Z#N1)

The finding is accurate. The doc comment of `get_file_users_linux` says that
the function returns an error when it cannot walk `target_path`. But
`collect_files_recursively` drops each walk error with
`filter_map(|e| e.ok())` and always returns `Ok`. Thus a failed walk gives a
shorter list of files, not an error. Only a failed open of `proc_root` is an
error.

**The cost is a new review cycle.** This round of the review loop is
record-only. A change to the comment is a new change that a review must read,
and a fresh review can find a new nit in it. Then a new fix round starts, and
the loop does not end clean. The defect is in the text of one doc comment. No
caller reads the claim, and no code branches on an error that does not come.
The behavior of `wu` does not change.

**The boundary.** This decision settles only the wording of that comment. A
caller that depends on an error from a failed walk, or a change that makes
`collect_files_recursively` return an error, is a new finding.
