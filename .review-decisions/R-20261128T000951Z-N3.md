## `src/nle/src/filters/color_scheme/tests.rs` — `a_value_of_the_wrong_type_is_refused` does not hold that each message names its option

**Settled** 2026-11-27 (branch issue-166, finding R-20261128T000951Z#N3)

The finding is accurate. The helper `refusal` panics when the parse succeeds.
Thus each `!is_empty()` assertion holds only that the message is not empty. A
message for `swap`, `cube`, or `theme` that names the wrong option passes the
test.

**The fix costs more than the defect in this round.** The test holds the
behavior that matters most: each value of the wrong type is a refusal, not a
filter that runs with a default. Each of the three messages comes from one
`format!` that takes the name of the option from a constant (`THEME_OPTION`,
`SWAP_OPTION`, or the `key` of `read_rule`). A wrong name in a message is a
defect of the text, not of the refusal. The fix is a change of a test file. A
review reads that change, thus the fix starts one more review cycle, and this
round of the review loop is record-only.

**The boundary.** This record settles only the content of the three
wrong-type messages. Each of these occurrences reopens it:

- a value of the wrong type that the parse accepts
- a wrong-type message on `main` that names a different option, or no option
- a wrong-type message that does not come from a `format!` with the constant
  of its option
