## `src/beta/NLE-ROADMAP.md` Phase 1 — "a pure function `Event[] → Event[]`" stays as it is

**Settled** 2026-11-26 (branch issue-154, finding R-20261127T033007Z#N1)

The finding is accurate. The rows of #153 and #154 in the Phase 1 table are
span filters, `Fn(Span, &FilterOptions) -> Result<Span, String>`. A span
filter takes and gives a length too, and it can give an error. Thus the
sentence above the table, "Every filter below is a pure function
`Event[] → Event[]`", is not true for those rows. The sentence was stale on
`main` after #153, and this branch adds one more row that says "Each one is a
span filter".

The defect is one sentence of a planning document, not code. Each row of the
table names its own interface. Item 2, **Filter interface**, of the same
document states the two kinds of filter correctly, and so does the code in
`src/nle/src/pipeline.rs`. A reader who uses
the table to do the work reads the row, not only the sentence above it. The
rest of the sentence stays true: each filter is pure, and a test can run it
with no UI.

The fix costs more than the defect. A change of the roadmap is new text that
a fresh review must read, and the loop then starts one more fix round for one
sentence of prose.

The boundary: this settles the sentence above the Phase 1 table. A row that
names the wrong interface for its own filter is a new finding. A change to
item 2, **Filter interface**, of the roadmap that states a wrong contract is
a new finding too.
