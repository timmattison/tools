## `src/nle/frontend/src/format-duration.ts` — `formatDuration` has no rule for a negative duration

**Settled** 2026-11-25 (branch 170, finding R-20261125T124305Z#N2)

The finding is accurate. `Recording.duration` in `src/nle/src/types.rs` is an
`f64` that `Recording::load` reads from the file with no check. A damaged file
with duration -0.5 shows a negative minute and a negative second in the
timeline and in the properties panel. `format-duration.test.ts` holds only
values of 0 or more.

The beta recorder writes the duration of a recording as the time from the
start to the end, and that time is never negative. Thus only a damaged file or
a file that a person edited gives a negative duration. The result is a strange
string in two labels. Nothing stops, and no data changes.

The fix needs a choice between two rules: `formatDuration` shows a negative
duration as `0m 0.0s`, or `load_recording` refuses a recording with a negative
duration. The cost of either fix: a code change, a test, and one more review
round, for input that the recorder does not write.

The boundary: a report that `formatDuration` has no rule for a negative
duration is this decision. A recording from beta with a negative duration, or a
command that does arithmetic on the duration, reopens it.
