## `src/nle/src/ui/tests.rs` `other_controls` — the timeline view is not one of the controls of the Undo and Redo test

**Settled** 2026-11-27 (branch issue-824, finding R-20261127T232554Z#N1)

The finding is accurate. The merge `0240d2d9` brought in the timeline view of
issue #150 (PR #826, branch `issue-150`). The view is a focusable element with
its own `onkeydown` handler (`src/nle/src/ui/timeline.rs:173`).
`other_controls` holds the Apply Speed button, the Find menu, the playhead
control, and the theme menu. It does not hold the timeline view. Thus no test
of the window presses Cmd/Ctrl+Z or Cmd/Ctrl+Shift+Z on the timeline view.

The behavior is correct now. The handler calls `key_action` with
`command = true` for a press with Cmd, Ctrl, or Alt. `key_action` then gives
`None`, and the handler returns before `prevent_default`. The event bubbles to
the history listener of the root. The unit test
`other_keys_and_keys_with_a_modifier_do_nothing`
(`src/nle/src/timeline/tests.rs`) holds the `None` for a press with a
modifier. The gap is a later change of the handler, for example a call of
`stop_propagation`. Only a test of the window finds that change.

**The fix costs more than the defect.** The fix is a new accessor for the
element of the timeline view in the `Window` test helper, and a fifth entry in
`other_controls`. That change is new test code that a review must read. A new
fix round then starts, and this round of the loop is record-only. The handler
calls no `stop_propagation` now, thus the test protects only against a
change that nobody made.

**The boundary.** This record settles only the missing entry for the timeline
view. These occurrences reopen it:

- a change of the `onkeydown` handler of the timeline view that calls
  `stop_propagation`, or that handles a key with Cmd, Ctrl, or Alt
- a change of `key_action` that gives an action for a press with a modifier
- a new focusable control with its own key handler that is not in
  `other_controls`
