## `src/nle/assets/main.css` `.chapter-mark-label` — the chapter label has no width limit

**Settled** 2026-11-27 (branch issue-164, finding R-20261127T215657Z#N1)

The finding is accurate. `.chapter-mark-label` has no `max-width`, and the
chapter editor refuses only an empty label. Thus a label of any length reaches
the timeline. The label sits at the top of the ruler band with `z-index: 4`,
in the same band as the time labels of the ruler. A long label, for example a
sentence, covers the time labels and the labels of the next chapters over its
width.

The defect is only visual. The ruler has no click handler, and the label has
no click handler. The zoom buttons are in `.timeline-zoom`, outside the ruler
band. Thus a long label hides text, but it takes no click that a control
needs. The `title` and the `aria-label` of the label give the full
description. The user types the label, and the user can make it shorter in
the chapter panel.

**The fix costs more than the defect.** The fix is a CSS change with a chosen
width, and a review can question that width again. A fresh review reads the
change. The loop then starts one more fix round for the look of a label that
the user chose to make long.

**The boundary.** This record settles only the width of the label on the
ruler. These occurrences reopen it:

- a click handler on the ruler, or on an area under the label, so that a long
  label takes a click that a control needs
- a label that covers the playhead, a clip block, or a zoom button
- a label that hides the marker line of its own chapter
