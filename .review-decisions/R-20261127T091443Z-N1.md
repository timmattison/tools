## `src/wdid/src/defs.rs` doc of `tally` — the sentence about reasons names only some of the starts

**Settled** 2026-11-27 (branch issue-728, finding R-20261127T091443Z#N1)

The finding is accurate. The doc of `tally` names the functions that a hook, a
trap, or a widget with a key runs, and the aliases that the code of a bash
start names. `reasons::find` in `src/wdid/src/defs/reasons.rs` also gives a
reason to `command_not_found_handler`, to the function of a special widget and
of each widget that `add-zle-hook-widget` adds, and to each function that the
code of a bash start names, because `code_runs` calls `function_runs`. Thus a
reader of the doc can think that such a function shows in Never used.

The behavior is correct, and only the prose is incomplete. The tests of
`reasons` and of `wdid defs` hold each of these starts. The fix is prose, and
the branch is in a record-only round of its review loop. A changed doc is new
text that a fresh review reads, and that review can find a new nit in it. That
starts a new fix round for a sentence that changes no result.

The boundary: this decision settles the sentence of the doc of `tally` as it is
at `src/wdid/src/defs.rs:439-444`. A new kind of start that `reasons::find`
reaches and that the doc does not name is the same case. A test or a user
report that shows a start function in Never used is a defect of the code, not
of this doc, and it reopens this decision.
