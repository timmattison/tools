## `src/msgs/frontend/src/search.ts` — no test holds a waiting search when the index build fails

**Settled** 2026-11-25 (branch msgs, finding R-20261125T014525Z#N2)

The finding is accurate. `resumeWaitingSearch` runs the waiting search for each
state that is not `building`, thus a build that fails runs the search, and the
result list shows `Search failed:` with the error of the backend. No test of
`search.test.ts` starts a wait and then sends the state `failed`. A change that
resumes only on `ready` leaves the spinner and the text "starts when the index
is ready" on the screen, and the tests still pass.

**The fix costs more than the defect.** The code is correct today, and the gap
is a missing test, not a wrong result. The test needs a fake of the status
event, a rejected `search_messages`, and a check of the list. This round of
the review loop is record-only, thus that test starts one more review cycle.

**The boundary.** This record settles the missing test of the `failed` state
for a waiting search only. A change to `resumeWaitingSearch` that treats
`failed` differently from `ready`, or a waiting search that stays on the
screen after the build ends, reopens this record.
