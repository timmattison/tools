## Commit order on a pushed branch — the green commit of the frozen flag of `cctop` held two rules that its red test did not ask for

**Settled** 2026-11-18 (branch issue-715, findings R-20261119T005324Z#N1 and R-20261119T005730Z#N1)

Two reviews reported the same defect in the same words. This record settles both ids.

The review found a green commit that implements more than its red commit asks for. The green commit `b3a0abf8`, "a frozen row shows the state of its file and the frozen flag", has the red commit `9690e16e`. That test asks only that a stopped session shows the state of its file and the frozen flag. The green commit also holds two rules, and it rewrites their tests in the same commit:

- A newer file of a frozen session is a change, and the row stays frozen. The old test `a_newer_file_of_a_frozen_session_changes_nothing_on_the_screen` asserted `applied == None`. The commit flipped it to `a_newer_file_of_a_frozen_session_changes_its_state_and_stays_frozen`.
- A freeze logs the state of the file on both sides. The test is `a_freeze_logs_the_state_of_the_file_on_both_sides`.

The TDD rule in `CLAUDE.md` asks for the red commit first. The finding is accurate.

It is not fixed, because the defect is the order of the commits and nothing else.

**The coverage is real.** The run of `address-issues` for this finding applied each mutant below alone to `2ee26a2c`, ran `cargo test -p cctop --lib board::`, and then restored the file. With no mutant, 37 tests pass.

- Mutant A, in `Board::apply`: `let same_state = old.map(|o| o.run) == Some(new_state.run);` in place of `let same_state = old == Some(new_state);`. Only the frozen flag decides, so a newer file of a frozen session is "the same state". 5 tests fail: `a_newer_file_of_a_frozen_session_changes_its_state_and_stays_frozen`, `a_change_of_state_removes_the_mark`, `apply_logs_a_change_of_state_with_the_new_stamp`, `changes_give_the_newest_first`, `the_log_keeps_at_most_log_capacity_changes_and_drops_the_oldest`.
- Mutant B, in `Board::set_run_status`: `let new = ShownState::new(PaneState::Idle, run);` in place of `let new = session.shown();`. The new side loses the state of the file. 2 tests fail: `a_freeze_logs_the_state_of_the_file_on_both_sides`, `a_newer_file_of_a_frozen_session_changes_its_state_and_stays_frozen`.
- Mutant C, in `Board::set_run_status`: `let old = ShownState::new(PaneState::Idle, session.run);` in place of `let old = session.shown();`. The old side loses the state of the file. 2 tests fail: `a_freeze_logs_the_state_of_the_file_on_both_sides`, `a_newer_file_of_a_frozen_session_changes_its_state_and_stays_frozen`.

What TDD gives, a test that can fail for the behavioral reason, is present. Only the order of the commits is wrong.

**The fix is a rewrite that buys nothing durable.** The branch is pushed, and PR #717 (branch issue-715) is open. A red-first order needs the green commit split into one step for each rule. Those steps are code that never existed, written only to make the history read red first. The rewrite then needs a force push, and only Tim can run one. The merge gate then asks for a fresh review of the whole branch. Against that: this repository squash-merges each PR with an explicit `--subject` and `--body`, thus no commit of this branch reaches `main`.

**The boundary.** This decision settles the order of `b3a0abf8` and `9690e16e` on branch `issue-715` only. It does not settle a missing test, or a test that nobody showed can fail. It does not permit a green commit that implements more than its red test asks for, as a habit.

**The pattern.** This is the third branch with this shape. The first two are `R-20261028T194028Z-N1` (branch issue-613) and `R-20261116T114306Z-N1` (branch issue-697). Those records point the repair at the brief of the green step, in the skills of the dotfiles repository, and not at a branch.
