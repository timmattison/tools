## `src/workit/src/main.rs` — a refused run does not state the total of the skipped entries

**Settled** 2026-11-25 (branch workit, finding R-20261125T043207Z#N4)

The finding is accurate. The README entry of `workit` says that the run states
the number skipped at the end. The refusal of duplicate package names and the
refusal of `member_paths` return before `skipped.state_total()`. Thus a refused
run that skipped entries prints a `Warning` line for each entry, but it does not
print the total.

It is not fixed, because the fix costs more than the defect:

- **The reader sees each skip.** Each skipped entry gets its own line on
  stderr. Only the line that counts them is missing.
- **The total guards a different risk.** The comment above
  `skipped.state_total()` says that a run that skipped something must not read
  like a run that used the whole tree. A refused run writes nothing and exits
  non-zero, thus nobody takes it for a run that used the whole tree.
- **The cost is a new review cycle.** This round of the review loop is
  record-only. A fix changes two return paths and adds tests, or it changes the
  README sentence. A review must read that new code or text, and a fresh review
  can find a new nit in it. Tim chose to settle each nit with a record
  (decision H-742-2 on issue #742).

**The boundary.** This decision settles the two refusals that the finding
names. A run that exits 0, skipped an entry, and does not state the total is a
new finding.
