## `.husky/pre-commit` — the header names one exception to the Rust trigger, and the hook has two

**Settled** 2026-11-24 (branch msgs, finding R-20261124T221923Z#N7)

The finding is accurate. The header of `.husky/pre-commit` says that the gates
run only for a staged Rust change, and that the tool-index block is "the one
deliberate exception". The msgs frontend block at the end of the hook is a
second exception. It runs `tsc --noEmit` and `vitest run` for a commit that
stages a file under `src/msgs/frontend/` or `src/msgs/scripts/`, with no Rust
file.

**The fix is prose, and it costs more than the defect.** The frontend block has
its own comment, which says what it runs and when. The hook does what the two
comments say together. The false header can mislead a reader of the hook, but
it does not change what the hook runs. This round of the review loop is
record-only, and a change of the header starts one more review cycle.

**The boundary.** This record settles the header sentence only. A gate of the
hook that runs for a commit that its own comment excludes reopens this record.
A gate that does not run for a commit that its comment names also reopens it.
