## `src/portcul/src/process.rs` — the non-unix error of `kill_process` keeps the PID

**Settled** 2026-11-24 (branch portcullis, finding R-20261124T195953Z#N2)

The finding is accurate. On a target that is not unix, `kill_process` gives
`cannot send SIGTERM to PID {pid}: killing processes is not supported on this
platform`. Commit `fa209965` put the PID into that text. Both callers put the
PID before the error: `kill_targets` writes `Failed to kill PID {}: {e}`, and
`confirm_kill` writes `Failed to kill PID {pid}: {e}`. A user on such a target
thus reads the PID two times in one line.

**The fix costs more than the defect.** This round of the review loop is
record-only, and a change of the code starts a new fix round. The text repeats
a correct value, and it gives no wrong information. Clippy on macOS does not
compile a `#[cfg(not(unix))]` block, thus a review of the fix needs a build for
a different target. On such a target, each kill fails with this message.

**The boundary.** This record settles the repeat of the PID in the non-unix
message only. A message that gives a wrong PID is a new finding. A non-unix
build with a warning is a new finding.
