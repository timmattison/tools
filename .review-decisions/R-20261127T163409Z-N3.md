## `src/nle/src/timeline/tests.rs` `a_mostly_vertical_wheel_with_no_modifier_does_nothing` — the Shift assertion stays in this test

**Settled** 2026-11-27 (branch issue-150, finding R-20261127T163409Z#N3)

The finding is accurate. The name of the test says "with no modifier does
nothing", but its last assertion sets Shift on the delta `(1.0, 40.0)` and
expects `Pan(40.0)`. The test `a_vertical_wheel_with_shift_scrolls` covers only
a delta with `x = 0`. Thus a failure of the Shift rule for a mixed delta shows
under a name that says "no modifier".

The assertion is correct, and it is a contrast with the two assertions above
it: the same delta does nothing with no modifier, and scrolls with Shift. A
failure of the Shift rule still fails the suite. The message of `assert_eq!`
gives the line, the expected value, and the value that `wheel_action` gave. The
person who reads that failure finds the cause in one step.

**The fix costs more than the defect.** The fix moves one assertion into a new
test or into `a_vertical_wheel_with_shift_scrolls`. That change is new test
code that a fresh review must read. The loop then starts one more fix round
for the name of a test whose assertions are all correct.

**The boundary.** This record settles only the place of the Shift assertion in
`a_mostly_vertical_wheel_with_no_modifier_does_nothing`. These occurrences
reopen it:

- a change that removes the Shift assertion for a mixed delta, so that no test
  covers the Shift rule with `x != 0`
- a change that makes an assertion of the test expect a wrong value
- a second assertion with a modifier that the name of the test does not give
