## `src/nle/src/pipeline.rs` `run_with_end` — the `# Errors` section does not name the errors of a screen step

**Settled** 2026-11-28 (branch issue-164, finding R-20261128T051847Z#N2)

The finding is accurate. The screen step of `run_with_end` refuses three
cases with `NleError::RenderError`: no size of the screen, an answered size
with no cells, and a changed size on a range. The `# Errors` section of
`run_with_end` names the span errors and the cut errors, but not these three.
The summary of the same doc says that a screen filter fails when `size` is
`None`, and the `# Errors` section of the public `run` names the screen case.
Nothing in the section is false.

The fix costs more than the defect. The fix is prose in the doc of a private
function. The branch is in the record-only round of the review loop. A
rewrite is new text that a fresh review reads, and a nit in it starts one more
fix round. The code and its error messages at the head of the branch state
each refusal.

The boundary: this record settles only the omission of the three screen
errors from the `# Errors` section of `run_with_end`. A statement in that
section that is false at the head of the branch is a new finding. An error
path that a later change adds, and that the section does not name, is a new
finding too.
