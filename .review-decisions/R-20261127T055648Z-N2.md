## `src/wdid/tests/shell-definitions.rs` `real_shell` and `zsh_without_zdotdir` — the ZSH variables of the test process stay

**Settled** 2026-11-27 (branch issue-727, finding R-20261127T055648Z#N2)

The finding is accurate. `real_shell` and `zsh_without_zdotdir` start the
child shell from `childenv::fixture_command`, which sheds only the `GIT_`
prefix. Thus the `ZSH` and `ZSH_CUSTOM` of the test process reach the child
zsh, and the script of `src/wdid/src/shell.rs` prints both places. Since
ea66272, `Setup::command` in `src/wdid/tests/cli.rs` sheds each variable whose
name starts with `ZSH` for the same reason.

No test result changes today. Each test of this file that judges the origin
`mine` uses `omz_home`, whose `OMZ_ZSHRC` sets `ZSH` and `ZSH_CUSTOM` in the
child, and that value replaces the inherited value. The bash script prints no
`ZSH`. Thus the gap is latent. It becomes a failure only when a later zsh test
of this file reads the `ZSH` places without `OMZ_ZSHRC`.

The fix costs more than the defect. The branch is in a record-only round of
its review loop. A shared helper and two changed call sites are new code that
a fresh review reads, and that review can find a new nit in it. That starts a
new fix round for a gap that no current test can show.

The boundary: this decision settles `real_shell` and `zsh_without_zdotdir` as
they are at `src/wdid/tests/shell-definitions.rs:506-513` and `:1426`. A new
test of this file that reads the `ZSH` places without `OMZ_ZSHRC` reopens this
decision, and that test sheds the `ZSH` prefix in the same commit. A test that
fails because of an inherited `ZSH` variable reopens it too.
