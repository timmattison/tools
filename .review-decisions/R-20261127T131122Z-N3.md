## `src/ufa/src/config.rs` — no test holds the removal of the comment lines above a removed field

**Settled** 2026-11-27 (branch ufa, finding R-20261127T131122Z#N3)

The finding is correct. The doc of `written_over` and `src/ufa/README.md` say
that a save removes the comment lines directly above a removed field, and the
comment lines at the top of the file when that field is the first key.
`a_save_removes_a_field_that_the_edit_cleared` clears `op_path`, but it reads
only the parsed fields. No test reads the comment above `op_path`, and no test
clears the first key.

The sentence describes a loss, not a promise to the user: it tells the user
which of their comments a save does not keep. The behavior comes from the way
`toml_edit` keeps the decor of a key. If a later `toml_edit` keeps those lines,
the user loses less text than the doc says, and no data is lost. The tests of
this file already hold the comments and the unknown keys that a save must keep.
A fix adds two test cases, and it starts one more review cycle.

**The boundary.** A save that removes a comment or a key that the doc says it
keeps is a new occurrence, and so is a save that removes a field that `Config`
still holds. The missing test of the comment lines that leave with a removed
field is settled.
