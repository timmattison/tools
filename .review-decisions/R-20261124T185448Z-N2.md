## `CLAUDE.md` — the Specs and Plans section names one skip of the `doc_placement` walk, not four

**Settled** 2026-11-24 (branch 191, finding R-20261124T185448Z#N2)

The finding is accurate. The "Guards Enforcing This" bullet of the Specs and
Plans section names one skip of the walk of `repo_guards::doc_placement`: a
directory that holds a `.git` entry. The walk also never enters `.git`,
`target`, or `node_modules`, at any depth (`SKIPPED_DIRS` in
`src/repo-guards/src/doc_placement.rs`). Thus `node_modules/pkg/specs/x.md`
passes `cargo test`, but the words of `CLAUDE.md` say that it fails. The skips
are correct. Only the text that describes the guard is incomplete.

**The cost is a new review cycle.** This round of the review loop is
record-only. A change to `CLAUDE.md` is a new document change that a review
must read, and a fresh review can find a new nit in it. Then a new fix round
starts, and the loop does not end clean. The three skipped names hold output
of tools, not documents that a person writes, so no reader of `CLAUDE.md`
puts a spec there. `SKIPPED_DIRS` states each skip with its reason, next to
the code that applies it.

**The boundary.** This decision settles only the list of skips in that
bullet. A skip in the code that hides a directory where a person can write a
spec, or a statement in `CLAUDE.md` that names a skip the code does not make,
is a new finding.
