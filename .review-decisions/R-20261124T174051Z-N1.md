## `faulte` module docs — `stream` starts the `top` child, not only `machine::macos`

**Settled** 2026-11-24 (branch issue-669, finding R-20261124T174051Z#N1)

The finding is accurate. The doc of `stream` in `src/faulte/src/lib.rs`
(lines 42-43) says that the module holds no clock and no process.
`lib.rs:52`, `machine.rs:10-11` and `machine/macos.rs:1-2` say that
`machine::macos` is the one part of `faulte` that runs a command. But
`TopStream::spawn` in `stream.rs` starts `top` through `childenv::command`, and
the reader thread of `TopStream` stamps each read with the clock. Only
`StreamParser` holds no clock and no process.

The boundary of the code is correct. The one production caller of
`TopStream::spawn` is `machine::macos` (`macos.rs:173`), thus the real `top`
starts only behind the `Machine` trait. The tests of `TopStream` start
`/bin/sh`, not `top`. The module doc of `stream.rs` (lines 11-14) states the
correct split: `TopStream` adds the child process and the clock.

The fix is doc text in three files. The round that found it was record-only.
A change of doc text is new text that the next review must read, and that
review starts one more round. That round costs more than the defect, because
no code reads these four sentences, and the doc of the module that holds the
process states the split correctly.

The boundary: this settles the wording of these four doc sites on branch
issue-669. A production caller of `TopStream::spawn` outside
`machine::macos`, or a test that starts the real `top` through it, is a new
finding. A new false claim in a later change of these docs is a new finding
too.
