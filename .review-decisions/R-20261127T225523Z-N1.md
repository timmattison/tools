## `README.md` `nle` section — "which zsh and bash turn on by default" names no version

**Settled** 2026-11-27 (branch issue-161, finding R-20261127T225523Z#N1)

The finding is correct. Bash turns on bracketed paste mode by default only from
bash 5.1 (readline 8.1). The bash of macOS, `/bin/bash` 3.2.57, has no
`enable-bracketed-paste` variable, and `bind -v` in it shows no such variable.
Bash 4.4 and 5.0 have the mode off by default. Thus a reader who records
`/bin/bash` and pastes `ls` CR `pwd` CR sees `ls Enter pwd Enter`, where the
sentence says `Paste`. The finding R-20261127T224006Z#I1 named the versions,
and the fix 8705c1b6 dropped them.

The defect is one loose clause of prose. The sentence before it tells the
reader what such a paste shows: "A paste gives such an event in a shell with
no bracketed paste mode." Thus a reader who sees `ls Enter pwd Enter` from
`/bin/bash` reads the behavior that the README describes for a shell without
the mode. The default shell of macOS is zsh, and zsh 5.9 of macOS has the mode
on. No code, no test, and no project file depends on the clause.

The fix costs more than the defect. A change of `README.md` is new text that
a fresh review must read, and the loop then starts one more fix round for one
clause. This round of the review loop is record-only.

Boundary: this settles the missing versions in that clause. A sentence that
says a shell has the mode on when no version of it has the mode on is a new
finding. A sentence that says the HUD shows `Paste` for a paste in a shell
without the mode is a new finding too.
