## `scripts/plugin-checks.sh` and `scripts/rust-checks.sh` — `cd "$(dirname "$0")/.."` does not resolve a symbolic link

**Settled** 2026-11-25 (branch github-actions-ci, finding R-20261125T164351Z#N1)

The finding is accurate. If a person starts either script through a symbolic
link in a different directory, `dirname "$0"` gives the directory of the link.
The `cd` then goes to the wrong directory, and the `.` of
`scripts/without-git-environment.sh` fails. `~/.claude/LOCATION-INDEPENDENT-SCRIPTS.md`
names this trap. `scripts/rust-checks.sh` has the same line on `main`, and
`scripts/plugin-checks.sh` copies it.

**The cost of the fix is a new review cycle.** This round of the review loop is
record-only. The fix changes two scripts, and it adds `realpath` to the `PATH`
links of the hook test `plugin_block_without_claude_fails_the_commit`, because
the script then runs `realpath` before its check for the CLI. A fresh review
can find a new nit in that change. Then a new fix round starts, and the loop
does not end clean.

**The failure is loud, not silent.** No caller starts either script through a
link. The pre-commit hook and CI each start the script by its path in the
repository. If a person makes such a link, the `.` of the helper fails, and
`set -euo pipefail` stops the script before it runs a check.

**The boundary.** This decision settles only the `cd` line of these two
scripts. A caller that starts either script through a symbolic link, or a
start through a link that runs the checks in the wrong directory and does not
fail, is a new finding.
