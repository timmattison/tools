## `README.md` — the `wl` entry keeps its sentence about the privilege note with no platform in it

**Settled** 2026-11-24 (branch wl, finding R-20261124T163502Z#N1)

The finding is accurate. The README entry of `wl` says: "When a run without
root names no process, `wl` writes a note about this limit to standard error,
unless the port is free." The note is Unix-only. On a platform that is not
Unix, `non_root_privilege_note` gives `None` and `current_euid` gives 0
(`src/wl/src/main.rs`, since `2b0b395d`). Thus `wl` on Windows never writes the
note. The settled record `R-20261124T160606Z-I2.md` says that a new false
statement about Windows in the docs is a new finding. This record is the
decision about that finding.

**The fix is a change of text, and it costs more than the defect.** The same
README bullet starts with "Without root", and root is a Unix concept. A user on
Windows does not get a false answer about the port: when `listeners` names no
process, `wl` prints that it reads the list of listening sockets on macOS and
Linux only. No machine of this project runs Windows: the development machine is
macOS, and CI is Linux. A change of one clause of the README starts a new
review cycle on this branch for no change of behavior.

**The boundary.** This record settles the sentence about the privilege note in
the README entry of `wl` only. A different false statement about Windows in the
output or in the docs is still a new finding, as `R-20261124T160606Z-I2.md`
says. A change that makes `wl` write the note on Windows, or a Windows reader of
the socket table, reopens this record.
