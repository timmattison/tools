## `src/nle/src/pipeline.rs` `StepTimes` and `move_chapter` — the docs omit the end pair of a cut step

**Settled** 2026-11-27 (branch issue-164, finding R-20261127T232322Z#N1)

The finding is accurate. The docs of `StepTimes::seen` and
`StepTimes::answered` say that for a cut filter the lists are the pairs of
`Cut`. The doc of `move_chapter` says that for a cut filter the pairs are the
kept events and the first event of each removed run. The cut branch of `apply`
also sets `span_end` to `Some((length, cut.length))`. The code after it pushes
that pair onto both lists, as for a span filter. Thus each list holds one more
entry than the docs say. Commit `3e53de06` wrote both the code and the docs.

The behavior is correct. The test
`a_chapter_keeps_its_place_when_the_cut_runs_to_the_end_of_the_range` in
`src/nle/src/filters/backspace/tests.rs` holds the end pair. A change that
removes the pair fails the suite. The push of the end pair is one `if let` on
`span_end`, a few lines below the cut branch, thus a reader of the code sees
the pair.

**The fix costs more than the defect.** The fix is a change of doc text in
three places. It changes no behavior, and a fresh review reads the changed
docs. The loop then starts one more fix round for docs of a private type whose
code and test are correct.

**The boundary.** This record settles only the words of the three docs. These
occurrences reopen it:

- a change that removes the end pair from the cut step, or that pushes it two
  times
- a chapter after the last kept event of a cut region that does not keep its
  place
- a change that makes `StepTimes` or `move_chapter` public, so that a reader
  outside the module gets only the docs
