## `src/ha/src/board.rs` `merge_group_run` — a skipped run of a merge group stays a candidate for Enter

**Settled** 2026-11-27 (branch issue-827, finding R-20261128T023838Z#N1)

The finding is accurate. `merge_group_run` takes each run in `self.runs` of
the repository whose `head_sha` is the merge group commit and whose branch
starts with `gh-readonly-queue/`. That set holds runs in the state `Skipped`
and `Other`. `sections` shows only active runs and finished runs
(`RunState::is_active`, `RunState::is_finished`), thus such a run has no row.
When no run of the merge group failed or is active, step 3 of the order picks
the run that GitHub created last. A skipped run can be that run, and then
Enter opens a skipped run in place of the passed run.

The code obeys the rule of issue #827: "the runs of an entry are the runs that
the board holds". The README text "the runs on the board" says the same thing
in other words, and it does not say that the run must have a row.

**The fix costs more than the defect.** The window is short. While a run of
the merge group is active, step 2 picks that run, and a skipped run never
wins. When each required run passed, GitHub merges the entry, and the next
poll of the queue removes its row. Thus the skipped run can win only between
the last pass and that poll. In that window, Enter still opens a page of the
merge group of the entry, not the wrong pull request. The fix is a change of
the filter and a new board test. That change is new code that a review must
read, and this round of the review loop is record-only.

**The boundary.** This record settles only a skipped run or an `Other` run
that wins step 3 or step 4 after each other run of the merge group finished.
These occurrences reopen it:

- a change that keeps an entry in the queue after each of its runs passed,
  for example a wait for other entries of a batch, so that the window is long
- a change of the order of `merge_group_run` that puts a skipped run or an
  `Other` run before a passed run, an active run, or a failed run
- a run in the state `Other` that GitHub reports as `action_required`, when a
  user reports that Enter opened such a run and not the run that waits
- a report from a user that Enter opened a skipped run of a merge group
