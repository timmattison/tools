## `src/ufa/src/site_manager/client.rs` — `get_hosts` has no ceiling on pages or hosts

**Settled** 2026-11-25 (branch ufa, finding R-20261125T160218Z#N3)

The finding is accurate, and it reports the same gap as
R-20261125T155649Z#N1. `get_hosts` stops only on a page with no token, or on
a token that it sent before. A server that gives a new token on each page
makes the walk run with no end, and `hosts` and `sent_tokens` grow with no
limit. The controller walk has a ceiling (`MAX_COLLECTION_ITEMS` in
`src/ufa/src/pagination.rs`), and the cloud walk has none.

**The cost is a new review cycle.** This round of the review loop is
record-only. A ceiling is new code, a new error, and a new test, and a fresh
review can find a new nit in each. The risk is low, and the finding says so
too. The client names `api.ui.com` and no other host, and it never waives the
certificate check. Each page answer is still capped at `MAX_RESPONSE_BYTES`.
`R-20261125T155649Z-N1.md` gives the full reason.

**The boundary.** The boundary of `R-20261125T155649Z-N1.md` applies. A
change that lets the Site Manager client reach a different host, or that
waives its certificate check, reopens this decision.
