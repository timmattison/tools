## Commit order on a pushed branch — two behaviors of the cancel box of `ha` got their tests after their green commits

**Settled** 2026-10-19 (branch issue-578, finding R-20261018T235403Z#N1)

The review found that two green commits added behaviors that their red commits
did not test:

- `b3d8f53a` added the rule that every key but `y` and Ctrl-C closes the box
  and does nothing more, in `handle_key` in `src/ha/src/app.rs`. Its red
  commit `93bc43dd` asks only that `c` and then `y` cancels. The tests
  `every_key_but_y_closes_the_box_and_cancels_nothing` and
  `enter_with_the_box_open_opens_nothing_and_down_does_not_move_the_highlight`
  came after it, in `9d07b2a0`.
- `e4939f9f` added the `Err` arm in `apply_updates`, which posts
  `could not cancel run {id}: {error}`. Its red commit `3c6206bb` tests only
  the `Ok` outcome. The test `a_refused_cancel_posts_the_run_and_the_error`
  came after it, in `4bd6cf98`.

The TDD rule in `CLAUDE.md` asks for the red commit first. The finding is
accurate.

It is not fixed, because the defect is the order of the commits and nothing
else.

**The coverage is real.** The review did a mutation check on `0a3ee869`, the
last commit of the review, with `cargo test -p ha --lib app::tests`:

- When every other key falls through to the normal match, two tests fail:
  `every_key_but_y_closes_the_box_and_cancels_nothing` and
  `enter_with_the_box_open_opens_nothing_and_down_does_not_move_the_highlight`.
- When the `Err` arm posts nothing, one test fails:
  `a_refused_cancel_posts_the_run_and_the_error`.

What TDD gives, a test that can fail for the behavioral reason, is present.
Only the order of the commits is wrong.

**The one fix is a rewrite of a pushed branch, and it buys nothing durable.**
To fix the order, each test must move into a red commit before its green
commit. That gives a new SHA to each commit from `b3d8f53a` to `0a3ee869`,
which is 11 commits. `origin/issue-578` holds those commits, thus the rewrite
needs a force push. `block-dangerous-git.ts` refuses a force push with no
override, thus only Tim can run it. The review `R-20261018T235403Z` ends on
`0a3ee869`. After the rewrite, `pr-merge-gate.ts` finds that the commit is not
on the branch, calls the review `rewritten`, and refuses the merge until a
fresh review of the whole branch. Against that cost: this repository
squash-merges every PR with an explicit `--subject` and `--body`, thus no
commit of this branch reaches `main`.

This decision applies the reasons of `R-20261017T222526Z-N1`,
`R-20261018T041353Z-N1`, and `R-20261018T170445Z-N1` to this branch.

**The process goes to the skills.** This branch is the fourth with this shape.
In each of the four branches, the green commit added a rule that the red test
did not ask for: here, an arm for the other keys and an `Err` arm. On
2026-10-19, Tim decided to change the brief of each green step, in the TDD
skills of his dotfiles, and not in this repository. The change is
timmattison/dotfiles issue #22.

**The boundary.** This decision settles the order of `b3d8f53a` and
`9d07b2a0`, and of `e4939f9f` and `4bd6cf98`, on the branch `issue-578` only,
where the tests exist and a mutation shows that each can fail. It does not
settle a missing test, or a test that nobody showed can fail. It does not
change the rule of `R-20260820T153740Z-N2` for an unpushed branch where no
review names the commits that a rebase moves. It does not permit
implementation first as a habit.
