## `src/cdva/tests/cli.rs` `LONG_NAME` — the constant stays beside the one test that reads it

**Settled** 2026-11-28 (branch issue-850, finding R-20261128T143910Z#N1)

The finding is accurate. Each other top-level constant of
`src/cdva/tests/cli.rs` is in the block at the top of the file, from
`GIT_PREFIX` to `HELP_FLAG_INDENT`. `LONG_NAME` is the only constant after
that block. It is directly above
`the_help_gives_the_long_name_of_the_tool`, which is the only test that reads
it. Thus a reader who looks for the constants at the top of the file does not
find it there.

**The fix costs more than the defect.** The defect is the position of one
constant. The behavior of the test does not change, and the constant is on
the screen with the only test that uses it. A move of the constant is a change
to a test file. That change is new code that a review must read, and a fresh
review can find a new nit in it. Then a new fix round starts. This round of
the review loop is record-only.

**The boundary.** This record settles only the position of `LONG_NAME` while
one test reads it. These occurrences reopen it:

- a second test, or a helper, that reads `LONG_NAME`
- a different constant that a change puts between the test functions of
  `src/cdva/tests/cli.rs`
- a change of the value of `LONG_NAME` that makes it differ from the long name
  that `src/cdva/src/main.rs` gives
