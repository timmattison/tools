## `README.md` backspace removal filter — the README does not name the option check and the empty-terminal check

**Settled** 2026-11-27 (branch issue-152, finding R-20261127T125059Z#N2)

The finding is accurate. "The checks" in the module doc of
`src/nle/src/filters/backspace.rs` states three failures of the render: a key
in the options, a terminal with no column or no row, and a terminal with more
than `MAX_CELLS` cells. The README section of the backspace removal filter
names only the cell limit. Both texts are from this branch (a0d11740e,
b024764cb).

The two docs do not disagree. The README says "The filter takes no option",
and the project file example gives `"options": {}`. A reader who obeys the
README does not hit the option check. A recording with no column or no row
draws nothing, so a reader does not apply the filter to one. The render error
names the cause in each case, so a reader who hits a check learns its rule from
the message.

**The fix costs more than the defect.** The fix is two sentences of README
prose. It changes no behavior, and a new review must read it. A new fix round
then starts for text that the module doc and the error messages already give.

**The boundary.** This record settles only the omission of the option check
and of the empty-terminal check from the README section of the backspace
removal filter. These occurrences reopen it:

- a change that makes the README say something false about a check, for
  example that the filter takes an option
- a change that makes a check fail with a message that does not name its cause
- a new check of the filter that the README does not name
