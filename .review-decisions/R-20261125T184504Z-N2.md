## `src/msgs/frontend/src/search.ts`, `export.ts` — two rejections show without `messageOf`

**Settled** 2026-11-25 (branch msgs, finding R-20261125T184504Z#N2)

The finding is accurate. `runSearch` in `search.ts` shows `String(e)`, and
`performExport` in `export.ts` shows `` `Export failed: ${e}` ``. `main.ts`,
`messages.ts`, and a different line of `search.ts` use `messageOf(e)` from
`utils.ts`. The text is different only when the rejection is an `Error`
object: then `String` adds the prefix `Error: `.

The usual rejection is a string. Each Tauri command of msgs returns
`MsgsError`, and its `Serialize` implementation in `src/msgs/src/error.rs`
writes `self.to_string()`. For a string, `String(e)` and `messageOf(e)` give
the same text. An `Error` object comes only from a failure of the IPC itself,
and the prefix `Error: ` is then the only difference.

The cost of a fix: change two lines, and add a test for each line that rejects
with an `Error` object. That change is new code for one more review round, and
it changes only a prefix in a rare error message.

The boundary: a rejection of a Tauri command that shows through `String(e)` or
a template literal is this decision. These changes reopen it:

- A command of msgs rejects with a value that is not a string, for example an
  object.
- Code reads the text of the error, or a test compares it.
- A third site shows a rejection without `messageOf`.
