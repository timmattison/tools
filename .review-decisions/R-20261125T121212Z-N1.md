## `scripts/rust-checks.sh` — the announcement of the test step names `CLICOLOR_FORCE=1` and not `COLORTERM=truecolor`

**Settled** 2026-11-25 (branch github-actions-ci, finding R-20261125T121212Z#N1)

The finding is accurate. Line 100 of `scripts/rust-checks.sh` announces the
test step as `cargo test --locked --no-fail-fast --workspace
(CLICOLOR_FORCE=1)`. The command at line 130 also sets `COLORTERM=truecolor`,
and commit 125894ec added that pin with no change to the announcement. A
person who copies the announced variables to run a test by hand gets no
`COLORTERM` pin.

**The cost is a new review cycle.** This round of the review loop is
record-only. A change to the announcement is a new change that a review must
read, and a fresh review can find a new nit in it. Then a new fix round
starts, and the loop does not end clean. The defect is in a log line only.
The command that the hook and CI run sets both variables, and the comment at
lines 123 thru 129 of the script names `COLORTERM=truecolor` and gives its
reason. The section "24-bit colors read `COLORTERM`" of `CLAUDE.md` gives the
command to run such a test by hand.

**The boundary.** This decision settles only the text of the announcement. A
test command in `scripts/rust-checks.sh` that does not set
`COLORTERM=truecolor`, or a change to the announcement that breaks the prefix
`TEST_ANNOUNCEMENT` of `src/repo-guards/tests/pre_commit_hook.rs`, is a new
finding.
