## PR #754 body, "How to try it" — the line count after the watch command stays as it is in this review loop

**Settled** 2026-11-24 (branch faulte-check, finding R-20261124T171347Z#N1)

The finding is accurate. The section "How to try it" in the body of PR #754
gives the command
`cargo run --release --bin faulte -- check --watch --interval 2s | head -3`.
The sentence after the output says that the watch printed two lines into
`head -2`. The command and the sentence name different counts of lines.

**The fix costs more than the defect in this round.** This round of the review
loop is record-only. A change to the PR body is a change that the next review
reads, and the review of the PR body found this nit. Thus a change starts one
more review cycle for one wrong digit. The defect is in the PR body only. No
file of the repository holds the text, and no code, test, or help text is wrong.
The PR body is not the body of the squash commit, because the merge step writes
its own subject and body.

**The boundary.** This decision settles the line count of the `--watch` example
in the body of PR #754 only. It does not settle a wrong count, a wrong flag, or
a wrong output in a file of the repository, for example `README.md`, `TLDR.md`,
or the help text of `faulte`. Such a defect is a new finding. A change to the PR
body for a different reason can correct the digit at the same time.
