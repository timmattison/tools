## `src/repo-guards/tests/pre_commit_hook.rs` — `the pipe is false` in the doc of `tool_index_in_a_large_commit_runs_the_index_guard` stays

**Settled** 2026-11-26 (branch issue-760, finding R-20261126T190353Z#N2)

The finding is accurate. The doc of
`tool_index_in_a_large_commit_runs_the_index_guard` says `the pipe is false`.
The hook comment at `.husky/pre-commit` says `the pipeline is then false`,
because the pipeline has the exit status. The two texts use two terms for one
concept.

No reader gets a wrong fact. The doc and the hook comment describe the same
failure, and the test asserts the behavior, not the words.

The cost of a fix: a change of a doc comment in a test file. That change is new
code, thus it starts one more review round, which can find a new nit in the new
text.

The boundary: a report about the term `pipe` against `pipeline` in this doc is
this decision. These changes reopen it:

- A change that makes the doc state a wrong fact about which command sets the
  exit status.
- A change of the hook comment that makes the two texts describe different
  failures.
