## `src/wdid/tests/shell-definitions.rs` `no_error_message_names_a_flag_of_one_report` — the hint stays out of `ShellError`

**Settled** 2026-11-26 (branch issue-725, finding R-20261126T230350Z#I2)

The finding is accurate. Acceptance criterion 2 of issue #725 says that the
tests of the tools report pass without change. On `main` (e767d2608),
`every_error_message_ends_with_the_no_shell_hint` held the `--no-shell` hint on
each of the 6 `ShellError` texts. Commit 10eecb465 replaced that test with a
test that holds each text with no flag in it. The old test fails on this
branch.

The behavior that the criterion protects did not change. The tools report wraps
each `ShellError` in `Error::Shell`, whose `#[error]` text adds the hint after
the text of the variant (`src/wdid/src/main.rs:153`). Thus the tools report
prints the same 6 texts as on `main`. The CLI test
`a_shell_that_wdid_cannot_read_stops_the_run_and_names_no_shell`
(`src/wdid/tests/cli.rs`) holds the whole stderr of one variant byte for byte.

The fix costs more than the defect. To keep the old test unchanged, the hint
must go back into each `ShellError` text. But `wdid defs` also prints a
`ShellError`, and `defs` has no `--no-shell` (`wdid --no-shell defs` is a usage
error). Commit c28952a00 removed the hint from `ShellError` because of that
defect. The fix thus brings back one of two costs:

- `wdid defs` again tells a person to use a flag that it does not have, or
- `Error::DefsShell` removes the hint from a text that the shared reader made,
  which is a second copy of the 6 texts or a cut of a suffix string.

Each cost puts the flag of one report into the reader that two reports share.

The boundary: this settles the change of that one unit test of `ShellError`. A
change to the text that the tools report prints, or a test of the tools report
that this branch changes, is a new finding.
