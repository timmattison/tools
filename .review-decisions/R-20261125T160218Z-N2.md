## `src/ufa/src/discovery.rs` — the discovery probe reads the whole body of an answer

**Settled** 2026-11-25 (branch ufa, finding R-20261125T160218Z#N2)

The finding is accurate. `probe` reads the body with `response.text()`, with
no cap on its size. `http.rs` caps each API answer at `MAX_RESPONSE_BYTES`
with a counted read, but the probe does not use that read. Discovery probes
`unifi`, `unifi.local`, each mDNS address, and each URL that the user types,
eight at a time. A host on the LAN that streams data can thus fill memory
until the timeout stops the probe.

**The cost is a new review cycle.** This round of the review loop is
record-only. A capped read in the probe is new code and a new test, and a
fresh review can find a new nit in each. Then a new fix round starts, and the
loop does not end clean. The damage has a limit:

- `PROBE_TIMEOUT` (3 s) is the `reqwest` timeout of the whole request, and
  that timeout includes the read of the body. Thus each probe stops after
  3 s.
- The process is a short CLI run that the user started. A hostile host on the
  LAN can make that one run use memory or fail, and nothing more.
- The probe sends no API key, thus a hostile host gets no secret from it.

**The boundary.** This decision settles only the size of the body that the
discovery probe reads under the 3 s timeout of the whole request. A change
that removes or increases that timeout, or that sends a credential with the
probe, reopens it. A different read of an untrusted body with no cap and no
timeout is a new finding.
