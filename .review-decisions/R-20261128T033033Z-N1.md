## `src/nle/src/pipeline/tests.rs` — the test of the start size of the first screen filter keeps the name of the old rule

**Settled** 2026-11-28 (branch issue-157, finding R-20261128T033033Z#N1)

The finding is accurate. The merge 0e924487 changed rule 1 of `ScreenFilterFn`
(`src/nle/src/pipeline.rs:202-205`): the first step gets the padded size of the
clips, not the header size of the clip that starts first. The test
`the_first_screen_filter_sees_the_header_size_of_the_first_clip`
(`src/nle/src/pipeline/tests.rs:1343`) keeps the name of the old rule. It
renders `one_clip_project`, where both rules give 100x30. The comment at
`src/nle/src/pipeline/tests.rs:1528` says "the header size stays" for the same
value.

No output is wrong, and the coverage gap is smaller than the finding says. A
screen filter and a span filter read one variable, `size` in
`FilterRegistry::apply` (`src/nle/src/pipeline.rs:389`). `FilterRegistry::render`
starts that variable at `Some(spliced.size)`, the padded size
(`src/nle/src/pipeline.rs:595-603`).
`render_gives_a_span_filter_the_padded_size_of_the_clips` renders clips of
different sizes and expects 132x43. Thus a return to the header size of the
first clip at that start fails that test. Only a new path for screen filters
alone can pass, and no such path exists.

**The fix costs more than the defect.** The fix is a rename, a new fixture of
clips of different sizes, and a changed comment. This round of the review loop
is record-only. A changed test is new code that a review must read, and a fresh
review can find a new nit in it. Then a new fix round starts, and the loop does
not end clean.

**The boundary.** This record settles only the name of that test and the words
of the comment at line 1528. These occurrences reopen it:

- a screen filter that reads its start size from a variable other than the one
  that a span filter reads
- a change of the start value of `size` in `FilterRegistry::render`
- a removal or a weaker assertion of
  `render_gives_a_span_filter_the_padded_size_of_the_clips`
