## `src/ha/src/estimate.rs` — the tails of a passed past run are not corrected for a partial re-run

**Settled** 2026-11-27 (branch issue-749, finding R-20261127T140125Z#N1)

The review found that a partial re-run ("Re-run failed jobs") of a past passed
run makes each tail of that run too long. The jobs endpoint gives the latest
execution of each job. A job that did not run again keeps the times of its first
execution. The end of the run is then the end of the re-run job, and the tail of
a job from the first execution holds the wait of the person before the re-run.

The finding is accurate. `Estimates::new` does not correct for this case.

**Tim decided on 2026-11-27 to change no code for this finding.** The value is
an estimate, and a partial re-run of a past passed run is rare. The fix is a
filter on the attempt of each job, for example the signal that `run_end` in
`board.rs` uses for jobs that started before `run.started_at`. That fix costs
more than the error.

**The boundary.** This decision covers only the tails from a past run after a
partial re-run. A different rule of `Estimates::new` that a re-run makes wrong,
for example the means of the jobs, is a new finding. A request from Tim for the
filter reopens this decision.
