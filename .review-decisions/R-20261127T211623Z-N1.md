## `src/portplz-core/README.md` usage example — the comments show port 51877, but the stated input gives 11375

**Settled** 2026-11-27 (branch issue-828, finding R-20261127T211623Z#N1)

The finding is accurate. `derive()` hashes `501\nfoo\nmain` for repo `foo` on
branch `main` for uid 501. The SHA-256 of that string starts with `2c6f`, and
`unprivileged_port_from_string` thus gives 11375. The two comments of the usage
example say 51877. The README copied that number from the doc comment of
`Derivation::describe` (`src/portplz-core/src/lib.rs`), which is older than
this branch and uses the number as an illustration.

The defect is small. The example reads `current_dir()` and the live user, thus
no reader gets the port of the comment from a real run. The comment shows the
form of the output, and that form is correct. No code, test, or tool reads the
number.

**The fix costs more than the defect in this round.** The fix is a change of
two comments in the README, and of the doc comment in `lib.rs` for the same
number. That change is new text that a review reads, and this round of the
review loop is record-only. A fresh review of that text can find a new nit,
and a new fix round then starts.

**The boundary.** This record settles only the number 51877 in the comments of
the usage example of `src/portplz-core/README.md` and in the doc comment of
`Derivation::describe`. Each of these occurrences reopens it:

- a test, a golden file, or a tool reads one of these numbers as the port of
  that input
- a different document or example gives a port as the real output of a stated
  input, and the port is wrong
- the form of the output in the example (`Port N for repo 'x' on branch 'y'
  (uid U)`) no longer agrees with `Derivation::describe`
