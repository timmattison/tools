## `termstate::TerminalState::set_extended_color` — the layer is a raw SGR code, not a type

**Settled** 2026-11-27 (branch issue-165, finding R-20261127T074810Z#N1)

The finding is accurate. `set_extended_color` takes the SGR code as a `u16`. It
sets the foreground for 38 and the background for each other code. Thus the
semicolon arm of `process_sgr_params` holds `if code != 58` to keep the
underline color out of the background. A new caller that passes 58 or 59 paints
the background, and nothing stops it.

The current code is correct. `set_extended_color` has two callers, and both are
in `process_sgr_params`. The colon arm calls it only for `38 | 48`. The
semicolon arm calls it only when the code is not 58. The tests of
`an_underline_color_sets_no_attribute` hold both forms of 58, and they fail if
the underline color goes to the background.

**The fix costs more than the defect in this round.** The fix is a private enum
for the layer, a change of the signature, and a change of both callers. This
round of the review loop is record-only. A change is a diff that a review must
read, and that review can find a new nit in it. Then one more fix round starts.

**The boundary.** This record settles only the two callers in
`process_sgr_params`. Each of these occurrences reopens it:

- a third caller of `set_extended_color`
- a call with a code other than 38 or 48
- a model of the underline color, which makes 58 a third layer
