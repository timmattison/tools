## `src/faulte/src/history.rs:1160` — the Claude Code count of a span counts only the Claude processes with faults

**Settled** 2026-11-25 (branch issue-669, finding R-20261125T014832Z#N5)

The finding is accurate. A reading of one frame takes `claude` from the frame
(`history.rs:1373`), and `rank` counts each Claude row of the sample, also a
row with no faults (`ranking.rs:328-335`). A frame stores only the rows with
faults (`history.rs:841`), and a span counts the Claude identities that have a
stored row. Three Claude sessions of which one faulted thus give 3 in the
one-frame view and 1 in the 1 m view of the same frame.

Each count is true on its own basis:

- The one-frame count is the count that the bare `faulte` ranking prints for
  the same sample, because both come from `rank`.
- The span count is on the basis of the line above it, which counts the
  processes with faults over the span. The faults of the Claude line of a
  span are the sum of `frame.claude.faults` over its frames, so both views
  count the faults of each Claude row, and a row with no faults adds zero.

The finding offers two fixes: state the basis in the doc of `span` and in the
README, or keep the count of a frame on the basis of the span. The first is
prose. The second changes the count of the one-frame view away from the count
of the bare ranking, and needs new code and a new test. The round that found
it was record-only, and either change is new text that the next review must
read. That review starts one more round, and the round costs more than a
count of processes whose fault total has the same basis in both views.

The boundary: this settles the basis of the count of Claude Code processes in
a span. A fault total of the Claude line that leaves out the faults of a
Claude row is a new finding.
