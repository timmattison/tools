## `src/wdid/src/defs.rs` `use_function` — its doc comment stays as it is

**Settled** 2026-11-27 (branch issue-727, finding R-20261127T055648Z#N1)

The finding is accurate. The doc comment of `use_function` says that a private
function has no entry, thus its use is dropped. Since cf2714956,
`empty_usages` makes an entry for each function whose name starts with `_` when
`all` is true. Thus under `--all`, the use of a private function is counted,
and the second half of the comment is false for that case. The doc of
`PRIVATE_PREFIX` and the doc of `tally` give the correct rule.

The code is correct. `use_function` counts a use only when an entry exists,
and `empty_usages` decides which entries exist. No behavior and no test result
depends on the comment.

The fix costs more than the defect. The fix is prose, and the branch is in a
record-only round of its review loop. A change of the comment is new text that
a fresh review reads, and that review can find a new nit in it. That starts a
new fix round for a comment whose correct rule is already in two docs of the
same file.

The boundary: this decision settles the doc comment of `use_function` at
`src/wdid/src/defs.rs:271-272`. A change of the behavior of `use_function` or of
`empty_usages` is a new finding. A different comment that states the rule of
private functions incorrectly is a new finding too.
