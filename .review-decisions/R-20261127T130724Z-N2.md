## `src/ufa/README.md` — the JSON document of a filtered delete is the parsed voucher model, not the raw reply

**Settled** 2026-11-27 (branch ufa, finding R-20261127T130724Z#N2)

The finding is correct. `Voucher` (`src/ufa/src/models.rs`) has no flatten
map, unlike `Host` and `ReportedState`. Thus a field that the controller sends
outside the 13 fields of the voucher schema leaves the document, and an
optional field that the controller does not send is written as `null`. The
README says "as the API reported them", and the test comment in
`src/ufa/src/commands/vouchers.rs` says "as the API sent it".

The second half of the README sentence is correct and is the contract that a
script uses: the document has the shape of
`ufa vouchers list --all --output json`, with the camelCase keys of the
schema, and numbers and booleans as JSON values. The two commands give the
same document for the same voucher. A fix changes prose in two files, and it
starts one more review cycle.

**The boundary.** A document whose shape is different from
`ufa vouchers list --all --output json`, or a key that is not the camelCase key
of the voucher schema, is a new occurrence. A request to add a flatten map to
`Voucher` is a new feature, not this finding. The words "as the API reported
them" and "as the API sent it" are settled.
