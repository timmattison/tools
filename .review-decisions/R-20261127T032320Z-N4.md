The finding is accurate. It joins R-20261126T223433Z#N2 and
R-20261127T030328Z#N1 into one finding. A crash between the two renames of an
update leaves no loaded folder of the plugin. Each project that names the
plugin then fails to render until the user installs it again. The old copy
stays in a `.` folder that nothing loads or removes. Each crash during an
install also leaves a `.` folder of up to 64 MiB that nothing removes.

The finding gives no new occurrence. It gives a new fix: name the old folder
`.old-<folder>`, rename it back at start when `<folder>` is absent, and delete
each other `.` folder. That fix is two new rules of the load. One rule renames
a folder, and one rule deletes folders in the plugins directory. Each rule
needs its own test in slice 7.
