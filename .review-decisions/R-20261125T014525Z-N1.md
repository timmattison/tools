## `src/msgs/src/error.rs` — the message of `MsgsError::CacheError` keeps the words "Text cache error"

**Settled** 2026-11-25 (branch msgs, finding R-20261125T014525Z#N1)

The finding is accurate. The branch renamed the text cache to the search index
in `README.md`, in the spec, and in `cache.rs`. But `MsgsError::CacheError`
still formats as `Text cache error: {0}`, and the spec repeats that line at
`specs/2026-03-17-msgs-imessage-browser-design.md:144`. Thus a failed build
shows `Search unavailable: Text cache error: Cannot open the index: ...` in the
search box, and a search during the build shows `Search failed: Text cache
error: The search index is still building`.

**The fix costs more than the defect.** The defect is one old word in a
prefix. The text after the prefix names the index, thus the user still reads
the correct cause. A fix changes `error.rs` and the spec, and each test that
compares the full text of the error. This round of the review loop is
record-only, thus that change starts one more review cycle for a word.

**The boundary.** This record settles the prefix `Text cache error` of
`MsgsError::CacheError` and its copy in the spec only. A message that names
the text cache as a file that msgs still keeps, or an error that sends the user
to the wrong cause, reopens this record.
