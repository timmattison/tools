## `src/ufa/src/test_support.rs` — two comments name `ufa config cloud` as the command that declares `UNIFI_SITE_MANAGER_API_KEY`

**Settled** 2026-11-25 (branch ufa, finding R-20261125T160218Z#N4)

The finding is accurate. The doc of `KNOWN_SETTINGS` and the doc of
`settings_read_by` say that `ufa config cloud` declares
`UNIFI_SITE_MANAGER_API_KEY`. `ConfigCommand::Cloud` takes no argument. The
flag `--site-manager-api-key` is on `Commands::Cloud`, which is `ufa cloud`.

**The cost is a new review cycle.** The fix is prose in a test file. This
round of the review loop is record-only, and a fresh review reads each changed
comment and can find a new nit in it. Then a new fix round starts, and the
loop does not end clean. No user reads these comments. The argument of the two
comments stays correct: a subcommand declares the variable, not the top-level
command, thus the walk must recurse. `KNOWN_SETTINGS` holds
`UNIFI_SITE_MANAGER_API_KEY`, thus a walk with no recursion fails that floor.

**The boundary.** This decision settles only the name of the subcommand in
those two comments. A comment that gives a wrong reason for the recursion, or
a change that moves the variable to a different command, is a new finding.
