## `src/workit/src/main.rs` — the rewrite drops an entry of `workspace.members` that is not a string and does not name it

**Settled** 2026-11-25 (branch workit, finding R-20261125T051139Z#N4)

The finding is accurate. The list of dropped members reads only the string
entries of `workspace.members`. `members_array.clear()` then also removes each
entry that is not a string, for example the `1` of `members = ["a", 1]`, and
stderr does not name it. The README says that the run names each member that
the rewrite drops.

It is not fixed, because the fix costs more than the defect:

- **Such an entry is not a member.** On 2026-11-25, cargo refused
  `members = ["a", 1]` with exit 101 and the message "invalid type: integer
  `1`, expected a string". Thus the existing manifest did not load before the
  run, and the value names no package.
- **The rewrite repairs the manifest.** The manifest that the run writes holds
  only strings, and cargo loads it. No package goes.
- **The cost is a new review cycle.** This round of the review loop is
  record-only. A refusal of such an entry and its test are new code that a
  review must read, and a fresh review can find a new nit in it. Tim chose to
  settle each nit with a record (decision H-742-2 on issue #742).

**The boundary.** This decision settles an entry of `workspace.members` that is
not a string. A string entry that the rewrite drops and does not name is a new
finding.
