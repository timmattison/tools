## `src/nle/src/filters.rs` `PAUSE_INSERTION` — the doc of a range that starts after the end of the timeline stays as it is

**Settled** 2026-11-26 (branch issue-154, finding R-20261127T032453Z#N1)

The finding is accurate. The doc says that the render refuses a point past
the end of the timeline when that end comes before the end of the range. A
range that starts after the end of the timeline gets the length 0 from the
pipeline (`(region_end.min(*end) - start).max(0.0)` in
`src/nle/src/pipeline.rs`). Thus `at = 0` passes the check in `insert_pause`,
and the render accepts a pause that is past the end of the timeline. For
`outputs(&[0.0, 3.0])` and a range of 5 s to 6 s, the result is `[0, 3]`, and
the end stays 3 s.

The defect is one sentence of doc text, not a wrong output. The doc gives the
reason for the refusal: the events after the region and the end of the
timeline move, but they are before the point. For a range that starts after
the end of the timeline, nothing moves. No event is in the region or after
it, and the pipeline moves the end only when the end is at or after the start
of the range. Thus the accepted pause changes nothing, and each span filter
on such a range changes nothing too. The window cannot add this filter until
issue #150 lets a person select a region.

The fix costs more than the defect. A change of the doc is new text that a
fresh review must read, and the loop then starts one more fix round for one
sentence. A refusal in code needs the pipeline to give the span a way to tell
a range that starts at the end of the timeline from one that starts after it,
because both have the length 0. That change is in the `Span` contract, which
each span filter shares.

The boundary: this settles the doc of the no-op case, a range that starts
after the end of the timeline. A pause that the render accepts and that moves
an event or the end of the timeline to a wrong time is a new finding. When
issue #150 lets the window add a pause on a range, a silent no-op that a
person can make in the window is a new finding too.
