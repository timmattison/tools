## `specs/2026-03-29-vpn-tunnel-auto-select-credential-design.md` — the test bullet "A second error line … stays an error" stays as it is

**Settled** 2026-11-24 (branch 191, finding R-20261124T184303Z#N2)

The finding is accurate. The last bullet of the test list says that a second
error line stays an error. Two removed listed containers give two
`no such object` lines, and `only_removed` in
`src/vpn-tunnel/src/credential.rs` skips both, as step 4 of the same spec
says. The bullet means a second line of another kind, for example
`permission denied`, which is the case that the test
`an_inspect_error_that_is_not_a_removed_listed_container_is_still_an_error`
holds. Its words do not say "of another kind".

**The cost is a new review cycle.** This round of the review loop is
record-only. A change to the spec is a new document change that a review must
read, and a fresh review can find a new nit in it. Then a new fix round
starts, and the loop does not end clean. The code and step 4 of the spec agree
with each other and are correct. Only a summary bullet is imprecise, and step
4 of the same spec gives the full rule.

**The boundary.** This decision settles only the words of that one bullet. A
change to `only_removed` that makes a second `no such object` line an error is
a new finding. A different statement in the spec that contradicts the code is
also a new finding.
