## `src/nle/src/filters/splice.rs` — a dropped sequence that restarted a CSI gets an ST, but the doc names only an OSC or a string

**Settled** 2026-11-28 (branch issue-166, finding R-20261128T034137Z#N2)

The finding is accurate. The doc of `Splicer` says that an ST goes where a
dropped sequence started when that start "had ended an earlier OSC or string".
But `Step::Restarted` sets `ends_open` for a restart of each kind of sequence.
The scanner in `src/nle/src/ansi.rs` gives `Step::Restarted` for an ESC inside
a CSI too. Thus for `\x1b[3\x1b[1m` with a dropped `\x1b[1m`, the splicer puts
an ST after `\x1b[3`. No splice test holds the restart of a sequence that is
not an OSC or a string.

No output is wrong on the screen. The terminal aborts the CSI `\x1b[3` at the
ESC of the next sequence in the original stream too. In the spliced stream, the
ESC of the ST aborts the CSI, and the `\` ends the escape with no effect. The
two streams thus give the same screen. The rule moved unchanged from the
`Rewriter` of `src/nle/src/filters/cursor.rs` at b1827b39, in commit 72a6153b of
this branch.

**The fix costs more than the defect.** One fix is prose: a doc that names
each restart. The other fix is a code change that sets `ends_open` only for a
restart of an OSC or a string, with a new test. Both are new text that a fresh
review must read in a record-only round, and that review can start one more fix
round. The code change also removes bytes that do no harm.

**The boundary.** This record settles only the ST after a restarted sequence
that is not an OSC or a string. These occurrences reopen it:

- an ST that changes the screen, for example an ST that ends a sequence that
  the original stream does not end
- an ST that the splicer puts in a place other than the start of the dropped
  sequence
- a filter of the splicer that reads `ends_open` for a purpose other than the ST
