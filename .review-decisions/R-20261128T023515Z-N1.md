## `src/nle/src/filters/viewport.rs` — the docs say that the message for no visible row or column names the option

**Settled** 2026-11-28 (branch issue-165, finding R-20261128T023515Z#N1)

The finding is accurate. The module doc of `src/nle/src/filters/viewport.rs`
says that each listed check fails the render "with a message that names the
option", also no visible row and no visible column. `Axis::visible` gives "no
row is visible" and "no column is visible", and the tests pin that text
(`src/nle/src/filters/viewport/tests.rs` lines 299, 307, 311 and 357). These two
messages name the axis, not `rows`, `hide_rows`, `columns` or `hide_columns`.
The spec (`specs/2026-11-27-nle-viewport-filter-design.md`) and the `README.md`
entry of `nle` state the same claim.

No output is wrong. The render fails for each listed case, as the docs say. The
message for no visible row or column names the axis, and a person who reads it
knows which options to change, because only the crop and the hidden indexes of
that axis remove rows or columns. The defect is only the claim about the text of
two messages.

**The fix costs more than the defect.** The fix is prose in three files: the
module doc, the spec, and the README. This round of the review loop is
record-only. Three changed documents are new text that a review must read, and
that review can start one more fix round. A change of the messages to name the
options is a code change, and three tests pin the present text.

`.review-decisions/R-20261127T070536Z-N2.md` settles a different case: a number
outside `i64`. This record does not change that record.

**The boundary.** This record settles only the claim that the message for no
visible row or no visible column names the option. These occurrences reopen it:

- a message of a crop or hidden-index check that does not name its option
- a change of the message for no visible row or column that names neither the
  axis nor an option
- a new check of the viewport filter whose message the docs describe wrongly
