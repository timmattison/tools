## `src/crap/tests/expand.rs` — on Linux, `FakeClaude` stops at once, and two tests use a zombie as the live session

**Settled** 2026-11-25 (branch github-actions-ci, finding R-20261125T220516Z#N2)

The finding is accurate. `FakeClaude::start` links `/bin/sleep` under the name
`claude`. The uutils coreutils of the `ubuntu-latest` runner refuse a renamed
utility. The log of job 139429344044 (head 08f82d95) shows "Security violation:
Requested utility `claude` does not match executable name" at lines 5531 and
5543. Thus on Linux, the fake stops at once. It stays a zombie until the drop of
the guard waits for it.

**The two tests still do a test of the live branch on Linux.** `pid_is_alive`
in `src/crap/src/main.rs` runs `ps -p <pid> -o command=` and looks for `claude`.
On Linux, `ps` lists a zombie as `[claude] <defunct>`, thus `crap` counts the
zombie as live. `a_live_original_does_not_block_expand` and
`the_no_compaction_fallback_keeps_the_live_check_and_force` each hold a control
that expects exit 7 (`SESSION_ALREADY_RUNNING`). Both tests pass at log lines
5544 and 5550, thus both controls pass. Only the doc comment of `FakeClaude`, "a
`sleep` that runs under the name `claude`", is not true on Linux.

**A change on Linux fails loudly, not silently.** If `pid_is_alive` stops
counting a zombie as live, the controls fail on Linux, and the job turns red.
The `macos-latest` job and each local run on macOS start a live `sleep`.

**The cost of the fix is a new review cycle.** This round of the review loop is
record-only. The fix writes the fake as a `#!/bin/sh` stub through
`gitscratch::testing::executable::write_executable`, as commit 1ebf64c8c did
for `nle`. That stub is new code in a test file that a fresh review must read,
and a fresh review can find a new nit in it. Then a new fix round starts, and
the loop does not end clean. The file comes from `main`, through issue #637
(PR #638, branch issue-637), and this branch does not change it.

**The boundary.** This decision settles only the fixture of these two tests on
Linux. A Linux test that passes because a fake stopped, and that has no control
to prove that `crap` saw a live session, is a new finding.
