## `src/ufa/src/discovery.rs` — `is_verified` is always true after discovery

**Settled** 2026-11-26 (branch ufa, finding R-20261126T235238Z#N6)

The finding is correct. After the commits that removed the name merge
(`d387ad2ad`) and the name (`fd8cb4bff`), each `DiscoveredController` that
leaves discovery passed the probe and has `is_verified` true. The check-mark
column of the setup table thus always shows the mark.

The column gives correct information: each row is a verified controller. The
cost of the field is one `bool` and one column that never shows an empty
cell. A removal changes the struct, the mDNS path, the probe path, the setup
table, and the tests that build a controller, in a part of the code that some
earlier rounds reviewed. That change adds review surface and fixes no
behavior that a user sees as wrong.

**The boundary.** A row that shows the check mark for a controller that did
not pass the probe is a new occurrence. A field that is always true and a
column that always shows the mark are settled.
