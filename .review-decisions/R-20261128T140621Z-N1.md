## `src/nle/src/export.rs` and `README.md` — the stage `ExportProgress::Rendering` says that the editor renders the project, also when the export writes a kept render

**Settled** 2026-11-28 (branch issue-167, finding R-20261128T140621Z#N1)

The finding is accurate. Since `cc42b7b` and `46fd906`, `Editor::export` in
`src/nle/src/editor.rs` writes the render that the editor keeps, with no render
and no copy. It renders the project only when the editor keeps no render. In
both cases it reports `ExportProgress::Rendering` first. The doc of that
variant in `src/nle/src/export.rs` says "The editor renders the project into
one recording." Thus the doc states a render also for an export that renders
nothing.

The finding also said that the stage copies the kept recording. That part is
obsolete, because `46fd906` removed the copy. The same stale rule is in the
Export section of `README.md` (lines 6594-6596): the editor first renders the
project. The paragraph "In code" of that section (lines 6628-6631) states the
new rule, thus the section states two rules. Finding R-20261128T142229Z#N1
named both places.

No behavior is wrong. In both cases the written file is the render of the
present state of the project. With a kept render, a check or an earlier read
rendered that state before the export. The export bar shows
"Step 1 of 2: render the edit" for the stage, and with a kept render the next
stage comes at once. The doc of `Editor::export` states the rule correctly. No
test and no tool reads the prose.
