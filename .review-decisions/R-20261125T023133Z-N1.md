## `.husky/pre-commit` — the plugin block came before its red test, and the order of the commits stays

**Settled** 2026-11-25 (branch ic-emit-rgba, finding R-20261125T023133Z#N1)

The finding is correct. Commit `7b744ed0` (typed `docs`) added the plugin block of the hook: the trigger, the refusal when no claude CLI is on `PATH`, and the loop of `claude plugin validate` and `claude plugin test`. No red test came before it. Commit `258b2c0d` (red, for the `GIT_` variables) and commit `6f9269b8` (the refusal and the failure path, proven by mutation) added the tests later, and they pass.

The only fix is a new order of the commits. That fix is a rewrite of the history of a pushed branch, with a force push. The git guardrail refuses a force push, and the review loop must not rewrite the branch. The rewrite changes no behavior, because the tests exist now. The squash merge also removes the order: `main` gets one commit, thus the order of the commits of the branch does not go into the history of `main`. The cost of the fix is thus more than the cost of the defect.

The boundary: this decision covers only the order of `7b744ed0`, `258b2c0d` and `6f9269b8`. A new commit on this branch that changes the behavior of a hook with no red test before it is a new occurrence.
