## `src/workit/tests/duplicates.rs` — `a_package_name_nothing_else_uses_is_not_reported` passes when the parse of the report finds nothing

**Settled** 2026-11-25 (branch workit, finding R-20261125T043207Z#N7)

The finding is accurate. The test asserts only that no name that
`duplicate_groups` returns ends with `unique-package`. If `duplicate_groups`
returns nothing, for example after a change of the format of the duplicate
report on stderr, the assertion passes, and the test alone checks nothing.

It is not fixed, because the fix costs more than the defect:

- **The sibling tests catch the empty parse.** In the same file,
  `the_duplicate_report_names_the_groups_in_order_by_package_name` compares the
  names from `duplicate_groups` with the names that `build_duplicates` made.
  `the_paths_inside_one_duplicate_group_are_in_order_by_path` panics when the
  report does not name a duplicated package. Both tests use the same fixture
  and the same parse. Thus a parse that returns nothing fails the file.
- **The cost is a new review cycle.** This round of the review loop is
  record-only. A fix in a test file needs a proof with a mutant of the code
  under test. A review must read that new code, and a fresh review can find a
  new nit in it. Tim chose to settle each nit with a record (decision H-742-2
  on issue #742).

**The boundary.** This decision settles this one test. A change that removes
the check of a non-empty parse from both sibling tests reopens it.
