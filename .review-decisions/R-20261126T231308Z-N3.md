## `src/wdid/tests/shell-definitions.rs` `first_line_of` — the doc comment names `name`, and the parameter is `body`

**Settled** 2026-11-26 (branch issue-725, finding R-20261126T231308Z#N3)

The finding is accurate. The doc comment of `first_line_of` says "the function
`name`", but the helper takes only `body: &str`. It always parses one function
named `f`, with that body. Commit 601382a6d added the helper.

The defect is one word in the doc comment of a private test helper. The
signature and the body of the helper are on the next 4 lines, and they show
`body` and the name `"f"`. `cargo doc` does not document a test target, thus
no generated page shows the wrong word.

The fix costs more than the defect. The change is one line, but it is a change
in a test file that a fresh review must read, and the loop then starts one more
fix round for one word.

The boundary: this settles the word `name` in the doc comment of
`first_line_of`. A doc comment that states a wrong behavior, for example a
helper that parses more than one function, is a new finding.
