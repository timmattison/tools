## `src/workit/src/main.rs` — each package manifest is read and parsed two times

**Settled** 2026-11-24 (branch workit, finding R-20261124T182455Z#N3)

The finding is accurate. `is_package_toml` reads and parses each manifest in the
walk, and `get_package_name` reads and parses each package manifest again in
`main`. The two functions repeat the read, the parse, and the error context.

It is not fixed, because the fix costs more than the defect:

- **The cost of the defect is small.** A package manifest is a small file, and
  a second read of a file that the walk just read comes from the page cache.
- **The fix changes the interface of the scan.** `Scan::packages` is a sorted
  list of paths. To carry the name out of the walk, it must hold a path and a
  name or a reason to skip. The loop in `main` that groups the names for the
  duplicate report must change with it. The change stays in this file, because
  `find_cargo_tomls` has one caller, but it changes the walk and `main` of the
  file that stalled the review.
- **The file already stalled the review.** Decision H-742-2 on issue #742
  counted three fix rounds in a row about `src/workit/src/main.rs`, with a new
  finding in each round. A refactor of the walk for a nit adds review surface
  to that file.
- **The two errors are not the same.** `is_package_toml` asks if a manifest is
  a package, and a manifest that holds `[workspace]` is no error.
  `get_package_name` refuses a `[package]` table that states no name. One
  merged function must keep both answers apart.
- **The branch stopped at the blocking level.** At the stall, Tim chose to fix
  each blocking finding and to settle each nit with a record.

The boundary: this settles the second read and parse of a manifest. A
difference between the two functions in what they read, for example a manifest
that one function takes as a package and the other refuses with no warning, is
a different finding.
