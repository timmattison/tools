## `src/wn/src/render.rs` — the summary tail of an open pull request keeps `(closes #N)`

**Settled** 2026-09-18 (branch issue-516, finding R-20260919T013109Z#N2)

The summary of a plan pads every tail to the widest one. The tail of an open pull
request, `→ PR #515 (closes #512)  review it and merge it`, is 47 columns. One
such tail thus sets the width of every tail. At 80 columns it leaves 29 columns
for the label of each stream, and at 50 columns it cuts every label to the
minimum of 8 and the line wraps.

The finding is accurate. It is not fixed, because each repair removes words that
issue #516 asks for.

- **`(closes #N)` is in the acceptance criteria.** Criterion 2 says the answer
  names the pull request and the issue it closes. Criterion 3 says the summary of
  a plan obeys that rule. A summary tail without the issue fails both.
- **The row above does not replace it.** A reader of the summary reads one line
  for each stream to pick the next step. The number the plan gave the work is
  `#512`, and a reader who looks for it in the summary finds the pull request
  that finishes it only when the tail names it.
- **Shorter finish words change the sentence of the answer.** The tail writes
  the same words as the answer of a chain and of a picture. Different words in
  the summary would give the reader two sentences for one step.
- **The cost falls only on a plan that holds an open pull request.** A plan of
  issues keeps the tail `→ #512  si 512`, and its labels do not change.

The boundary: this settles the width of the tail of an open pull request. A
label that the summary cuts although the window has columns for the whole line
is a defect of the layout, and it reopens this decision. A change to the words
that issue #516 asks for also reopens it.
