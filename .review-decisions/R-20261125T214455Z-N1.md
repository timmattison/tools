## `src/ic/src/main.rs` `starts_no_image` — `--diff` calls a binary file that is no image a text file

**Settled** 2026-11-25 (branch issue-763, finding R-20261125T214455Z#N1)

The finding is correct. When the first block of a file names no image format,
`starts_no_image` returns `true`, and it does not ask
`first_block_can_be_text`. A binary file that is no image thus gets the refusal
`--diff compares two still images, and <path> is a text file`. A file of 3000
random bytes named `data.zip` and an empty file with no extension each give
that refusal at commit `728bb9590`.

The refusal itself is correct, because neither file is a still image. Only the
word for the cause is wide. That word obeys a documented rule: `src/ic/README.md`
says that a file is text when its extension names no image format and its first
bytes start no image. Plain `ic <file>` uses the same rule (`src/ic/src/main.rs`,
the `else` branch after `is_image_file`), and it prints such a file as text.
The two paths thus agree.

The fix changes code, adds a test, and changes the doc of `show_diff` and the
README rule. It also makes the rule of `--diff` different from the rule of
plain `ic`. Its cost is that change and one more review cycle of this branch,
which is in a record-only round. The cost of the gap is one refusal that names
a wide cause for a file that `--diff` must refuse in any case.

The boundary: a review that asks again for a decode error in place of the text
refusal for a binary file that is no image is settled by this record. A file
that is a still image and gets the text refusal is a new finding. A change of
the README rule, or of the rule of plain `ic`, reopens this decision.
