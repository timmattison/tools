## `src/wdid/tests/defs-render.rs` — the two tests of a long `Through` cell keep their own fixture

**Settled** 2026-11-26 (branch issue-725, finding R-20261126T231043Z#N1)

The finding is accurate. `long_through_cell_wraps_inside_thirty_columns` and
`no_width_keeps_the_through_cell_on_one_line` each build the same `wt` row:
`never("wt", Kind::Alias, "cwt")`, six `alias<n>` entries in `through`, 21
uses, and `Classification::Used`. Each test also states the same expected
cell, `"alias1 6, alias2 5, alias3 4, alias4 3, alias5 2, alias6 1"`. A later
change to one copy can leave the other test on a different list.

The defect is a copy of 4 setup lines and one string, in two tests that are
next to each other in one file. A stale copy does not make a test pass for the
wrong reason. Each test builds its own row and states the cell of that row,
thus each test stays correct alone. The risk is only that the two tests stop
holding the same case.

The fix costs more than the defect. A helper and a constant are new test code
that a fresh review must read, and the loop then starts one more fix round for
a copy of 5 lines.

The boundary: this settles the copy in these two tests. A third test that
copies the same row, or two copies that disagree, is a new finding.
