## `specs/2026-11-27-nle-viewport-filter-design.md` `ScreenView` — the spec does not name the field `whole_timeline`

**Settled** 2026-11-27 (branch issue-165, finding R-20261127T075338Z#N3)

The finding is accurate. The `ScreenView` of the spec has three fields:
`region`, `size` and `before`. The code in `src/nle/src/pipeline.rs` has a
fourth field, `whole_timeline`. Commit `cf8aa42eb` added it after the spec
(commit `069d18ee5`). `viewport.rs` reads it to know if it can change the size
of the screen. The doc of `ScreenFilterFn` says that a filter reads it, and not
`RegionView::open`, because a range that holds each event is not `All`. The
spec names neither the field nor that rule.

The defect is in prose only. The code holds the rule, and the doc of the field
and the doc of `ScreenFilterFn` state it. The tests of the viewport filter hold
the behavior on a region that is `All` and on a range that holds each event.

**The fix costs more than the defect in this round.** The fix is prose. This
round of the review loop is record-only. A change is a diff that a review must
read, and that review can find a new nit in it. Then one more fix round starts.

**The boundary.** This record settles only the missing field `whole_timeline`
and its rule in the spec. Each of these occurrences reopens it:

- a field of `ScreenView` other than `whole_timeline` that the spec does not
  name
- a change of the rule in the code, for example a filter that reads
  `RegionView::open` to change the size
- a second screen filter that reads `whole_timeline`
