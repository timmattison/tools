## `src/nle/src/filters/idle_compression/tests.rs` — the two size tests do not tell the recording size from 80x24

**Settled** 2026-11-27 (branch issue-167, finding R-20261128T000319Z#N1)

The finding is accurate. `the_filter_replays_on_the_columns_of_the_recording`
and `the_ignored_rows_are_the_rows_of_the_recording` tell the size of the
recording from the old 20x5 options of the filter. They do not tell it from the
VT100 size of 80x24. Column 25 is blank on 80 columns too, and row 5 is not the
bottom row of 24 rows. Thus a mutant of `activity_times` that does the check of
`screen_of` on `context.size` and then replays on
`TerminalState::new(80, 24, …)` passes both tests.

The production code is correct. `activity_times` builds the emulator and the
watched range from the width and the height that `screen_of` gives back. A
pipeline that sends `TerminalSize::VT100` in place of the recording size fails
`more_ignored_rows_than_the_recording_has_fail_the_render`. Only a mutant inside
the filter, which reads one size and replays on a different size, escapes.

**The fix costs more than the defect in this round.** The fix changes the two
fixtures: a recording of 10 columns, where both writes clamp to the last
column, and a recording of 3 rows with the bottom row ignored. Those changes
are new code in a test file, which a review must read, and that review can find
a new nit in them. Then one more fix round starts. This round of the review
loop is record-only.

**The boundary.** This record settles only the gap between the recording size
and 80x24 in these two tests. These occurrences reopen it:

- a change to `activity_times` or `screen_of` that reads the size from a
  source other than `context.size`
- a change that removes or weakens
  `more_ignored_rows_than_the_recording_has_fail_the_render`
- a new size test in this file that has the same gap
