## `src/nle/src/filters/typing_speed.rs` `from_options` — the jitter keeps its f64 default

**Settled** 2026-11-26 (branch issue-155, finding R-20261127T004114Z#N1)

The finding is accurate. After ad800cb, `from_options` reads its two optional
options in two shapes. The pause uses `DEFAULT_PAUSE` as it is, and gives only
a value from the options to `Seconds::new`. The jitter turns `Jitter::NONE`
into an `f64` with `get`, and gives that `f64` to `Jitter::new` again at each
call.

The defect has no effect on the behavior. `Jitter::new(0.0)` always succeeds,
so the default jitter never fails a render, and a bad jitter from the options
still gives the message that names `jitter`. The cost of the round trip is one
range check at each call of `from_options`, which occurs once for each filter
in a render.

The fix costs more than the defect. It is new code in `from_options`, and a
fresh review must read it. The review loop then starts one more fix round for
a change of shape that the tests cannot tell from the current code.

The boundary: this decision settles the shape of the jitter default in
`from_options`. A default that can fail its own constructor, or a message for
a bad jitter that does not name the option, is a new finding. A later change
that touches `from_options` for a different reason can take the shape of the
pause, and that change closes this decision.
