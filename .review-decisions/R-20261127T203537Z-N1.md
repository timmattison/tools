## `src/nle/src/filters/backspace/tests.rs` `render_marked` — the fixture build repeats the six lines of `render_in`

**Settled** 2026-11-27 (branch issue-167, finding R-20261127T203537Z#N1)

The finding is accurate. `render_marked` and `render_in` each build the source
recording and the `EditProject` with the same six lines: the test fixture, the
width, the height, the duration from the largest event time, the events, and
`EditProject::from_recording`. If one copy changes how it sets the duration and
the other copy does not, the two helpers build different sources.

The defect is in test code, and no behavior of the filter depends on it. Both
copies give the same source today. `render_marked` states its size (80 by 24)
and its duration rule in its doc comment, and each of its tests reads that
contract. A drift makes a test of the marks fail or pass for the wrong source,
but it cannot change what the filter does for a user.

**The fix costs more than the defect in this round.** The fix moves the six
lines into one helper that both functions call. That change is new code in a
test file, which a review must read, and that review can find a new nit in it.
Then one more fix round starts. This round of the review loop is record-only.

**The boundary.** This record settles only the copy of the fixture build in
`render_marked` and `render_in`. These occurrences reopen it:

- a change that makes the two copies build different sources, for example a
  different duration rule or a different size in one copy only
- a third copy of the same six lines in this test file
