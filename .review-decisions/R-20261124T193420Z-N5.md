## `src/nle/src/commands.rs` — the export commands build their arguments on the async runtime

**Settled** 2026-11-24 (branch 170, finding R-20261124T193420Z#N5)

`export_video` and `export_web` are async commands. They call
`video_export_args` and `web_export_args` on a worker of the async runtime, and
those functions call `exists`, `canonicalize`, and `parent.exists()`. A slow or
network file system can hold that worker.

The finding is accurate. It is not fixed, because:

- **The file work is metadata only.** Each export does at most two `exists`
  calls and two `canonicalize` calls. The load, save and list commands read or
  write a full recording, and 7233b47a moved that work to the blocking pool.
- **The export itself does not hold a worker.** The shell plugin runs `beta` as
  a child process, and the command awaits it.
- **The PR body agrees with the code.** It scopes `run_blocking` to the three
  file commands.
- **The round is record-only.** A fix puts each call in `run_blocking` and
  needs a test. That change is new code, and it starts a new review cycle.

The boundary: a report of a stall in an export, or an export function that
reads the content of a file, reopens this decision.
