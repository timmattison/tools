## `src/faulte/src/sampler.rs:226` — a stray line before the first header of the first `top` gives a second gap with the restart reason

**Settled** 2026-11-25 (branch issue-669, finding R-20261125T014832Z#N2)

The finding is accurate. `StreamParser::refuse_stray` (`stream.rs:241`) gives
`StreamEvent::Refused` for the first line that is not blank before the first
`Processes:` line. `Sampler::read` sends that event as a gap, and `send_gap`
sets `covered_until`. The stream does not stop. The first `Header` of the same
stream then sees `first && ledger.covered_until.is_some()`, and it sends a
second gap with `RESTART_REASON`, although no earlier `top` ran.

The effect is small and needs an abnormal stream:

- `top` must print a line that is not a sample before its first header. The
  parser treats that output as a refusal, and the first gap already shows the
  true reason with the text of the line.
- The second gap starts where the first gap ends, so its lost time is only
  the time from the stray line to the header.
- For each later `top`, a restart did occur, so the reason is true there.

The fix is a new flag in `Run::start`, a new parameter of `read`, and a new
sampler test. The round that found it was record-only, and that code is new
code that the next review must read. That review starts one more round, and
the round costs more than one extra gap of near zero length after a refusal
that the view already reports.

The boundary: this settles the extra gap after a stray line of the first
`top`. A path that sends `RESTART_REASON` when no stray line and no earlier
`top` came first, or a lost time that counts time that a sample measured, is
a new finding.
