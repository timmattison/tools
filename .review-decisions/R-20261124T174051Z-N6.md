## `src/faulte/src/top.rs:67` — the comment on `-l` says that the run stops

**Settled** 2026-11-24 (branch issue-669, finding R-20261124T174051Z#N6)

The finding is accurate. `build_arguments` serves two callers: `arguments`,
which passes `-l 2`, and `stream_arguments`, which passes `-l 0` (the constant
`ENDLESS`). The comment "Logging mode: print this count of samples, then
stop." is false for the second caller, because `top -l 0` prints samples until
the caller stops it.

The correct rule is stated twice next to it. The doc of `ENDLESS`
(`top.rs:33-35`) says that `top` reads zero as "print samples until the
process stops". The test `the_stream_arguments_ask_for_endless_samples` holds
the `-l 0` list. The call `build_arguments(ENDLESS, …)` names that constant.

The fix is one line of comment. The round that found it was record-only, and
a changed comment is new text that the next review must read. That review
starts one more round, and the round costs more than a comment that the named
constant beside it corrects.

The boundary: this settles the wording of this one comment. A third caller of
`build_arguments` with a `-l` value that the comment and the doc of `ENDLESS`
do not describe is a new finding.
