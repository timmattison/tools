## `src/nle/src/filters/keystroke_hud/paint.rs` — each paint keeps ESC 7 and ESC 8

**Settled** 2026-11-27 (branch issue-161, finding R-20261127T014638Z#I2)

The finding is correct: the paint of the keystroke HUD wraps its cells in
ESC 7 and ESC 8, and the program shares that one save slot of the terminal.
A program that saves, lets a box paint, and then restores gets the cursor of
the paint in the viewer. Its output goes there first, and the repair after
the event puts the screen back.

The fix kept ESC 7 and ESC 8. The repair now also puts back the character
set when the two replays disagree on it, the test names say what they prove,
and the limits in README.md and in the module doc name the shared slot.

The other fix, an explicit restore (CUP, SGR and the character set) instead
of ESC 8, was refused. It writes the state of the `termstate` replay into the
viewer on each paint, and that replay has no DECOM, no SO and SI, and no G1:
it takes `ESC ) 0` as line drawing. So the explicit restore can turn off the
origin mode of a program or put line drawing into its text on every paint,
which is a larger defect than the transient one on the rare path above.

Boundary: a new argument against ESC 7 and ESC 8 does not reopen this. A
reason to reopen is a `termstate` that models DECOM, SO, SI and G0 to G3, or
a new case where the save slot of the program is lost on the final screen.
