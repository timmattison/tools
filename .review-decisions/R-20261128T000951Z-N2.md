**Settled** 2026-11-27 (branch issue-166, finding R-20261128T000951Z#N2)

The finding is accurate. The truecolor row gives the value `invert`. The
refusal lists the names `keep, invert-lightness`, and `invert` is a part of
`invert-lightness`. Thus `message.contains(value)` holds also when the message
does not echo the bad value.

**The fix costs more than the defect in this round.** The three rule options
`cube`, `grayscale`, and `truecolor` make their refusal in one function,
`read_rule`, with one `format!`. The cube row and the grayscale row can fail,
thus a loss of the echo in that shared `format!` fails the test. The truecolor
row adds no coverage of a different code path. The fix is a change of a test
file. A review reads that change, thus the fix starts one more review cycle,
and this round of the review loop is record-only.

**The boundary.** This record settles only the substring overlap of the value
`invert` in the truecolor row. Each of these occurrences reopens it:

- a refusal of the `truecolor` option that does not come from `read_rule`
- a change that makes the cube row or the grayscale row unable to fail
- a refusal of a rule value on `main` that does not echo the value
